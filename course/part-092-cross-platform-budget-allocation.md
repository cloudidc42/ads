## ทำไม Part นี้สำคัญ

ถึงจุดนี้คุณผ่านการเรียนรู้ Facebook Ads แบบเจาะลึก (Section A-F) และ TikTok Ads แบบเจาะลึก (Section G-I) มาแล้วทั้งคู่ Part 089-091 พาคุณสร้างระบบวัดผลกลางที่รวมทั้งสองแพลตฟอร์มไว้ในที่เดียว (UTM/GA4, Server-Side Tracking, Dashboard) — คำถามที่ตามมาทันทีคือ **"แล้วควรแบ่งงบระหว่าง Facebook กับ TikTok เท่าไหร่ดี"**

นี่คือคำถามที่นักยิงแอดมือใหม่ถึงระดับกลางส่วนใหญ่ตอบแบบเดา — บางคนแบ่ง 50/50 เพราะ "ดูยุติธรรม" บางคนทุ่มทั้งหมดไปที่แพลตฟอร์มที่ตัวเองถนัดกว่า โดยไม่มีกรอบคิดที่วัดผลได้จริง ผลคือเสียโอกาสจากแพลตฟอร์มที่ควรได้งบมากกว่า หรือแย่กว่านั้นคือหลอกตัวเองว่าทั้งสองแพลตฟอร์มทำงานดีพร้อมกัน (เพราะแต่ละแพลตฟอร์มรายงาน ROAS สูงในระบบของตัวเอง) ทั้งที่ยอดขายจริงไม่ได้เพิ่มขึ้นตามสัดส่วนที่ควรจะเป็น

Part นี้จะให้คุณกรอบคิดที่เป็นระบบตั้งแต่การตัดสินใจสัดส่วนงบเริ่มต้น การทดสอบอย่างมีวินัย การจัดการปัญหา Attribution ที่ซ้อนกันระหว่างสองแพลตฟอร์ม ไปจนถึงการทำ Incrementality Test เพื่อรู้ผลจริงที่ปราศจากอคติของระบบ Attribution ของแต่ละแพลตฟอร์มเอง และปิดท้ายด้วยการวางแผนงบตามฤดูกาลและโครงสร้างทีมที่รองรับการรันสองแพลตฟอร์มพร้อมกันได้อย่างมีประสิทธิภาพ

ข้อความสำคัญที่ต้องจำไว้ตลอด Part นี้คือ **ตัวเลข ROAS ที่แต่ละแพลตฟอร์มรายงานเอง ไม่ใช่ความจริงทั้งหมด และการรวมตัวเลขทั้งสองแพลตฟอร์มเข้าด้วยกันแบบตรงๆ (บวกกัน) มักทำให้ประสิทธิภาพที่แท้จริงของธุรกิจดูดีเกินจริง** — นักยิงแอดที่เก่งข้ามแพลตฟอร์มไม่ใช่คนที่รู้ Facebook เก่งและ TikTok เก่ง แต่คือคนที่รู้วิธี "หักดิบ" ตัวเลขทั้งสองระบบให้กลับมาเป็นภาพความจริงเดียวของธุรกิจ

4. **Step 914 — Blended CAC และ Blended ROAS** วิธีคิดต้นทุนและผลตอบแทนข้ามแพลตฟอร์มให้สะท้อนความจริงของธุรกิจ

7. **Step 917 — Seasonal Reallocation** การปรับงบตามฤดูกาล/เทรนด์ และปฏิทินการตลาดของธุรกิจไทย

9. **Step 919 — ข้อผิดพลาดที่พบบ่อยที่สุด 10 ข้อ** ในการแบ่งงบข้ามแพลตฟอร์ม พร้อมวิธีป้องกัน
10. **Step 920 — Workshop: สร้างโมเดลแบ่งงบข้าม Facebook/TikTok** ของธุรกิจจริงแบบครบวงจร พร้อมสรุป Part

## Step 911: กรอบคิดและ Decision Scorecard สำหรับแบ่งงบ Facebook vs TikTok

### ความแตกต่างพื้นฐานที่ต้องเข้าใจก่อนแบ่งงบ

ก่อนจะพูดถึงตัวเลขสัดส่วน ต้องเข้าใจธรรมชาติของทั้งสองแพลตฟอร์มให้ชัดก่อน เพราะสัดส่วนงบที่ดีไม่ได้มาจากการเดาหรือทำตามเทรนด์ แต่มาจากการจับคู่ธรรมชาติของแพลตฟอร์มกับธรรมชาติของธุรกิจ

| มิติ | Facebook/Instagram | TikTok |
|---|---|---|
| กลไกหลักในการค้นพบคอนเทนต์ | Interest/Behavior + Social Graph (เพื่อน, Page ที่ติดตาม) | Interest จากพฤติกรรมการดู (For You Feed) มากกว่า Social Graph |
| ความแม่นยำของ Interest Targeting | สูงกว่าในหลายอุตสาหกรรม เพราะมีข้อมูล Demographic ลึก | กว้างกว่า เน้น Behavioral Signal จากการดูวิดีโอ |
| จุดแข็งของ Retargeting | แข็งมาก มี Custom Audience/Pixel ที่ Mature และ Ecosystem CRM เชื่อมง่าย | กำลังพัฒนา ยังไม่ Mature เท่า Facebook ในหลายธุรกิจ |
| ความเร็วของ Content Fatigue | ปานกลาง ครีเอทีฟอยู่ได้นานกว่าถ้าคุณภาพดี | เร็วมาก ต้องผลิตครีเอทีฟใหม่ต่อเนื่อง |
| กลุ่มอายุที่ Dominant | กว้าง ครอบคลุมถึงกลุ่มอายุมากกว่า 35 ปีได้ดี | เน้นกลุ่มอายุ 16-34 ปีเป็นหลัก แม้จะขยายกว้างขึ้นทุกปี |
| ความเหมาะกับสินค้าราคาสูง/พิจารณานาน (Considered Purchase) | เหมาะมาก เพราะ Retargeting Funnel แข็งและครีเอทีฟอธิบายละเอียดได้ | เหมาะกับการสร้าง Awareness แต่ปิดยอดขายจริงต้องอาศัย Funnel ต่อ |
| ความเหมาะกับสินค้า Impulse Buy ราคาต่ำ-กลาง | ดี แต่ CPM มักสูงกว่า | ดีมาก เพราะ CPM ต่ำกว่าและพฤติกรรม Discovery นำไปสู่การซื้อทันทีได้ง่าย |

### ปัจจัยที่ใช้ตัดสินใจสัดส่วนงบเริ่มต้น

ไม่มีสัดส่วนสากลที่ใช้ได้กับทุกธุรกิจ แต่มีปัจจัยที่ควรพิจารณาเป็นระบบ 8 ข้อ:

1. **อายุและพฤติกรรมของกลุ่มเป้าหมายหลัก** — ถ้าฐานลูกค้าหลักอายุ 18-30 ปี TikTok ควรได้น้ำหนักมากกว่า ถ้าฐานลูกค้าอายุ 35 ปีขึ้นไป Facebook ควรได้น้ำหนักมากกว่า
2. **ประเภทการซื้อ (Purchase Type)** — Impulse Buy (แฟชั่น, ของกิน, ของใช้ราคาไม่แพง) เหมาะกับ TikTok มากกว่า Considered Purchase (คอร์สราคาสูง, อสังหาริมทรัพย์, B2B) เหมาะกับ Facebook มากกว่าเพราะต้องใช้ Retargeting Funnel ที่ยาว
3. **ความพร้อมด้าน Creative/UGC** — TikTok ต้องการ Creative Velocity สูงมาก (ครีเอทีฟใหม่ทุกสัปดาห์) ถ้าทีมผลิตคอนเทนต์ไม่ทันควรเริ่มน้ำหนักที่ Facebook มากกว่าก่อน
4. **Funnel Stage ที่ธุรกิจต้องการเน้น** — ถ้าเน้น Awareness/การเข้าถึงลูกค้าใหม่ TikTok มักได้ CPM ที่ถูกกว่า ถ้าเน้น Retargeting/ปิดยอดขายจากฐานลูกค้าเดิม Facebook ได้เปรียบ
5. **ข้อมูลในมือ (Retargeting Pool ที่มีอยู่)** — ธุรกิจที่มี Customer List/Pixel Data สะสมมานานควรให้ Facebook ได้น้ำหนักมากกว่าในช่วงแรก เพราะ Lookalike และ Custom Audience จะทำงานได้ดีทันที
6. **ราคาสินค้าและ Margin** — สินค้าราคาสูง Margin สูงสามารถรองรับ CPA ที่แพงกว่าได้ ทำให้เปิดโอกาสทดสอบทั้งสองแพลตฟอร์มพร้อมกันได้ง่ายกว่าสินค้า Margin ต่ำที่ต้องระมัดระวังงบมากกว่า
7. **ความพร้อมของทีมและ Skillset** — ถ้าทีมมีคนเดียวที่ต้องดูแลทั้งสองแพลตฟอร์ม ควรเริ่มจากแพลตฟอร์มเดียวที่ Scorecard สูงกว่าก่อน แล้วค่อยขยายไปแพลตฟอร์มที่สอง
8. **สถานะการแข่งขันในอุตสาหกรรม** — ถ้าคู่แข่งหลักยังไม่ลง TikTok อย่างจริงจัง อาจเป็นโอกาสที่ CPM ยังถูกและได้เปรียบด้าน First Mover

### Decision Scorecard: ตารางให้คะแนนเพื่อหาสัดส่วนงบเริ่มต้น

ให้คะแนน 1-5 ในแต่ละเกณฑ์สำหรับ Facebook และ TikTok แยกกัน (5 = เหมาะมาก, 1 = ไม่เหมาะเลย) แล้วรวมคะแนนเพื่อคำนวณสัดส่วนงบเริ่มต้น

| เกณฑ์ | น้ำหนัก | คะแนน Facebook (1-5) | คะแนน TikTok (1-5) |
|---|---|---|---|
| อายุกลุ่มเป้าหมายตรงกับ Dominant User ของแพลตฟอร์ม | 15% | | |
| ความเหมาะกับประเภทการซื้อ (Impulse vs Considered) | 15% | | |
| ความพร้อมด้าน Creative/UGC ของทีม | 15% | | |
| ขนาดและคุณภาพของ Retargeting Pool ที่มีอยู่ | 15% | | |
| Margin สินค้าที่รองรับการทดสอบได้ | 10% | | |
| ความพร้อมของทีม/เวลาที่ดูแลได้ | 10% | | |
| ระดับการแข่งขันของคู่แข่งบนแพลตฟอร์มนี้ | 10% | | |
| Data/Benchmark ในอดีตของธุรกิจนี้บนแพลตฟอร์มนี้ (ถ้ามี) | 10% | | |

**วิธีคำนวณ:** คูณคะแนนแต่ละเกณฑ์ด้วยน้ำหนัก แล้วรวมคะแนนทั้งหมดของ Facebook และ TikTok เข้าด้วยกัน จากนั้นแปลงสัดส่วนคะแนนรวมเป็นสัดส่วนงบเริ่มต้น เช่น Facebook ได้คะแนนรวม 3.6 และ TikTok ได้ 2.4 → สัดส่วนงบเริ่มต้นควรอยู่ที่ประมาณ Facebook 60% : TikTok 40% (3.6/(3.6+2.4) = 60%)

### ข้อผิดพลาดที่พบบ่อย

- ใช้ Scorecard ครั้งเดียวแล้วยึดตลอดไป ทั้งที่ควรทำใหม่ทุก 3-6 เดือนเพราะปัจจัยเปลี่ยน (เช่น Retargeting Pool ใหญ่ขึ้น, ทีมเก่ง TikTok มากขึ้น)

คะแนนรวม FB ≈ 3.75, TikTok ≈ 2.65 → สัดส่วนเริ่มต้นแนะนำ **Facebook 58-62% : TikTok 38-42%** โดยใช้ TikTok เน้นสร้าง Awareness ในกลุ่มฟรีแลนซ์รุ่นใหม่ที่ Facebook เข้าถึงได้จำกัดขึ้นเรื่อยๆ ส่วน Facebook ยังคงเป็นตัวหลักสำหรับ Retarget Free Trial User ให้อัปเกรดเป็นเสียเงิน

**ธุรกิจ E: ร้านอาหารเดลิเวอรีท้องถิ่น 3 สาขาในกรุงเทพ**

| เกณฑ์ | น้ำหนัก | FB | TikTok |
|---|---|---|---|
| อายุกลุ่มเป้าหมาย (กว้าง 20-45 ปี ในรัศมีสาขา) | 15% | 4 | 3 |
| ประเภทการซื้อ (Impulse สูงมาก มื้ออาหาร) | 15% | 3 | 5 |
| ความพร้อม Creative/UGC (ถ่ายอาหาร/หน้าร้านง่าย) | 15% | 3 | 5 |
| Retargeting Pool (ลูกค้าประจำสั่งซ้ำผ่าน LINE OA) | 15% | 4 | 1 |
| Margin (Margin อาหารต่ำ-กลาง) | 10% | 3 | 3 |
| ความพร้อมทีม (ทีมเล็ก ไม่มีเวลาผลิตคอนเทนต์มาก) | 10% | 4 | 2 |
| การแข่งขัน (ร้านคู่แข่งโซนเดียวกันเล่น TikTok เยอะแล้ว) | 10% | 3 | 3 |
| Data ในอดีต | 10% | 3 | 2 |

คะแนนรวม FB ≈ 3.4, TikTok ≈ 3.15 → สัดส่วนเริ่มต้นแนะนำ **Facebook 52% : TikTok 48%** — แม้ TikTok เหมาะกับประเภทการซื้อและ Creative มาก แต่คะแนนความพร้อมทีมที่ต่ำและ Retargeting Pool ที่อ่อนดึงคะแนนรวมลงมาใกล้เคียงกับ Facebook ธุรกิจนี้ควรพิจารณาจ้างคนทำคอนเทนต์เพิ่มก่อนขยายสัดส่วน TikTok มากกว่านี้

## Step 912: Starting Split และวิธีทดสอบสัดส่วนงบอย่างเป็นระบบ

### หลักการสำคัญ: Scorecard ให้จุดเริ่มต้น การทดสอบให้คำตอบจริง

Decision Scorecard ใน Step 911 ให้สัดส่วนเริ่มต้นที่มีเหตุผลรองรับ แต่ไม่ใช่คำตอบสุดท้าย เพราะทฤษฎีกับความจริงในตลาดอาจต่างกัน (เช่น คู่แข่งเพิ่งอัดงบ TikTok มหาศาลจนราคาประมูลพุ่ง หรือทีม Creative เก่ง TikTok กว่าที่ประเมินไว้) การทดสอบอย่างเป็นระบบคือขั้นตอนที่ขาดไม่ได้

### Starting Split แนะนำตามระยะของธุรกิจ

| สถานะธุรกิจ | Starting Split แนะนำ | เหตุผล |
|---|---|---|
| ธุรกิจใหม่ ไม่มี Data เดิมเลย | ตามผลจาก Decision Scorecard ตรงๆ | ไม่มีข้อมูลอื่นให้อ้างอิง |
| มี Data บน Facebook อยู่แล้ว ยังไม่เคยลอง TikTok | Facebook 70-80% : TikTok 20-30% | เริ่ม TikTok ในสัดส่วนที่พอทดสอบได้จริงโดยไม่เสี่ยงงบเดิมที่ทำงานอยู่ |
| มี Data บน TikTok อยู่แล้ว ยังไม่เคยลอง Facebook | TikTok 70-80% : Facebook 20-30% | เช่นเดียวกันในทิศทางกลับ |
| มี Data ทั้งสองแพลตฟอร์มแต่ยังไม่เคยเทียบกันอย่างเป็นระบบ | ใช้ Historical Blended ROAS ของ 90 วันล่าสุดเป็นฐาน ปรับตาม Scorecard 10-15% | ผสมข้อมูลจริงกับกรอบคิดเชิงคุณภาพ |
| ทีมเล็ก คนเดียวดูแลทั้งหมด | เริ่มจากแพลตฟอร์มเดียวที่ Scorecard สูงกว่า 100% ก่อน 4-6 สัปดาห์ แล้วค่อยเปิดแพลตฟอร์มที่สอง | ป้องกันการทำทุกอย่างพร้อมกันแต่ไม่มีอย่างใดทำได้ดีจริง |

### ระยะเวลาและปริมาณข้อมูลขั้นต่ำก่อนตัดสิน

ข้อผิดพลาดที่พบบ่อยที่สุดคือการตัดสินใจเปลี่ยนสัดส่วนงบเร็วเกินไปจากข้อมูลที่ไม่มีนัยสำคัญทางสถิติ กฎขั้นต่ำที่แนะนำ:

- **จำนวน Conversion ขั้นต่ำ:** อย่างน้อย 30-50 Conversion ต่อแพลตฟอร์มก่อนเริ่มเปรียบเทียบ CPA/ROAS อย่างจริงจัง (ยิ่งน้อยกว่านี้ ความผันแปรจากโชคจะสูงเกินกว่าจะสรุปได้)
- **ระยะเวลาขั้นต่ำ:** อย่างน้อย 2 สัปดาห์ต่อรอบทดสอบ เพื่อให้ผ่านช่วง Learning Phase ของทั้งสองแพลตฟอร์มและเห็นความผันแปรตามวันในสัปดาห์
- **จำนวนรอบทดสอบ:** อย่างน้อย 2 รอบติดต่อกันที่ได้ผลสอดคล้องกัน ก่อนสรุปว่าสัดส่วนใหม่ดีกว่าจริง (ไม่ใช่ผลจากความผันแปรระยะสั้น)

### วิธีเก็บ Baseline ให้ยุติธรรม (Apples to Apples)

การเปรียบเทียบที่ไม่ยุติธรรมเป็นสาเหตุอันดับหนึ่งที่ทำให้สรุปผลผิด ต้องควบคุมตัวแปรเหล่านี้ให้เท่ากันหรือใกล้เคียงที่สุดระหว่างสองแพลตฟอร์ม:

1. **Objective/Funnel Stage เดียวกัน** — เทียบ Conversion Campaign กับ Conversion Campaign เท่านั้น ไม่เทียบ Awareness ของแพลตฟอร์มหนึ่งกับ Conversion ของอีกแพลตฟอร์ม
2. **คุณภาพ Creative ในระดับเดียวกัน** — ถ้า Facebook ใช้ครีเอทีฟที่ผ่านการทดสอบมาแล้วหลายรอบ แต่ TikTok ใช้ครีเอทีฟที่ทำครั้งแรก การเทียบจะไม่ยุติธรรม ควรให้แต่ละแพลตฟอร์มมีครีเอทีฟที่ "ดีที่สุดที่ทำได้ในเวลานั้น" เท่าเทียมกัน
3. **ช่วงเวลาเดียวกัน** — ทดสอบทั้งสองแพลตฟอร์มพร้อมกันในช่วงเวลาเดียวกัน ไม่ใช่ทดสอบ Facebook เดือนนี้แล้วทดสอบ TikTok เดือนหน้า เพราะสภาวะตลาด/ฤดูกาลเปลี่ยนได้
4. **Attribution Window ที่รับรู้ตรงกัน** — เข้าใจว่า Facebook และ TikTok อาจใช้ Attribution Window ต่างกัน (ทบทวน Step 914-915) ต้องปรับความเข้าใจตัวเลขให้สอดคล้องกันก่อนเทียบ
5. **Landing Page/Offer เดียวกัน** — ใช้หน้า Landing Page และ Offer เดียวกันสำหรับทั้งสองแพลตฟอร์ม เพื่อไม่ให้ความแตกต่างของ Conversion Rate มาจากปัจจัยนอกแพลตฟอร์ม

### ตาราง Test Plan ตัวอย่าง 8 สัปดาห์

| สัปดาห์ | กิจกรรม | เป้าหมาย |
|---|---|---|
| 1-2 | เปิดทั้งสองแพลตฟอร์มตาม Starting Split เก็บ Baseline | ผ่าน Learning Phase ทั้งคู่ เก็บข้อมูลดิบ |
| 3-4 | เก็บข้อมูล Blended CAC/ROAS ต่อเนื่อง ไม่ปรับสัดส่วนงบ | ให้ครบ 30-50 Conversion ต่อแพลตฟอร์ม |
| 5 | วิเคราะห์ผล เทียบ Marginal ROAS ของแต่ละแพลตฟอร์ม | ตัดสินใจว่าจะปรับสัดส่วนหรือไม่ |
| 6-7 | ปรับสัดส่วนงบทีละ 10-20% ตามผลวิเคราะห์ เก็บข้อมูลรอบใหม่ | ยืนยันว่าสัดส่วนใหม่ดีขึ้นจริง |
| 8 | สรุปผลรอบทดสอบ วางสัดส่วนงบมาตรฐานสำหรับไตรมาสถัดไป | ได้สัดส่วนงบที่มีข้อมูลรองรับจริง |

### ข้อผิดพลาดที่พบบ่อย

- เปลี่ยนสัดส่วนงบทุกสัปดาห์ตามความรู้สึกว่า "แพลตฟอร์มนี้กำลังดี" โดยไม่รอให้ครบรอบทดสอบ
- เทียบ ROAS ที่รายงานในระบบของแต่ละแพลตฟอร์มตรงๆ โดยไม่ตระหนักถึงปัญหา Attribution Overlap (ดู Step 915)
- ทดสอบด้วยงบน้อยเกินไปจนไม่ผ่าน Learning Phase แล้วรีบสรุปว่าแพลตฟอร์มนั้น "ไม่เหมาะกับธุรกิจนี้"
- ไม่บันทึกสภาวะตลาด/เหตุการณ์พิเศษ (โปรโมชั่น, ข่าว, วันหยุด) ที่เกิดขึ้นระหว่างการทดสอบ ทำให้ตีความผลผิดพลาดในภายหลัง

## Step 913: Trigger การปรับสัดส่วนงบ

### เหตุผลที่ต้องมี Trigger ที่ชัดเจน

ถ้าไม่มีเกณฑ์ที่ชัดเจนล่วงหน้า การปรับงบจะกลายเป็นเรื่องของความรู้สึกและอคติ (เช่น ชอบดู TikTok ก็เลยอยากลงงบ TikTok มากกว่า) การกำหนด Trigger ทั้งเชิงตัวเลขและเชิงคุณภาพไว้ล่วงหน้าช่วยให้การตัดสินใจเป็นระบบและอธิบายให้ลูกค้า/เจ้าของธุรกิจเข้าใจได้ง่าย

### Trigger เชิงตัวเลข (Quantitative Triggers)

| Trigger | เกณฑ์แนะนำ | การตอบสนอง |
|---|---|---|
| Blended ROAS ต่ำกว่า Break-even ต่อเนื่อง | 3-5 วันติดต่อกัน | ลดงบรวมทั้งระบบ 10-20% ก่อนตัดสินใจว่าแพลตฟอร์มไหนมีปัญหา |
| ROAS ของแพลตฟอร์มหนึ่งสูงกว่าอีกแพลตฟอร์ม 40%+ ต่อเนื่อง 2 รอบทดสอบ | 2 รอบทดสอบ (4 สัปดาห์ขึ้นไป) | โยกงบเพิ่ม 10-20% ไปแพลตฟอร์มที่ดีกว่า |
| Marginal ROAS ของงบที่เพิ่มล่าสุดต่ำกว่า Break-even | ทันทีที่ตรวจพบ | หยุดเพิ่มงบแพลตฟอร์มนั้น แม้ ROAS เฉลี่ยรวมยังดูดีอยู่ |
| CPA Rolling 7-Day เพิ่มขึ้น 30%+ จาก Rolling 7-Day ก่อนหน้า | ต่อเนื่อง 2 ช่วง 7 วัน | ตรวจสอบสาเหตุก่อนตัดสินใจลดงบ (อาจเป็น Ad Fatigue ไม่ใช่ปัญหาสัดส่วน) |
| Frequency สูงเกินเกณฑ์ของแพลตฟอร์มนั้นต่อเนื่อง | ตามเกณฑ์แต่ละแพลตฟอร์ม (ทบทวน Part 060, Part 086) | เพิ่มความหลากหลาย Creative ก่อนลดงบ ไม่ใช่ลดงบทันที |

### Trigger เชิงคุณภาพ (Qualitative Triggers)

- **ครีเอทีฟหมดไอเดียบนแพลตฟอร์มหนึ่ง** — ถ้าทีม Creative ผลิตคอนเทนต์ TikTok ไม่ทันต่อความเร็วของ Fatigue ควรลดงบ TikTok ชั่วคราวแล้วโยกไป Facebook จนกว่าจะมีคอนเทนต์ใหม่พร้อม
- **ทีมงานไม่มีเวลาดูแลสองแพลตฟอร์มพร้อมกันในมาตรฐานเดียวกัน** — ดีกว่าจะรันแพลตฟอร์มเดียวให้ดีมาก แทนที่จะรันสองแพลตฟอร์มแบบครึ่งๆกลางๆ
- **ปัญหานโยบาย/บัญชีถูกจำกัด** — ถ้าบัญชีหนึ่งมีความเสี่ยงถูกระงับ ควรกระจายงบให้อีกแพลตฟอร์มมากขึ้นชั่วคราวเป็นการกระจายความเสี่ยง (Risk Diversification)
- **สัญญาณตลาด/คู่แข่ง** — ถ้าคู่แข่งหลักเพิ่งอัดงบหนักบนแพลตฟอร์มหนึ่งจนราคาประมูลพุ่งสูงผิดปกติ ควรพิจารณาลดน้ำหนักชั่วคราวจนกว่าราคาจะกลับสู่ระดับปกติ
- **Feedback เชิงคุณภาพจากทีมขาย/CS** — ถ้าทีมขายรายงานว่าลูกค้าจากแพลตฟอร์มหนึ่งมีคุณภาพต่ำกว่า (ถามคำถามมาก ปิดการขายยาก) แม้ CPA จะดูถูกกว่าในระบบ ควรนำ Feedback นี้มาถ่วงน้ำหนักการตัดสินใจด้วย

### หลักการปรับแบบ Step ไม่ใช่ All-in

ข้อผิดพลาดที่พบบ่อยคือการเห็น Trigger แล้วโยกงบทั้งหมดไปแพลตฟอร์มเดียวทันที วิธีที่ปลอดภัยกว่าคือปรับทีละ 10-20% ของงบรวมต่อรอบ แล้วสังเกตผล 1-2 สัปดาห์ก่อนปรับรอบต่อไป การปรับแบบค่อยเป็นค่อยไปช่วยให้:

1. ไม่กระทบ Learning Phase ของแพลตฟอร์มที่ถูกลดงบรุนแรงเกินไปจนเรียนรู้ใหม่ทั้งหมด
2. มีเวลาสังเกตว่าผลลัพธ์ที่ดีขึ้น/แย่ลงเป็นผลจากสัดส่วนงบจริงหรือจากปัจจัยอื่นที่เกิดขึ้นพร้อมกัน
3. ลดความเสี่ยงจากการตัดสินใจผิดที่ส่งผลกระทบรุนแรงต่อยอดขายรวม

### ตาราง Trigger Matrix สรุป

| สถานการณ์ | ปรับเพิ่มงบให้ | ปรับลดงบจาก | ขนาดการปรับ |
|---|---|---|---|
| ROAS แพลตฟอร์ม A สูงกว่า B ต่อเนื่อง 2 รอบ | A | B | 10-20% |
| Marginal ROAS ของ A ต่ำกว่า Break-even | คงที่ | A | หยุดเพิ่ม ไม่ต้องลดจนกว่ามีข้อมูลเพิ่ม |
| Creative Fatigue รุนแรงบน B ทีมผลิตไม่ทัน | A (ชั่วคราว) | B (ชั่วคราว) | 15-25% จนกว่า Creative ใหม่พร้อม |
| บัญชี A มีความเสี่ยงถูกจำกัด | B | A (ชั่วคราว) | ตามความเสี่ยง อาจสูงถึง 30-40% |
| เทศกาล/เทรนด์ที่เหมาะกับ B มากเป็นพิเศษ | B | A (ชั่วคราว) | ตาม Step 917 |

### ข้อผิดพลาดที่พบบ่อย

- ปรับงบตาม ROAS ของวันเดียวหรือสัปดาห์เดียวที่ผันแปรสูง โดยไม่รอ Rolling Average ที่มีนัยสำคัญ
- โยกงบทั้งหมดจากแพลตฟอร์มหนึ่งไปอีกแพลตฟอร์มทันทีเมื่อเห็น Trigger แรก ไม่ปรับแบบค่อยเป็นค่อยไป
- ไม่บันทึก Trigger และการตัดสินใจแต่ละครั้งเป็นเอกสาร ทำให้ไม่สามารถย้อนดูภายหลังว่าการปรับที่ผ่านมาได้ผลจริงหรือไม่

## Step 914: Blended CAC และ Blended ROAS

### ทำไมต้องคิดแบบ Blended

เมื่อรันทั้งสองแพลตฟอร์มพร้อมกัน การดู CAC/ROAS แยกแพลตฟอร์มอย่างเดียวจะทำให้เข้าใจผิดได้ง่าย เพราะแต่ละแพลตฟอร์มมักรายงาน ROAS ที่ "ดูดี" พร้อมกันทั้งคู่ (จากปัญหา Attribution Overlap ที่จะอธิบายเจาะลึกใน Step 915) แต่ยอดขายจริงของธุรกิจไม่ได้เพิ่มขึ้นตามสัดส่วนที่ตัวเลขบอก

### สูตรคำนวณ Blended CAC และ Blended ROAS

**Blended CAC** = (งบ Facebook + งบ TikTok) ÷ จำนวนลูกค้าใหม่ที่ได้จริง (นับจากระบบหลังบ้าน ไม่ใช่นับจาก Conversion ที่แต่ละแพลตฟอร์มรายงาน)

**Blended ROAS** = รายได้จริงที่มาจากช่องทางโฆษณาทั้งหมด (ยืนยันจากระบบขาย/บัญชี) ÷ (งบ Facebook + งบ TikTok)

จุดสำคัญที่สุดคือ **ตัวเศษ (จำนวนลูกค้า/รายได้) ต้องมาจากระบบหลังบ้านของธุรกิจ (Order System, POS, Shopify Admin, ระบบบัญชี) ไม่ใช่นับจากตัวเลข Conversion ที่ Ads Manager ของแต่ละแพลตฟอร์มรายงาน** เพราะการนับจาก Ads Manager ทั้งสองแพลตฟอร์มแล้วรวมกันจะเกิดการนับซ้ำ (Double-Counting) จากปัญหา Attribution Overlap

### ตัวอย่างคำนวณเชิงตัวเลข

สมมติเดือนหนึ่ง:

- งบ Facebook: 100,000 บาท → Facebook Ads Manager รายงาน Purchase 200 รายการ รายได้ที่ระบบอ้าง 500,000 บาท (ROAS 5.0)
- งบ TikTok: 80,000 บาท → TikTok Ads Manager รายงาน Purchase 150 รายการ รายได้ที่ระบบอ้าง 360,000 บาท (ROAS 4.5)
- **ถ้ารวมตัวเลขที่แต่ละระบบอ้างตรงๆ:** Purchase รวม 350 รายการ, รายได้รวม 860,000 บาท, งบรวม 180,000 บาท → ROAS ที่ดูเหมือนได้ 4.78

- **แต่ระบบหลังบ้านจริง (Order System) รายงานยอดขายเดือนนั้นทั้งหมด 620,000 บาท จาก 280 Order** (เพราะมี Overlap ที่ทั้งสองแพลตฟอร์มอ้างสิทธิ์ลูกค้าคนเดียวกันประมาณ 70 Order)

**Blended ROAS ที่แท้จริง** = 620,000 ÷ 180,000 = **3.44** (ต่ำกว่าตัวเลขที่แต่ละแพลตฟอร์มอ้างรวมกันอย่างมีนัยสำคัญ)

**Blended CAC ที่แท้จริง** = 180,000 ÷ 280 = **643 บาทต่อลูกค้าใหม่** (สูงกว่าที่คำนวณจากตัวเลขแต่ละแพลตฟอร์มแยกกัน)

ตัวเลขนี้คือความจริงที่ใช้ตัดสินใจเชิงธุรกิจได้ ส่วนตัวเลข ROAS 5.0 และ 4.5 ที่แต่ละแพลตฟอร์มรายงาน ใช้ได้แค่สำหรับ **เปรียบเทียบประสิทธิภาพเชิงสัมพัทธ์ระหว่างแคมเปญภายในแพลตฟอร์มเดียวกันเท่านั้น** ไม่ควรใช้ตัดสินใจเชิงธุรกิจข้ามแพลตฟอร์ม

### การกระทบยอด (Reconciliation) กับ Revenue จริง

ขั้นตอนแนะนำสำหรับการกระทบยอดรายเดือน:

1. ดึงยอดขายจริงทั้งหมดจากระบบหลังบ้าน (Order System/POS/บัญชี) แยกตามช่วงเวลาเดียวกันกับที่รันแอด
2. หักยอดขายที่มาจากช่องทาง Organic/ไม่เกี่ยวกับโฆษณาออกก่อน (ใช้ UTM/Source Tracking จาก Part 089-091)
3. เทียบยอดขายที่เหลือ (ที่มาจากโฆษณาทั้งหมด) กับผลรวมงบ Facebook + TikTok เพื่อได้ Blended ROAS ที่แท้จริง
4. ใช้ Blended ROAS นี้เป็นตัวเลขหลักในการรายงานผลต่อผู้บริหาร/ลูกค้า ส่วนตัวเลขแยกแพลตฟอร์มใช้เป็นข้อมูลเสริมเพื่อวิเคราะห์รายละเอียดภายใน

### ข้อผิดพลาดที่พบบ่อย

- รายงานผลต่อลูกค้า/เจ้าของธุรกิจโดยรวม ROAS ของทั้งสองแพลตฟอร์มแบบบวกตรงๆ ทำให้ดูดีเกินจริงและตั้งเป้าหมายผิดสำหรับเดือนถัดไป
- ไม่มีระบบกระทบยอดกับ Revenue จริงเลย ใช้ตัวเลขจาก Ads Manager เป็นความจริงทั้งหมด
- คำนวณ Blended CAC โดยไม่หักลูกค้าเก่าที่กลับมาซื้อซ้ำออก (ควรคำนวณ CAC จากลูกค้าใหม่เท่านั้น แยกจาก Repeat Purchase)

## Step 915: ปัญหา Attribution Overlap

### กลไกที่ทำให้เกิด Overlap

ลองนึกภาพลูกค้าคนหนึ่ง: เห็นโฆษณา TikTok ตอนเช้า กดเข้าไปดูสินค้าแต่ยังไม่ซื้อ ตกเย็นเห็นโฆษณา Facebook ของสินค้าเดียวกัน (เพราะ Retargeting Pixel จับได้ว่าเคย View Content) กดซื้อจาก Facebook

- **Facebook Ads Manager** จะนับ Purchase นี้เป็นผลจากแคมเปญ Facebook (เพราะลูกค้าคลิกและซื้อภายใน Attribution Window ของ Facebook)
- **TikTok Ads Manager** ก็จะนับ Purchase นี้เป็นผลจากแคมเปญ TikTok เช่นกัน (เพราะ TikTok Pixel/Events API ก็จับได้ว่าลูกค้าคนนี้คลิกมาจาก TikTok ก่อนซื้อ ภายใน Attribution Window ของ TikTok เช่นกัน — ค่าเริ่มต้นมักเป็น 7-Day Click)

ผลคือ **ยอดขาย 1 รายการ ถูกนับเป็น Conversion 2 ครั้งในระบบของสองแพลตฟอร์มที่แยกจากกัน** โดยไม่มีแพลตฟอร์มใด "รู้" ว่าอีกแพลตฟอร์มก็นับไปแล้วเหมือนกัน เพราะแต่ละแพลตฟอร์มมองเห็นแค่ข้อมูลของตัวเอง

### ทำไมปัญหานี้ยิ่งรุนแรงขึ้นในยุค Privacy-First

หลัง iOS14+ และการจำกัด Third-Party Cookie ทำให้การติดตาม Cross-Platform Journey แบบสมบูรณ์ (รู้ทุกจุดสัมผัสของลูกค้าคนเดียวกัน) ยากขึ้นมาก แต่ละแพลตฟอร์มจึงยิ่งพึ่งพา Modeled Conversion และ Attribution ของตัวเองมากขึ้น ทำให้ปัญหา Overlap อาจซ่อนอยู่มากกว่าที่ตัวเลขแสดงให้เห็น

### วิธีจัดการแบบ Pragmatic (ใช้งานได้จริง ไม่ใช่ทฤษฎีสมบูรณ์แบบ)

การพยายามหา Attribution ที่ "ถูกต้อง 100%" ข้ามแพลตฟอร์มเป็นไปไม่ได้ในทางปฏิบัติสำหรับธุรกิจส่วนใหญ่ (ต้องมี Data Infrastructure ระดับ Enterprise) แนวทางที่ใช้งานได้จริงคือ:

1. **ยึด Blended Metrics เป็นหลักเสมอ** (จาก Step 914) — ไม่เถียงกันว่า "ใครปิดยอดขายนี้จริง" ระหว่างสองแพลตฟอร์ม แต่ดูภาพรวมว่างบรวมทั้งหมดสร้างผลตอบแทนรวมเท่าไหร่
2. **ใช้ Source/Medium จาก GA4 หรือ Last Non-Direct Click เป็นตัว Tie-Breaker รอง** สำหรับการวิเคราะห์เชิงลึกภายใน (ไม่ใช่การตัดสินใจงบระดับใหญ่) เพื่อดูแนวโน้มว่าแพลตฟอร์มไหนมักเป็นจุดสัมผัสแรก (First Touch) และแพลตฟอร์มไหนมักเป็นจุดปิดยอดขาย (Last Touch)
3. **ทำ Incrementality Testing เป็นระยะ** (Step 916) เพื่อรู้ผลตอบแทนจริงที่ไม่ผ่านอคติของ Attribution เลย — นี่คือวิธีที่แม่นยำที่สุดในระยะยาว
4. **ตกลงกันในทีมล่วงหน้าว่าจะไม่ใช้ตัวเลข Attributed Conversion ของแต่ละแพลตฟอร์มมาเถียงแย่งผลงานกัน** ระหว่างทีม Facebook และทีม TikTok (ถ้าเป็นทีมแยก) เพราะจะกลายเป็นการเมืองภายในที่ไม่สร้างประโยชน์ต่อธุรกิจ

### การ Reconciliation แบบ Manual Matching Order ID — ทำได้แต่ไม่ Scale

สำหรับธุรกิจขนาดเล็กที่มี Order ไม่มาก อาจลองจับคู่ Order ID กับ Click ID ของทั้งสองแพลตฟอร์ม (ผ่าน UTM/Server-Side Log) เพื่อดูว่า Order ไหนถูกนับซ้ำจริง วิธีนี้ให้ความแม่นยำสูงแต่ **ใช้เวลามากและไม่ Scale ได้กับธุรกิจที่มี Order หลักร้อยหลักพันต่อวัน** ควรใช้เป็นการสุ่มตรวจ (Audit) เป็นครั้งคราวเพื่อประเมินขนาดของปัญหา Overlap มากกว่าทำเป็นประจำทุกวัน

### ตัวอย่างเคสตัวเลข Overlap

จากตัวอย่างใน Step 914: Facebook รายงาน Purchase 200, TikTok รายงาน Purchase 150, รวมกันตรงๆ = 350 แต่ระบบหลังบ้านจริงมี Order เพียง 280 → **ส่วนต่าง 70 Order (20% ของยอดรวมที่แต่ละแพลตฟอร์มอ้าง) คือ Overlap ที่ถูกนับซ้ำ** การรู้ขนาดของ Overlap นี้ (แม้จะประมาณ ไม่ต้องแม่นยำ 100%) ช่วยให้ประเมินตัวเลข Blended ที่แม่นยำขึ้นในรอบถัดไปได้

### ข้อผิดพลาดที่พบบ่อย

- พยายามหาว่า "แพลตฟอร์มไหนปิดยอดขายจริง" อย่างจริงจังเกินไปจนเสียเวลาและทรัพยากรมากกว่าประโยชน์ที่ได้
- ใช้ Attributed ROAS ของแต่ละแพลตฟอร์มเป็นเกณฑ์ตัดสินใจงบระดับใหญ่โดยไม่ปรับด้วย Blended Metrics ก่อน
- ปล่อยให้ทีม Facebook และทีม TikTok แย่งเครดิตผลงานกันจากตัวเลข Attribution ที่รู้อยู่แล้วว่ามี Overlap สูง

## Step 916: Incrementality Testing ข้ามแพลตฟอร์ม (Holdout Test)

### นิยาม Incrementality และทำไม Attributed Metrics ไม่พอ

**Incrementality** คือคำถามว่า "ถ้าไม่ได้ลงโฆษณาแพลตฟอร์มนี้เลย ยอดขายจะลดลงเท่าไหร่จริง" ซึ่งต่างจาก Attributed Conversion ที่บอกแค่ว่า "ระบบคิดว่าลูกค้าคนนี้มาจากไหน" — ลูกค้าบางคนจะซื้อสินค้าอยู่แล้วแม้ไม่เห็นโฆษณา (เช่น ลูกค้าประจำที่ตั้งใจกลับมาซื้อ) แต่ระบบ Attribution ก็ยังนับเป็น Conversion จากโฆษณาถ้าลูกค้าคนนั้นบังเอิญคลิกโฆษณาก่อนซื้อ

Blended ROAS ที่คำนวณใน Step 914 ยังคง "Overstate" ผลจากโฆษณาอยู่บ้าง เพราะรวมยอดขายที่จะเกิดขึ้นอยู่แล้วไว้ด้วย Incrementality Test คือวิธีเดียวที่ตัดปัจจัยนี้ออกและบอกผลตอบแทน "ที่แท้จริง" จากการลงโฆษณา

### วิธี Geo Holdout Test ข้ามแพลตฟอร์ม

**หลักการ:** แบ่งพื้นที่ทางภูมิศาสตร์ (จังหวัด/ภูมิภาค) เป็นกลุ่มทดสอบและกลุ่มควบคุม

**ขั้นตอน:**
1. เลือกพื้นที่ที่มีลักษณะประชากรและยอดขายใกล้เคียงกัน แบ่งเป็น 2 กลุ่ม (เช่น กลุ่ม A = ภาคกลาง+ภาคใต้, กลุ่ม B = ภาคเหนือ+ภาคอีสาน)
2. เปิด TikTok ตามปกติในกลุ่ม A แต่ปิด TikTok สนิท (Exclude Location) ในกลุ่ม B เป็นเวลา 2-4 สัปดาห์ (ยัง Run Facebook ตามปกติทั้งสองกลุ่ม)
3. เทียบยอดขายรวม (จากระบบหลังบ้าน แยกตามพื้นที่จัดส่ง) ระหว่างกลุ่ม A กับกลุ่ม B ในช่วงเวลาเดียวกัน
4. ส่วนต่างของยอดขายระหว่างสองกลุ่ม (หลังปรับตามขนาดตลาดพื้นฐานของแต่ละกลุ่ม) คือ Incremental Contribution ของ TikTok จริง

### วิธี Time-Based Holdout Test

สำหรับธุรกิจที่ไม่สามารถแบ่ง Geo ได้ชัดเจน (เช่น ขายทั่วประเทศผ่านช่องทางเดียว) ใช้วิธีสลับเปิด-ปิดตามช่วงเวลาแทน:

1. เลือกสัปดาห์คู่ (Even Week) เปิด TikTok ตามปกติ, สัปดาห์คี่ (Odd Week) ปิด TikTok สนิท (ยัง Run Facebook ตามปกติทุกสัปดาห์)
2. ทำต่อเนื่องอย่างน้อย 6-8 สัปดาห์ (3-4 คู่) เพื่อลดผลกระทบจากความผันแปรรายสัปดาห์ปกติ
3. เทียบ Blended Revenue เฉลี่ยระหว่างสัปดาห์ที่เปิด TikTok กับสัปดาห์ที่ปิด
4. ส่วนต่างคือ Incremental Revenue จาก TikTok

**ข้อจำกัดของวิธีนี้:** ต้องระวังผล Carry-over (ลูกค้าที่เห็นโฆษณาสัปดาห์ที่เปิด แต่ซื้อในสัปดาห์ที่ปิด) ซึ่งทำให้ผลคลาดเคลื่อนได้บ้าง ควรเว้นช่วง Buffer 2-3 วันระหว่างการสลับเปิด-ปิด

### Conversion Lift Study ระดับ Enterprise

ทั้ง Meta และ TikTok มีเครื่องมือ Conversion Lift Study ให้บัญชีที่มีงบใหญ่พอ (มักต้องผ่าน Account Manager/Rep ของแพลตฟอร์ม) ซึ่งจะสุ่มแบ่งกลุ่มผู้ใช้เป็น Test/Control แบบอัตโนมัติในระดับ User ไม่ใช่ Geo ทำให้ได้ผลที่แม่นยำกว่าการทำ Geo/Time Holdout เอง แต่ต้องมีงบและ Volume Conversion สูงพอที่แพลตฟอร์มจะรับทำการทดสอบให้

### วิธีคำนวณ Incremental ROAS จาก Holdout

**Incremental ROAS** = Incremental Revenue (ส่วนต่างยอดขายจาก Holdout Test) ÷ งบที่ใช้ในแพลตฟอร์มนั้น

ตัวอย่าง: จาก Geo Holdout Test พบว่ากลุ่มที่เปิด TikTok มียอดขายเฉลี่ยสูงกว่ากลุ่มที่ปิด TikTok 180,000 บาทต่อเดือน (หลังปรับตามขนาดตลาดพื้นฐานแล้ว) ขณะที่งบ TikTok ที่ใช้ในกลุ่มนั้นเฉลี่ย 60,000 บาทต่อเดือน

**Incremental ROAS ของ TikTok = 180,000 ÷ 60,000 = 3.0**

เทียบกับ Attributed ROAS ที่ TikTok Ads Manager รายงานอาจอยู่ที่ 4.5 (ตามตัวอย่าง Step 914) — ส่วนต่างระหว่าง 4.5 กับ 3.0 คือ **ผลจากยอดขายที่จะเกิดขึ้นอยู่แล้วโดยไม่ต้องมีโฆษณา TikTok** ซึ่งเป็นข้อมูลสำคัญมากสำหรับการตัดสินใจงบระยะยาว

### ข้อผิดพลาดที่พบบ่อย

- ทำ Holdout Test สั้นเกินไป (น้อยกว่า 2 สัปดาห์) จนผลไม่มีนัยสำคัญทางสถิติ
- เลือกกลุ่มทดสอบและกลุ่มควบคุมที่มีลักษณะประชากร/ยอดขายพื้นฐานต่างกันมากเกินไป ทำให้เทียบกันไม่ได้อย่างยุติธรรม
- ทำ Holdout Test เพียงครั้งเดียวแล้วยึดผลตลอดไป ทั้งที่ Incrementality เปลี่ยนได้ตามช่วงเวลา/ฤดูกาล/สภาวะตลาด ควรทำซ้ำทุก 6-12 เดือน

### ตัวอย่างตารางเก็บผล Geo Holdout Test แบบละเอียด

การทำ Geo Holdout ให้ได้ผลที่เชื่อถือได้ ควรบันทึกข้อมูลรายสัปดาห์แบบนี้ตลอดช่วงทดสอบ 4 สัปดาห์ (ตัวอย่างสมมติของธุรกิจที่แบ่งภาคกลาง+ใต้เป็นกลุ่มเปิด TikTok และภาคเหนือ+อีสานเป็นกลุ่มปิด TikTok):

| สัปดาห์ | ยอดขายกลุ่มเปิด TikTok (บาท) | ยอดขายกลุ่มปิด TikTok (บาท) | งบ TikKok ที่ใช้ในกลุ่มเปิด (บาท) | ส่วนต่างยอดขาย (ปรับตามสัดส่วนขนาดตลาด) |
|---|---|---|---|---|
| 1 | 420,000 | 310,000 | 55,000 | +38,000 |
| 2 | 445,000 | 325,000 | 58,000 | +42,000 |
| 3 | 460,000 | 335,000 | 60,000 | +47,000 |
| 4 | 435,000 | 320,000 | 57,000 | +40,000 |
| **เฉลี่ย** | **440,000** | **322,500** | **57,500** | **+41,750** |

**หมายเหตุการปรับตามสัดส่วนขนาดตลาด:** สมมติว่ากลุ่มเปิด TikTok มีขนาดตลาดพื้นฐาน (Baseline Sales ก่อนทดสอบ ไม่รวมผลโฆษณา) ใหญ่กว่ากลุ่มปิด TikTok อยู่แล้วประมาณ 12% ต้องหักส่วนนี้ออกก่อนคำนวณส่วนต่างที่แท้จริง เพื่อไม่ให้ขนาดตลาดที่ต่างกันมาปนกับผลของโฆษณา

**Incremental ROAS = 41,750 ÷ 57,500 = 0.73 ต่อสัปดาห์... ** แต่เนื่องจากตัวเลขนี้คำนวณจากยอดขายสัปดาห์เดียว ต้องนำไปเทียบกับ Break-even ROAS ที่คำนวณจากหน่วยเวลาเดียวกัน (ไม่ใช่เทียบข้ามหน่วยเวลาโดยไม่ปรับ) — ในทางปฏิบัติควรคำนวณ Incremental ROAS แบบสะสมทั้งช่วงทดสอบ (รวมยอดขายและงบทั้ง 4 สัปดาห์) แทนการเฉลี่ยรายสัปดาห์ เพื่อลดผลจากความผันแปรระยะสั้น

## Step 917: Seasonal Reallocation

### หลักการพื้นฐาน: ธรรมชาติของแต่ละแพลตฟอร์มเหมาะกับฤดูกาลต่างกัน

TikTok มีจุดแข็งด้าน Discovery และการตอบสนองต่อเทรนด์ที่รวดเร็ว ทำให้เหมาะกับช่วงที่พฤติกรรมผู้บริโภคเป็นแบบ "เสพคอนเทนต์เพื่อหาไอเดีย/แรงบันดาลใจซื้อของ" สูงเป็นพิเศษ ในขณะที่ Facebook มีจุดแข็งด้าน Retargeting ที่แม่นยำ เหมาะกับช่วงที่มีฐาน Traffic/Cart Abandoner สะสมไว้มากที่ต้องไล่ปิดยอดขาย

### ช่วงที่ควรเพิ่มน้ำหนัก TikTok

- **ช่วงเทศกาลใหญ่ที่มีการ Discovery คอนเทนต์สูง** เช่น 11.11, 12.12, วันหยุดยาว ที่คนใช้เวลาบนแอปมากกว่าปกติ
- **ช่วงที่มีเทรนด์/Challenge ที่เกี่ยวข้องกับสินค้าธุรกิจกำลังไวรัล** ควบคู่กับการ Boost คอนเทนต์ผ่าน Spark Ads
- **ช่วงเปิดตัวสินค้าใหม่ที่ต้องการสร้าง Buzz/Awareness เร็ว** เพราะ TikTok มักได้ Reach ต่อบาทที่สูงกว่าในการสร้างการรับรู้เบื้องต้น
- **ช่วงที่กลุ่มเป้าหมายหลักเป็นวัยรุ่น/นักศึกษาปิดเทอม** ที่มีเวลาเสพคอนเทนต์มากกว่าปกติ

### ช่วงที่ควรเพิ่มน้ำหนัก Facebook

- **หลังจบ Flash Sale ใหญ่** ที่มี Cart Abandoner/Traffic สะสมจำนวนมากรอ Retarget
- **ช่วงปลายไตรมาส/ปลายปีที่ฐาน Custom Audience สะสมมานานพร้อมใช้งาน** เพื่อ Reactivate ลูกค้าเก่า
- **ช่วงเทศกาลที่พฤติกรรมเป็นการซื้อของขวัญ/วางแผนล่วงหน้า** (เช่น ก่อนปีใหม่ 2-3 สัปดาห์) ที่ผู้บริโภคมักพิจารณานานกว่าปกติ เหมาะกับ Funnel ที่มี Retargeting หลายขั้น
- **ช่วงที่ธุรกิจต้องการเน้นกลุ่มอายุ 35 ปีขึ้นไปเป็นพิเศษ** เช่น โปรโมชั่นสำหรับผู้ปกครอง/ผู้มีอำนาจซื้อในครอบครัว

### ปฏิทินตัวอย่างการวางแผนงบตามฤดูกาลสำหรับธุรกิจไทย

| ช่วงเวลา | เหตุการณ์ | น้ำหนัก TikTok | น้ำหนัก Facebook | เหตุผล |
|---|---|---|---|---|
| ปลายม.ค.-ก.พ. | ตรุษจีน | สูง (55-65%) | ปานกลาง (35-45%) | พฤติกรรม Discovery/ของฝากสูง คนเสพคอนเทนต์มาก |
| มี.ค.-เม.ย. | สงกรานต์ | สูง (55-60%) | ปานกลาง (40-45%) | เทรนด์/Challenge ตามฤดูกาลมาก คนอยู่บ้าน/เที่ยวเสพคอนเทนต์ |
| มิ.ย.-ก.ค. | Mid-Year Sale (6.6-7.7) | ปานกลาง-สูง (50%) | ปานกลาง (50%) | เน้นทั้ง Discovery และ Retargeting พร้อมกัน |
| ส.ค.-ก.ย. | เปิดเทอม | ปานกลาง (45%) | สูง (55%) | กลุ่มผู้ปกครอง/การตัดสินใจที่พิจารณานานกว่า |
| พ.ย. | 11.11 | สูงมาก (60-65%) | ปานกลาง (35-40%) | Peak Discovery Season ของทั้งปี |
| ธ.ค. | 12.12 + ปีใหม่ | สูง (55%) แล้วค่อยลดลงปลายเดือน | เพิ่มขึ้นปลายเดือน (45% → 55%) | ต้นเดือน Discovery แรง ปลายเดือนต้อง Retarget Cart Abandoner จำนวนมาก |
| ม.ค. (หลังปีใหม่) | Retargeting Cart จากช่วง 12.12 | ต่ำ (30-35%) | สูง (65-70%) | ฐาน Retargeting สะสมมากที่สุดของปี |

### วิธี Pre-plan งบล่วงหน้า

1. **4-6 สัปดาห์ก่อนช่วงพีค:** เริ่มปรับ Creative และเตรียม Ad Account ให้พร้อม (ทบทวน Part 062) พร้อมทดสอบสัดส่วนงบใหม่ในสเกลเล็กก่อน
2. **2-3 สัปดาห์ก่อนช่วงพีค:** เพิ่มงบตามสัดส่วนที่วางแผนไว้แบบค่อยเป็นค่อยไป ไม่เพิ่มทีเดียวทั้งหมดเพื่อไม่กระทบ Learning Phase ในช่วงที่สำคัญที่สุด
3. **ระหว่างช่วงพีค:** เฝ้าติดตาม Trigger จาก Step 913 อย่างใกล้ชิดกว่าปกติ (เช็ควันละ 2 ครั้งเป็นอย่างน้อย) เพราะการแข่งขันสูงทำให้สถานการณ์เปลี่ยนเร็ว
4. **หลังช่วงพีค:** ปรับกลับสู่สัดส่วนปกติแบบค่อยเป็นค่อยไป พร้อมเก็บ Custom Audience ใหม่ที่ได้จากช่วงพีคไว้ Retarget ต่อ (มักเป็นช่วงที่ Facebook ควรได้น้ำหนักเพิ่มตามที่อธิบายไว้ข้างต้น)

### ข้อผิดพลาดที่พบบ่อย

- ปรับสัดส่วนงบกะทันหันในวันที่เทศกาลเริ่มแล้ว ทำให้ไม่มีเวลาให้ Learning Phase ปรับตัวก่อนช่วงที่สำคัญที่สุด
- ใช้ปฏิทินเดียวกันทุกปีโดยไม่ปรับตามพฤติกรรมที่เปลี่ยนไปหรือผลการทดสอบจริงของธุรกิจตัวเอง
- ลืมปรับกลับสู่สัดส่วนปกติหลังช่วงพีค ทำให้เสียโอกาสจากแพลตฟอร์มที่ควรได้น้ำหนักคืนในช่วงถัดไป (เช่น ลืมเพิ่ม Facebook สำหรับ Retargeting หลัง 12.12)

### ตัวอย่างการวางแผน Pacing งบรายวันช่วง 11.11 (Zoom-in)

การวางแผนตามฤดูกาลไม่ควรหยุดแค่ระดับ "สัดส่วนรายเดือน" แต่ควรวางแผน Pacing รายวันช่วงเทศกาลสำคัญด้วย เพราะพฤติกรรมการซื้อในแต่ละวันของแคมเปญ 11.11 ต่างกันมาก:

| วัน | ช่วงเวลา | พฤติกรรมหลัก | น้ำหนัก TikTok | น้ำหนัก Facebook |
|---|---|---|---|---|
| 1-5 พ.ย. | Teaser | สร้าง Awareness/รอลุ้นโปร | สูง (65%) — เน้น Discovery/Viral Content | ต่ำ (35%) — เริ่มสร้าง Custom Audience จาก Engagement |
| 6-10 พ.ย. | Pre-sale | ลูกค้าเข้าดูสินค้า/กดจองล่วงหน้า | สูง (60%) | ปานกลาง (40%) — Retarget คนที่ Engage ช่วง Teaser |
| 11 พ.ย. | Peak Day | ซื้อจริงจำนวนมากในวันเดียว | ปานกลาง (45%) — ยังต้องจับคนที่ยังไม่เห็นโปร | สูง (55%) — Retarget เต็มกำลังไปยัง Cart/Engager สะสมทั้งหมด |
| 12-15 พ.ย. | Post-sale/Cart Recovery | ไล่ปิดคนที่ยังไม่ได้ซื้อ | ต่ำ (30%) | สูงมาก (70%) — Retargeting Funnel เข้มข้นที่สุดของทั้งแคมเปญ |

ตารางนี้แสดงให้เห็นว่าแม้สัดส่วนรายเดือนโดยรวมอาจอยู่ที่ TikTok 60:Facebook 40 ตามตารางปฏิทินก่อนหน้า แต่การ Pacing ราย 4-5 วันย่อยภายในเดือนเดียวกันต้องปรับกลับไปกลับมาตามพฤติกรรมลูกค้าที่เปลี่ยนเร็วมากในช่วงเทศกาล

### ข้อสังเกตเรื่องความแตกต่างระหว่างภูมิภาค/กลุ่มธุรกิจ

ปฏิทินที่แนะนำในตารางก่อนหน้าเป็นค่าเฉลี่ยกว้างๆ ธุรกิจแต่ละประเภทควรปรับตามลักษณะเฉพาะของตนเอง เช่น ธุรกิจ B2B ที่ลูกค้าเป็นองค์กรจะไม่ได้รับผลกระทบจากเทศกาลผู้บริโภคทั่วไปมากเท่าธุรกิจ B2C และควรมีปฏิทินของตัวเองที่อิงตามรอบงบประมาณองค์กร (เช่น ต้นปีงบประมาณ, ไตรมาสสุดท้ายก่อนปิดงบ) แทนที่จะอิงตามเทศกาลผู้บริโภคทั่วไป

## Step 918: Skillset และโครงสร้างทีมที่ต้องมีเมื่อรันสองแพลตฟอร์มพร้อมกัน

### ความแตกต่างของ Skillset ที่ต้องการ

| ด้าน | Facebook ต้องการ | TikTok ต้องการ |
|---|---|---|
| Testing Methodology | Structured A/B Testing ที่ละเอียด (ทบทวน Part 043-044) | Volume-based Testing ที่เร็วและปริมาณมาก |
| Creative Pipeline | คุณภาพสูง ผลิตน้อยกว่าแต่ทนทานนานกว่า | ปริมาณสูง ผลิตต่อเนื่อง ตามเทรนด์ทัน |
| ความรู้ Data/Attribution | ลึกเรื่อง Pixel/CAPI/Event Match Quality | ลึกเรื่อง Events API แต่ยังต้องตามความเปลี่ยนแปลง Feature บ่อยกว่า |
| Trend Awareness | ไม่จำเป็นมาก | จำเป็นมากและต้องอัปเดตแทบทุกวัน |
| Community/Culture Sense | มีประโยชน์แต่ไม่ critical | Critical มาก ต้องเข้าใจภาษา/มุกที่ Native กับแพลตฟอร์ม |

### โครงสร้างทีมตามขนาดธุรกิจ

**ธุรกิจ SME/สตาร์ทอัพ (งบโฆษณารวมต่ำกว่า 200,000 บาท/เดือน):** แนะนำให้คนเดียวหรือทีมเล็ก (2-3 คน) ดูแลทั้งสองแพลตฟอร์ม โดยแบ่งบทบาทเป็น 1 คนโฟกัส Strategy/Data ข้ามแพลตฟอร์ม และอีกคนโฟกัส Creative Production ที่ปรับให้เข้ากับทั้งสองแพลตฟอร์มได้

**ธุรกิจกลาง-ใหญ่ (งบ 200,000-1,000,000 บาท/เดือนขึ้นไป):** แนะนำ Specialist แยกตามแพลตฟอร์ม (Facebook Specialist 1 คน, TikTok Specialist 1 คน) บวกกับตำแหน่ง **Cross-Platform Analyst** 1 คนที่ดู Dashboard รวม (จาก Part 091), คำนวณ Blended Metrics, และเป็นผู้ตัดสินใจสัดส่วนงบสุดท้ายเพื่อไม่ให้ Specialist แต่ละคนตัดสินใจแบบเข้าข้างแพลตฟอร์มตัวเอง

**เอเจนซี่ที่ดูแลหลายลูกค้า:** จัดเป็น Pod ที่มี Facebook Specialist + TikTok Specialist + Account Manager ต่อกลุ่มลูกค้า โดย Account Manager รับผิดชอบการตัดสินใจสัดส่วนงบและสื่อสารกับลูกค้า (รายละเอียดเชิงลึกเรื่องเอเจนซี่จะอยู่ใน Section K ที่กำลังจะเริ่มถัดจาก Part นี้)

### เครื่องมือที่ต้องแชร์กันระหว่างทีม

1. **Dashboard กลางเดียว** ที่รวมข้อมูลทั้งสองแพลตฟอร์ม (ทบทวน Part 091) — ไม่ใช่ให้แต่ละทีมดู Dashboard ของตัวเองแยกกันแล้วมาเถียงกันทีหลัง
2. **Naming Convention มาตรฐานเดียวกัน** สำหรับ Campaign/Ad Set/Ad ทั้งสองแพลตฟอร์ม เพื่อให้ดึงข้อมูลมาเทียบกันได้ง่าย (ทบทวน Part 016)
3. **UTM Parameter มาตรฐานเดียวกัน** ที่ระบุแพลตฟอร์ม/แคมเปญ/ครีเอทีฟชัดเจน เพื่อให้ GA4/Dashboard แยกแหล่งที่มาได้ถูกต้อง (ทบทวน Part 089)
4. **ปฏิทินการสื่อสารประจำสัปดาห์** ที่ทั้งสองทีมมารายงานผลร่วมกันต่อ Cross-Platform Analyst/Account Manager เพื่อตัดสินใจสัดส่วนงบร่วมกัน ไม่ใช่แต่ละทีมตัดสินใจแยกกันเอง

### การสื่อสารเพื่อไม่ให้การตัดสินใจงบขัดแย้งกัน

ปัญหาที่พบบ่อยในทีมที่แยก Specialist คือแต่ละคนอยากได้งบเพิ่มให้แพลตฟอร์มตัวเอง (เพราะ KPI ส่วนตัวผูกกับผลงานแพลตฟอร์มนั้น) วิธีแก้คือ:

1. ตั้ง KPI ของทั้งทีมให้ผูกกับ **Blended ROAS/CAC ของธุรกิจโดยรวม** ไม่ใช่ ROAS แยกแพลตฟอร์มของแต่ละคน
2. ให้การตัดสินใจสัดส่วนงบขั้นสุดท้ายอยู่ที่คนกลาง (Cross-Platform Analyst/Account Manager) ที่ไม่มีผลประโยชน์ทับซ้อนกับแพลตฟอร์มใดแพลตฟอร์มหนึ่ง
3. ใช้ข้อมูลจาก Trigger Matrix (Step 913) และ Scorecard (Step 911) เป็นหลักฐานอ้างอิงในการประชุม ไม่ใช่ความรู้สึก/อคติส่วนตัว

### ข้อผิดพลาดที่พบบ่อย

- ให้ Specialist แต่ละแพลตฟอร์มเป็นคนตัดสินใจสัดส่วนงบเอง โดยไม่มีคนกลางที่มองภาพรวมทั้งธุรกิจ
- ตั้ง KPI ส่วนตัวของทีมผูกกับ ROAS แยกแพลตฟอร์ม ทำให้เกิดแรงจูงใจที่ขัดกับผลประโยชน์ของธุรกิจโดยรวม
- ปล่อยให้ Naming Convention/UTM ของสองแพลตฟอร์มไม่สอดคล้องกัน ทำให้ Dashboard กลางใช้งานไม่ได้จริงและต้องเสียเวลา Manual Matching ทุกเดือน

### ตัวอย่างโครงสร้างทีมและ KPI สำหรับธุรกิจกลาง-ใหญ่

| ตำแหน่ง | ความรับผิดชอบหลัก | KPI หลักที่ผูก |
|---|---|---|
| Facebook Specialist | สร้าง/ดูแลแคมเปญ Facebook, Testing Creative, Optimization รายวัน | Facebook CPA/ROAS ภายในกรอบ Blended ROAS ที่ตกลงกัน |
| TikTok Specialist | สร้าง/ดูแลแคมเปญ TikTok, ผลิต/ทดสอบ Creative ปริมาณสูง, ตาม Trend | TikTok CPA/ROAS ภายในกรอบ Blended ROAS ที่ตกลงกัน |

## Case Study: ร้านเครื่องสำอาง "Glowlab" ปรับสัดส่วนงบข้ามแพลตฟอร์มใน 6 เดือน

### สถานการณ์เริ่มต้น

Glowlab เป็นแบรนด์เครื่องสำอางออนไลน์ ขายผ่าน Facebook Ads มา 2 ปี มี Custom Audience สะสมกว่า 80,000 คน ROAS เฉลี่ยบน Facebook อยู่ที่ 3.8 เจ้าของแบรนด์ต้องการเริ่มลง TikTok เพราะเห็นคู่แข่งหลายรายเติบโตเร็วบนแพลตฟอร์มนี้ แต่ไม่รู้ว่าควรแบ่งงบเท่าไหร่ และกังวลว่าถ้าเริ่ม TikTok จะกระทบผลงาน Facebook ที่ทำได้ดีอยู่แล้วหรือไม่

### เดือนที่ 1: Decision Scorecard และ Starting Split

ทีมทำ Scorecard ตาม Step 911 พบว่า Facebook ได้คะแนนสูงกว่าใน Retargeting Pool (เพราะมี Custom Audience สะสมมาก) แต่ TikTok ได้คะแนนสูงกว่าในด้านอายุกลุ่มเป้าหมาย (ลูกค้าใหม่ที่แบรนด์อยากขยายไปคืออายุ 18-24 ปี ซึ่งเป็นกลุ่มที่ Facebook เข้าถึงได้จำกัดมากขึ้นเรื่อยๆ) และประเภทการซื้อ (เครื่องสำอางราคา 300-800 บาท เป็น Impulse Buy ที่เหมาะกับ TikTok)

ทีมตัดสินใจใช้ Starting Split ตามหลักการ "มี Data Facebook อยู่แล้ว ยังไม่เคยลอง TikTok" คือ **Facebook 75% : TikTok 25%** ของงบรวม 300,000 บาท/เดือน

### เดือนที่ 2-3: ทดสอบตาม Test Plan

ทีมรัน Test Plan ตาม Step 912 เก็บ Baseline 2 สัปดาห์แรก แล้วเก็บข้อมูลต่อเนื่องอีก 2 สัปดาห์ พบว่า TikTok ทำ CPM ถูกกว่า Facebook มากถึง 40% และ CPA ของ TikTok (เมื่อดูจากตัวเลขที่ระบบรายงานเอง) ต่ำกว่า Facebook 15% แต่ทีมยังไม่รีบสรุป เพราะจำนวน Conversion บน TikTok ยังไม่ถึง 50 รายการในช่วงทดสอบแรก

### เดือนที่ 4: คำนวณ Blended Metrics และพบ Overlap

หลังจับคู่ยอดขายกับระบบหลังบ้าน (Shopify Admin) ทีมพบว่ายอดขายจริงเดือนนั้นต่ำกว่าตัวเลขที่ Facebook + TikTok รายงานรวมกันประมาณ 18% ซึ่งตรงกับปัญหา Attribution Overlap ตาม Step 915 — ทีมจึงปรับมาใช้ Blended ROAS เป็นตัวชี้วัดหลักในการรายงานต่อเจ้าของแบรนด์ตั้งแต่เดือนนี้เป็นต้นไป และเลิกใช้ ROAS แยกแพลตฟอร์มในการรายงานผลภาพรวม

### เดือนที่ 5: ปรับสัดส่วนงบตาม Trigger

Blended ROAS โดยรวมดีขึ้นจากการมี TikTok เข้ามาเสริม (จาก 3.8 เดิมเฉพาะ Facebook เป็น Blended 4.1) และ Marginal ROAS ของงบ TikTok ที่เพิ่มขึ้นยังสูงกว่า Break-even ทีมจึงปรับสัดส่วนเป็น **Facebook 60% : TikTok 40%** ตามหลักการปรับทีละ Step (Step 913)

### เดือนที่ 6: ทำ Time-Based Holdout Test

เพื่อยืนยันว่า TikTok สร้างผลตอบแทนที่เป็น Incremental จริง ไม่ใช่แค่ดึงยอดขายที่จะเกิดจาก Facebook อยู่แล้วมา ทีมทำ Time-Based Holdout ตาม Step 916 สลับปิด-เปิด TikTok เป็นรายสัปดาห์ 6 สัปดาห์ พบว่า Incremental ROAS ของ TikTok อยู่ที่ 2.6 (ต่ำกว่า Attributed ROAS ที่ระบบรายงานซึ่งอยู่ที่ 3.9 แต่ยังสูงกว่า Break-even ของธุรกิจที่ 1.8 อย่างชัดเจน) ทีมจึงมั่นใจว่าการลงงบ TikTok เป็นการตัดสินใจที่ถูกต้องและคงสัดส่วน 60/40 ต่อไปพร้อมวางแผนปรับเพิ่มในช่วง 11.11 ที่กำลังจะมาถึงตามปฏิทิน Seasonal Reallocation

### บทเรียนจาก Case Study นี้

1. การมี Custom Audience สะสมจาก Facebook ไม่ได้แปลว่าต้องปิดโอกาสของ TikTok — Scorecard ช่วยชี้จุดที่ TikTok เหนือกว่าได้ชัดเจน
2. ตัวเลข ROAS ที่แต่ละแพลตฟอร์มรายงานเองอาจเกินจริงจากทั้ง Overlap และ Incrementality — ต้องผ่านทั้งสองขั้นการตรวจสอบก่อนเชื่อเต็มที่
3. การปรับสัดส่วนงบแบบค่อยเป็นค่อยไปพร้อมข้อมูลรองรับทุกขั้น ทำให้ธุรกิจเติบโตได้โดยไม่เสี่ยงเสียผลงานเดิมที่ทำได้ดีอยู่แล้ว

### ตารางสรุปตัวเลข Blended Metrics ของ Glowlab ตลอด 6 เดือน

| เดือน | งบรวม (บาท) | Split FB:TikTok | Attributed ROAS รวม (บวกตรงๆ) | Blended ROAS จริง | ส่วนต่าง (Overlap+Incrementality) |
|---|---|---|---|---|---|
| 1 | 300,000 | 75:25 | — (Baseline) | — | — |
| 2 | 300,000 | 75:25 | 3.85 | 3.60 | 6.5% |
| 3 | 310,000 | 75:25 | 4.05 | 3.75 | 7.4% |
| 4 | 320,000 | 70:30 | 4.30 | 4.10 (หลังพบ Overlap 18%) | 4.7% |
| 5 | 330,000 | 60:40 | 4.45 | 4.10 | 7.9% |
| 6 | 340,000 | 60:40 | 4.60 (Attributed) / Incremental TikTok 2.6 | 4.15 (Blended) | เห็นภาพครบทั้ง Overlap และ Incrementality |

ตารางนี้แสดงให้เห็นว่าตัวเลข "ที่ดูดีขึ้นเรื่อยๆ" ในคอลัมน์ Attributed ROAS ไม่ได้สะท้อนการเติบโตที่แท้จริงทั้งหมด — ส่วนที่เพิ่มขึ้นจริงและยั่งยืนคือคอลัมน์ Blended ROAS ที่ผ่านการกระทบยอดกับระบบหลังบ้านแล้ว

## Case Study เสริม: เอเจนซี่เล็กจัดการ 3 ลูกค้าที่มีสัดส่วนงบต่างกันสิ้นเชิง

เอเจนซี่ขนาดเล็กทีมงาน 4 คนดูแลลูกค้า 3 ราย ทั้งหมดเป็นธุรกิจอีคอมเมิร์ซแต่มีลักษณะต่างกันมาก ทีมใช้ Decision Scorecard เดียวกันแต่ได้ผลลัพธ์ต่างกันโดยสิ้นเชิง ซึ่งเป็นตัวอย่างที่ดีว่าทำไม "สัดส่วนงบสากล" ไม่มีจริง:

| ลูกค้า | ประเภทสินค้า | อายุกลุ่มเป้าหมาย | สัดส่วนที่ Scorecard แนะนำ | ผลหลังทดสอบ 2 เดือน |
|---|---|---|---|---|
| ลูกค้า A — เสื้อผ้าสตรีทแฟชั่น | ราคา 250-600 บาท | 16-24 ปี | TikTok 65 : FB 35 | ยืนยันตามคาด TikTok ทำ Blended ROAS สูงกว่า คงสัดส่วนไว้ |
| ลูกค้า B — เครื่องใช้ไฟฟ้าในบ้านราคาสูง | ราคา 8,000-25,000 บาท | 30-50 ปี | FB 80 : TikTok 20 | TikTok ทำ Awareness ได้ดีแต่ปิดยอดขายเองได้น้อย ต้องพึ่ง FB Retargeting ปิด ยืนยันสัดส่วนเดิม |
| ลูกค้า C — อาหารเสริมสุขภาพ | ราคา 690-1,290 บาท | 25-45 ปี | ใกล้เคียงกัน 55:45 | ผลออกมาใกล้เคียงคาดการณ์ แต่ต้องเพิ่มความเข้มงวดด้าน Compliance บน TikTok (หมวดสุขภาพ) ทำให้ต้นทุน Creative สูงกว่าที่ประเมินไว้ จึงปรับกลับมาที่ FB 60:40 |

บทเรียนสำคัญคือ Scorecard ให้จุดเริ่มต้นที่แม่นยำในกรณีลูกค้า A และ B แต่กรณีลูกค้า C แสดงให้เห็นว่าปัจจัยที่ Scorecard มาตรฐานอาจไม่ครอบคลุมทั้งหมด (เช่น ต้นทุน Compliance ของหมวดสินค้าเฉพาะ) จำเป็นต้องปรับ Scorecard ให้เข้ากับบริบทของแต่ละธุรกิจเสมอ ไม่ใช่ใช้สูตรสำเร็จตายตัว

## คำถามที่พบบ่อย (FAQ)

**Q: ถ้างบโฆษณารวมน้อยมาก (ต่ำกว่า 50,000 บาท/เดือน) ควรรันทั้งสองแพลตฟอร์มพร้อมกันหรือไม่?**

A: โดยทั่วไปไม่แนะนำ เพราะงบที่แบ่งเป็นสองส่วนจะเล็กเกินกว่าจะผ่าน Learning Phase ได้ดีทั้งคู่ ควรเลือกแพลตฟอร์มเดียวที่ Scorecard สูงกว่าก่อน ทำให้ได้ผลลัพธ์ที่ชัดเจนและมี Data พอสำหรับตัดสินใจ แล้วค่อยขยายไปแพลตฟอร์มที่สองเมื่องบเพิ่มขึ้นหรือแพลตฟอร์มแรกเริ่มอิ่มตัว (Diminishing Returns)

**Q: Blended ROAS กับ Attributed ROAS ต่างกันมาก ควรเชื่อตัวเลขไหนตอนคุยกับเจ้าของธุรกิจ/ลูกค้า?**

A: ใช้ Blended ROAS เป็นตัวเลขหลักเสมอในการรายงานภาพรวมและตัดสินใจเชิงธุรกิจ ส่วน Attributed ROAS ของแต่ละแพลตฟอร์มใช้อธิบายรายละเอียดว่าแคมเปญไหนภายในแพลตฟอร์มนั้นทำงานดี/แย่ อธิบายให้ลูกค้าเข้าใจความแตกต่างนี้ตั้งแต่ต้น จะช่วยลดความเข้าใจผิดตอนตัวเลขสองชุดไม่ตรงกัน

**Q: ทำ Incrementality Test แล้วพบว่า Incremental ROAS ต่ำกว่า Break-even ควรหยุดแพลตฟอร์มนั้นทันทีหรือไม่?**

A: ไม่ควรหยุดทันทีในทุกกรณี ให้พิจารณาว่าแพลตฟอร์มนั้นทำหน้าที่อะไรในระบบ ถ้าใช้เป็น Awareness/Top of Funnel ที่ป้อน Retargeting Pool ให้อีกแพลตฟอร์ม การวัด Incremental ROAS แบบเดี่ยวอาจไม่ยุติธรรม ควรดู Incremental Effect ต่อ Blended Revenue ทั้งระบบ (รวมผลที่ป้อนต่อไปยัง Retargeting) ก่อนตัดสินใจหยุดถาวร

**Q: ควรทำ Decision Scorecard ใหม่บ่อยแค่ไหน?**

A: แนะนำทุก 3-6 เดือน หรือทันทีที่มีการเปลี่ยนแปลงใหญ่ เช่น ขยายกลุ่มเป้าหมายใหม่ เปิดสินค้าใหม่ที่มีลักษณะต่างจากเดิมมาก หรือทีม Creative เปลี่ยนแปลงความสามารถอย่างมีนัยสำคัญ

**Q: ถ้าเจ้าของธุรกิจยืนกรานอยากได้สัดส่วนที่ไม่ตรงกับ Scorecard/ผลทดสอบ ควรทำอย่างไร?**

A: นำเสนอข้อมูล Scorecard และผลทดสอบให้เห็นภาพชัดก่อน แต่ถ้าเจ้าของธุรกิจยังต้องการยืนยันสัดส่วนของตัวเอง (มักมาจากเหตุผลเชิงกลยุทธ์ที่กว้างกว่าตัวเลข เช่น ต้องการสร้างแบรนด์บน TikTok ระยะยาว) ให้ทำตามแต่กำหนด KPI ที่ชัดเจนร่วมกันและติดตามผลอย่างใกล้ชิด พร้อมรายงานผล Blended Metrics อย่างตรงไปตรงมาเป็นระยะ

## กรอบการตัดสินใจแบบย่อ (Decision Snapshot)

เมื่อต้องตัดสินใจเรื่องสัดส่วนงบข้ามแพลตฟอร์ม ให้ไล่ถามตามลำดับนี้:

1. ทำ Decision Scorecard ล่าสุดหรือยัง (ไม่เกิน 6 เดือน)
2. มีข้อมูล Conversion ครบ 30-50 รายการต่อแพลตฟอร์มในรอบทดสอบล่าสุดหรือยัง
3. ตัวเลขที่กำลังจะใช้ตัดสินใจเป็น Blended Metrics ที่กระทบยอดกับ Revenue จริงแล้วหรือยัง หรือยังเป็นตัวเลขที่แต่ละแพลตฟอร์มรายงานเอง
4. มี Trigger ที่ตรงกับ Trigger Matrix จริงหรือเป็นแค่ความรู้สึก
5. ถ้าจะปรับ ปรับในขนาด 10-20% หรือกำลังจะ All-in
6. ช่วงเวลานี้ตรงกับปฏิทิน Seasonal Reallocation ที่วางไว้หรือไม่
7. เคยทำ Incrementality Test ยืนยันผลตอบแทนจริงของแพลตฟอร์มที่กำลังจะเพิ่มงบหรือยัง

## Checklist ท้ายบท

- [ ] ทำ Decision Scorecard เพื่อหาสัดส่วนงบเริ่มต้นก่อนเปิดทั้งสองแพลตฟอร์มพร้อมกัน
- [ ] กำหนด Starting Split ตามสถานะธุรกิจ ไม่ใช่ 50/50 แบบไม่มีเหตุผล
- [ ] เก็บ Baseline อย่างน้อย 2 สัปดาห์และรอให้ครบ 30-50 Conversion ก่อนตัดสินใจปรับสัดส่วน
- [ ] กำหนด Trigger เชิงตัวเลขและเชิงคุณภาพล่วงหน้า ไม่ปรับงบตามความรู้สึก
- [ ] ปรับสัดส่วนงบทีละ 10-20% ต่อรอบ ไม่ All-in ทันที
- [ ] คำนวณ Blended CAC/ROAS จากระบบหลังบ้านจริง ไม่ใช่รวมตัวเลขจาก Ads Manager ตรงๆ
- [ ] ตระหนักถึงปัญหา Attribution Overlap และใช้ Blended Metrics เป็นตัวชี้วัดหลักในการรายงานผล
- [ ] ทำ Incrementality Testing (Geo หรือ Time-Based Holdout) อย่างน้อยปีละ 1-2 ครั้ง
- [ ] วางปฏิทิน Seasonal Reallocation ล่วงหน้า 4-6 สัปดาห์ก่อนช่วงพีคทุกครั้ง
- [ ] จัดโครงสร้างทีม/KPI ให้ผูกกับ Blended Metrics ไม่ใช่ผลงานแยกแพลตฟอร์มที่มีผลประโยชน์ทับซ้อน
- [ ] บันทึก Decision Log ทุกครั้งที่ปรับสัดส่วนงบ พร้อมเหตุผลและผลลัพธ์ที่ตามมา
- [ ] ใช้ Naming Convention และ UTM มาตรฐานเดียวกันทั้งสองแพลตฟอร์มเพื่อให้ Dashboard กลางใช้งานได้จริง

## Workshop / แบบฝึกหัด

เลือกธุรกิจจริงที่คุณดูแล (หรือธุรกิจของคุณเอง) แล้วทำตามขั้นตอนต่อไปนี้ให้ครบ:

**ส่วนที่ 1 — Decision Scorecard**

สร้างตาราง Scorecard ตาม Step 911 ให้คะแนน Facebook และ TikTok ในทั้ง 8 เกณฑ์ตามความเป็นจริงของธุรกิจนั้น คำนวณคะแนนรวมและสัดส่วนงบเริ่มต้นที่ได้

**ส่วนที่ 2 — Test Plan 8 สัปดาห์**

เขียน Test Plan ตามตาราง Step 912 โดยระบุ: งบรวมต่อเดือน, Starting Split, จำนวน Conversion ขั้นต่ำที่ต้องรอ, และวันที่จะประเมินผลรอบแรก

**ส่วนที่ 3 — Blended Metrics Template**

สร้างตาราง (ใน Excel/Google Sheets) ที่มีคอลัมน์: งบ Facebook, งบ TikTok, Purchase ที่ Facebook รายงาน, Purchase ที่ TikTok รายงาน, Purchase จริงจากระบบหลังบ้าน, Blended CAC, Blended ROAS — กรอกด้วยตัวเลขสมมติหรือตัวเลขจริงถ้ามี แล้วคำนวณ % Overlap ที่พบ

**ส่วนที่ 4 — Trigger Matrix ของธุรกิจนี้**

เขียน Trigger Matrix เฉพาะของธุรกิจนี้ (ปรับจากตารางตัวอย่าง Step 913) พร้อมระบุตัวเลขเกณฑ์ที่เหมาะกับ Break-even ROAS ของธุรกิจนั้นจริง

**ส่วนที่ 5 — ปฏิทิน Seasonal Reallocation**

เลือกเทศกาล/ช่วงพีค 3 ช่วงที่สำคัญที่สุดสำหรับธุรกิจนี้ในรอบ 12 เดือนข้างหน้า และเขียนแผนสัดส่วนงบสำหรับแต่ละช่วง พร้อมวันที่ควรเริ่มปรับงบล่วงหน้า

**ส่วนที่ 6 — ออกแบบ Holdout Test อย่างง่าย**

เขียนแผน Time-Based Holdout Test 6 สัปดาห์สำหรับธุรกิจนี้ ระบุว่าสัปดาห์ไหนเปิด-ปิดแพลตฟอร์มไหน และวิธีคำนวณ Incremental ROAS ที่จะใช้

ทำครบทั้ง 6 ส่วนแล้วรวมเป็นเอกสาร "แผนแบ่งงบข้ามแพลตฟอร์ม" ฉบับสมบูรณ์ที่พร้อมนำไปใช้กับธุรกิจจริงหรือเสนอต่อลูกค้า

## สรุปและเชื่อมไปยัง Part ถัดไป

Part นี้ให้คุณกรอบคิดที่เป็นระบบสำหรับปัญหาที่นักยิงแอดข้ามแพลตฟอร์มทุกคนต้องเจอ — เริ่มจาก Decision Scorecard ที่ช่วยหาจุดเริ่มต้นที่มีเหตุผล ผ่านการทดสอบอย่างมีวินัย การคิด Blended Metrics ที่สะท้อนความจริงของธุรกิจ การจัดการปัญหา Attribution Overlap แบบใช้งานได้จริง การทำ Incrementality Testing เพื่อรู้ผลตอบแทนที่แท้จริง ไปจนถึงการวางแผนตามฤดูกาลและโครงสร้างทีมที่รองรับการทำงานข้ามแพลตฟอร์มอย่างมีประสิทธิภาพ

บทเรียนที่สำคัญที่สุดที่ควรพกติดตัวไปคือ **ตัวเลขที่แต่ละแพลตฟอร์มรายงานเองไม่ใช่ความจริงทั้งหมด — Blended Metrics ที่กระทบยอดกับระบบหลังบ้านจริงคือสิ่งที่ควรใช้ตัดสินใจเชิงธุรกิจ** ส่วนตัวเลขแยกแพลตฟอร์มมีประโยชน์แค่สำหรับการวิเคราะห์เชิงลึกภายในแต่ละแพลตฟอร์มเท่านั้น

Part ถัดไป (Part 093) จะปิดท้าย Section J ด้วยเรื่อง **Marketing Automation Tools และ AI Tools สำหรับนักยิงแอด** — เครื่องมือที่จะช่วยให้คุณทำงานทุกอย่างที่เรียนมาตลอดหลักสูตรได้เร็วขึ้น ตั้งแต่การเขียนคอปี้ การผลิตครีเอทีฟ การวิเคราะห์ข้อมูล ไปจนถึงระบบ Automation ที่เชื่อมต่อกับ Email/SMS/CRM ทั้งนี้ Part 093 ยังเป็น Part สุดท้ายของ Section J ทั้งหมด ก่อนที่หลักสูตรจะเปลี่ยนทิศทางจาก "การรันแอด" ไปสู่ "การรันธุรกิจเอเจนซี่" ใน Section K
