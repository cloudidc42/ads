## บทนำก่อนเริ่ม

Part นี้คือหัวใจของหลักสูตรฝั่ง Facebook Ads สำหรับธุรกิจ E-commerce เพราะ Sales Objective พร้อม Conversion Location คือรูปแบบแคมเปญที่ธุรกิจขายของออนไลน์ส่วนใหญ่ในโลกใช้เป็นหลักในการสร้างยอดขาย ต่างจาก Lead Generation (Part 024) หรือ Messages (Part 025) ที่เน้นการเก็บข้อมูลติดต่อหรือเริ่มบทสนทนา Sales Objective คือการบอก Meta ตรงๆ ว่า "ช่วยหาคนที่จะจ่ายเงินจริงให้เรา" ซึ่ง Optimize ตรงไปที่เป้าหมายทางธุรกิจที่สุด

สิ่งที่ทำให้แคมเปญประเภทนี้ซับซ้อนกว่า Objective อื่นคือมันพึ่งพาคุณภาพของ Pixel/Conversions API และปริมาณข้อมูล (Data Volume) มากกว่าที่อื่น ถ้าตั้งค่าผิด เช่น เลือก Optimize Event ที่มีข้อมูลน้อยเกินไป แคมเปญจะไม่นิ่ง ต้นทุนพุ่งสูง หรือไม่ Deliver เลย ในทางกลับกัน ถ้าตั้งค่าถูกต้อง แคมเปญประเภทนี้คือแคมเปญที่สเกลได้ไกลที่สุดและวัดผลได้ตรงที่สุดในทุก Objective ของ Facebook Ads

Part นี้จะพาไปเจาะลึกทุกขั้นตอน ตั้งแต่การเลือก Conversion Event ให้ถูกต้องตามปริมาณข้อมูลที่มี ไปจนถึงการอ่านเมตริกหลังแคมเปญวิ่งเพื่อตัดสินใจว่าควรปรับอะไรต่อ

## Step 251: Sales Objective กับ Conversion Location ภาพรวมและตัวเลือกทั้งหมด

### ทำไม Sales Objective ถึงเป็น Objective ที่สำคัญที่สุดสำหรับ E-commerce

ในโครงสร้าง ODAX ปัจจุบัน เมื่อกด **+ Create** ใน Ads Manager แล้วเลือก Objective = **Sales** ระบบจะถามต่อว่าต้องการ "Conversion location" แบบไหน ซึ่งเป็นจุดตัดสินใจสำคัญที่สุดของทั้งแคมเปญ เพราะมันกำหนดว่า Pixel/Dataset ไหนจะถูกใช้วัดผล และ AI จะไป Optimize เพื่อเป้าหมายอะไร

Sales Objective ต่างจาก Traffic Objective (Part 022) ตรงที่ Traffic เพียง Optimize ให้คนคลิกไปที่เว็บไซต์ ไม่สนใจว่าคลิกแล้วจะซื้อหรือไม่ ในขณะที่ Sales Objective มองข้ามการคลิกไปไกลกว่านั้น โดย Optimize ตรงไปที่ Event ที่เกิดขึ้น **หลังจาก** คนเข้าเว็บไซต์แล้ว เช่น การเพิ่มสินค้าลงตะกร้า หรือการจ่ายเงินสำเร็จ

### ตัวเลือก Conversion Location ทั้งหมด

เมื่อเลือก Objective = Sales หน้า Ad Set จะมีตัวเลือก Conversion location ดังนี้:

1. **Website** — Optimize การขายบนเว็บไซต์ที่ติดตั้ง Pixel/Conversions API แล้ว (ตัวเลือกที่ใช้มากที่สุด)
2. **App** — Optimize การซื้อภายในแอปมือถือที่เชื่อม SDK/App Events แล้ว
3. **Website and app** — ใช้ทั้งสองแหล่งพร้อมกัน เหมาะกับธุรกิจที่ขายทั้งบนเว็บและแอป
4. **Messaging apps** — Optimize การขายที่เกิดขึ้นผ่านการแชท (ผสมแนวคิดกับ Part 025 แต่ยังคง Optimize เพื่อ Event การซื้อ ไม่ใช่แค่การเริ่มแชท)
5. **Calls** — Optimize ให้คนโทรเข้ามาซื้อ/สอบถามที่นำไปสู่การขาย

Part นี้จะโฟกัสที่ Conversion location = **Website** เป็นหลัก เพราะเป็นรูปแบบที่ธุรกิจไทยส่วนใหญ่ใช้ และมีรายละเอียดมากที่สุดที่ต้องเข้าใจให้ครบ

### ข้อกำหนดพื้นฐานก่อนสร้างแคมเปญ Sales

ก่อนสร้างแคมเปญนี้ ต้องมี:

- Facebook Pixel ติดตั้งบนเว็บไซต์แล้ว (ทบทวน Part 013-014)
- Standard Events อย่างน้อย Purchase, AddToCart, InitiateCheckout ยิงทำงานถูกต้อง (ทบทวน Part 015)
- แนะนำอย่างยิ่งให้มี Conversions API เชื่อมต่อคู่กับ Pixel เพื่อความแม่นยำของข้อมูลหลัง iOS14+ (ทบทวน Part 013 Step 125-126)
- Catalog สินค้า (ถ้าต้องการทำ Dynamic Ads ในอนาคต — แต่ Part นี้ยังไม่จำเป็นต้องมี)

## Step 252: การเลือก Conversion Event ให้ถูกต้อง (Purchase vs AddToCart vs InitiateCheckout) ตามปริมาณข้อมูล

นี่คือจุดตัดสินใจที่สำคัญที่สุดของทั้ง Part และเป็นจุดที่นักยิงแอดมือใหม่ทำผิดพลาดบ่อยที่สุด

### หลักการพื้นฐาน: Event ที่ "ลึก" กว่าให้ Lead ที่ "ตรง" กว่า แต่ต้องมีข้อมูลมากพอ

Funnel การซื้อของออนไลน์มีลำดับ Event คร่าวๆ ดังนี้:

```
ViewContent (ดูสินค้า) → AddToCart (เพิ่มตะกร้า) → InitiateCheckout (กดชำระเงิน) → Purchase (จ่ายเงินสำเร็จ)
```

ยิ่ง Event อยู่ลึกในฟันเนล (ใกล้ Purchase) ยิ่งบอกความตั้งใจซื้อที่แท้จริงมากขึ้น แต่จำนวนคนที่ทำ Event นั้นก็จะน้อยลงตามลำดับ (เพราะมีคนดร็อปออกทุกขั้น) ปัญหาคือ **AI ของ Meta ต้องการข้อมูล (Data) จำนวนหนึ่งถึงจะเรียนรู้ได้แม่นยำ** ถ้าเลือก Optimize Event ที่มีจำนวนน้อยเกินไป ระบบจะไม่มีสัญญาณพอในการหาคนที่คล้ายกัน ทำให้ Performance ไม่นิ่ง

### กรอบการตัดสินใจเลือก Conversion Event

| สถานการณ์ธุรกิจ | Event ที่ควรเลือก Optimize |
|---|---|
| เว็บใหม่ ยังไม่มี Purchase Event เกิดขึ้นเลย หรือมีน้อยกว่า 10 ครั้ง/สัปดาห์ | เริ่มที่ **AddToCart** หรือ **InitiateCheckout** เพื่อสร้างสัญญาณให้ระบบเรียนรู้ก่อน |
| เว็บมี Purchase Event เกิดขึ้นแล้ว 10-25 ครั้ง/สัปดาห์ | ทดลอง Optimize เป็น **Purchase** ได้ แต่เตรียมใจว่า Learning Phase อาจใช้เวลานานกว่าปกติ |
| เว็บมี Purchase Event มากกว่า 50 ครั้ง/สัปดาห์อย่างสม่ำเสมอ | Optimize ที่ **Purchase** ได้เต็มที่ เป็นสถานการณ์ที่เหมาะสมที่สุด |
| ธุรกิจ B2B/High-ticket ที่มี Purchase Event น้อยมากตลอดไป (เช่น ขายละ 5-10 ครั้ง/เดือน) | พิจารณา Optimize ที่ **InitiateCheckout** หรือใช้ Lead Objective แทนไปเลย (ย้อนดู Part 024) |

### ตัวอย่างสถานการณ์จริง

ร้านค้าออนไลน์ขายเครื่องสำอางเปิดใหม่ ยังไม่มี Purchase Event เกิดขึ้นเลยในสัปดาห์แรก ถ้าตั้งแคมเปญ Optimize สำหรับ Purchase ทันที ระบบจะหาคนไปเรื่อยๆ แบบสุ่ม (Random) เพราะไม่มีสัญญาณให้เรียนรู้ ผลคือ CPA พุ่งสูงมากในสัปดาห์แรกๆ แนวทางที่แนะนำคือเริ่มจาก Optimize ที่ AddToCart ก่อน 1-2 สัปดาห์ เพื่อให้ระบบสร้างสัญญาณพื้นฐาน (คนที่มีพฤติกรรมสนใจซื้อของออนไลน์ในหมวดนี้) จากนั้นเมื่อมี Purchase Event สะสมมากพอ (ผ่านการซื้อจริงจากแคมเปญ AddToCart) ค่อยสร้าง Ad Set ใหม่ที่ Optimize เป็น Purchase โดยตรง

### ทำไมไม่ควร Optimize ที่ ViewContent

Event ViewContent (การดูหน้าสินค้า) มีจำนวนสูงมากและเรียนรู้ได้เร็ว แต่ **ไม่ควรใช้เป็น Conversion Event สำหรับ Sales Campaign** เพราะมันบอกความตั้งใจซื้อต่ำเกินไป (คนดูหน้าสินค้าเฉยๆ ไม่ได้แปลว่าจะซื้อ) การ Optimize ที่ ViewContent ในบริบทของ Sales Objective มักทำให้ได้ Traffic คุณภาพต่ำที่ดูสินค้าแล้วไม่ซื้อจำนวนมาก ควรใช้ ViewContent เป็นแค่ Event สำหรับสร้าง Custom Audience Retargeting เท่านั้น (ดู Part 049)

## Step 253: กฎ Minimum Event Volume (~50 events/สัปดาห์) และผลกระทบต่อ Learning Phase

### Learning Phase คืออะไร (ทบทวนสั้นๆ จาก Part 009)

Learning Phase คือช่วงที่ Ad Set กำลังทดลองส่งโฆษณาไปยังกลุ่มคนต่างๆ เพื่อเก็บข้อมูลว่าใครมีโอกาสทำ Conversion Event ที่กำหนดมากที่สุด ในช่วงนี้ต้นทุนมักจะไม่แน่นอน (บางวันถูก บางวันแพง) เพราะระบบยังไม่มั่นใจว่าโฆษณาควรไปหาใคร

### กฎ ~50 Events ต่อสัปดาห์

Meta แนะนำอย่างเป็นทางการว่า Ad Set ควรได้รับ Conversion Event ที่ Optimize ไว้ **อย่างน้อยประมาณ 50 ครั้งต่อสัปดาห์** เพื่อให้ Ad Set มีโอกาสออกจาก Learning Phase ได้อย่างมีเสถียรภาพ (สถานะจะเปลี่ยนจาก "Learning" เป็น "Active" ใน Column Delivery ของ Ads Manager)

ถ้า Ad Set ได้ Event ต่ำกว่า 50 ครั้ง/สัปดาห์อย่างต่อเนื่อง สถานะจะค้างอยู่ที่ **"Learning Limited"** ซึ่งหมายความว่าระบบไม่มีข้อมูลพอที่จะออกจาก Learning Phase ได้ ต้นทุนจะสูงกว่าที่ควรและผลลัพธ์จะไม่สม่ำเสมอไปตลอดจนกว่าจะปรับอะไรบางอย่าง

### วิธีคำนวณงบที่ต้องใช้

สูตรคร่าวๆ: **งบต่อสัปดาห์ที่ต้องการ = CPA เป้าหมาย (หรือ CPA จริงที่เคยได้) x 50**

ตัวอย่าง: ถ้า CPA (ต้นทุนต่อการขาย 1 ครั้ง) เฉลี่ยของธุรกิจอยู่ที่ 200 บาท ต้องมีงบอย่างน้อยประมาณ 10,000 บาท/สัปดาห์ (~1,430 บาท/วัน) ต่อ Ad Set ที่ Optimize เป็น Purchase ถึงจะมีโอกาสได้ 50 Purchase/สัปดาห์และออกจาก Learning Phase ได้อย่างเสถียร

ถ้างบจริงของธุรกิจน้อยกว่านี้มาก มี 3 ทางเลือก:

1. **ลด Ad Set ให้เหลือน้อยลง** และรวมงบเข้า Ad Set เดียวเพื่อให้สัญญาณ Conversion กระจุกตัวมากพอ
2. **เปลี่ยนไป Optimize Event ที่ตื้นกว่า** เช่น AddToCart ซึ่งมีจำนวนมากกว่า ทำให้เข้าเกณฑ์ 50 ครั้ง/สัปดาห์ได้ง่ายกว่าด้วยงบเท่ากัน
3. **ยอมรับว่า Ad Set จะอยู่ใน Learning Limited ต่อไป** และติดตามผลอย่างระมัดระวังมากขึ้น พร้อมปรับกลยุทธ์เมื่อมีงบเพิ่ม

### ผลกระทบของการแก้ไขแคมเปญกลาง Learning Phase

การแก้ไข Ad Set หรือ Ad อย่างมีนัยสำคัญ (เปลี่ยน Audience อย่างมาก, เปลี่ยน Budget เกิน 20% ในครั้งเดียว, เปลี่ยน Optimization Event, ปิดแล้วเปิดใหม่) จะทำให้ Ad Set **รีเซ็ต Learning Phase ใหม่ทั้งหมด** ซึ่งเป็นเหตุผลที่นักยิงแอดมืออาชีพจะไม่แก้ไขแคมเปญที่กำลังอยู่ใน Learning Phase บ่อยเกินไป ควรตั้งค่าให้ถูกต้องตั้งแต่ต้นและรอให้ผ่าน Learning Phase ก่อน (ปกติใช้เวลาประมาณ 3-7 วัน หรือจนกว่าจะสะสม Event ครบ 50 ครั้ง) ก่อนพิจารณาปรับแก้ (รายละเอียดเพิ่มเติมเรื่องการปรับ Budget โดยไม่รีเซ็ต Learning Phase อยู่ใน Part 018 Step 178)

## Step 254: Conversion Location ทุกตัวเลือก — Website, App, Website+App, Messaging Apps

### Website (ตัวเลือกหลักสำหรับธุรกิจส่วนใหญ่)

เมื่อเลือก Website ระบบจะให้เลือก **Pixel** ที่จะใช้วัดผล (Dropdown แสดงรายชื่อ Pixel ทั้งหมดใน Business Manager) จากนั้นเลือก **Conversion Event** ที่จะ Optimize (Purchase, AddToCart, InitiateCheckout, Lead, CompleteRegistration ฯลฯ ตาม Standard Events ที่มีข้อมูลอยู่)

ข้อดี: ตั้งค่าง่ายที่สุด เหมาะกับธุรกิจที่มีเว็บไซต์/ระบบ Checkout สมบูรณ์แล้ว

### App (สำหรับธุรกิจที่มีแอปมือถือ)

เลือก Conversion location = App ต้องมีการเชื่อม **App Events** ผ่าน Facebook SDK หรือ Mobile Measurement Partner (MMP) เช่น AppsFlyer, Adjust ไว้ก่อนแล้ว ระบบจะให้เลือก App ที่ลงทะเบียนไว้ใน Meta App Dashboard และเลือก Event เช่น Purchase (in-app), Add to Cart (in-app) รายละเอียดเชิงลึกของ App Promotion Objective จะอยู่ใน Part 028

### Website and App

ใช้เมื่อธุรกิจมีทั้งเว็บไซต์และแอป และต้องการให้ Meta มองทั้งสองแหล่งเป็นภาพเดียวกันในการ Optimize เช่น ร้านค้าที่ลูกค้าอาจซื้อผ่านเว็บหรือแอปก็ได้ ระบบจะรวม Event จากทั้งสองแหล่งมานับเป็น Conversion เดียวกัน ซึ่งช่วยให้ถึงเกณฑ์ 50 Events/สัปดาห์ได้ง่ายขึ้นถ้าแต่ละแหล่งมีข้อมูลไม่มากพอแยกกัน

### Messaging Apps (Sales ผ่านแชท)

ตัวเลือกนี้ต่างจาก Messages Objective ใน Part 025 ตรงที่ Optimize เพื่อ **การซื้อที่เกิดขึ้นจริงผ่านแชท** ไม่ใช่แค่การเริ่มบทสนทนา เหมาะกับธุรกิจที่ปิดการขายทั้งหมดผ่าน Messenger/WhatsApp (เช่น ธุรกิจที่ไม่มีเว็บไซต์ Checkout แต่ใช้แชทรับออเดอร์และโอนเงินทั้งหมด) ต้องมีการติดตั้ง Conversions API for Messaging เพื่อส่งสัญญาณ "การซื้อสำเร็จ" กลับเข้า Meta ซึ่งมักต้องพึ่ง Chatbot Platform หรือ Developer ช่วยตั้งค่า

### ตารางสรุปการเลือก Conversion Location

| ธุรกิจแบบไหน | Conversion Location ที่เหมาะ |

## Step 255: Value-Based Optimization และ Highest Value Optimization Goal

### Value-Based Optimization คืออะไร

โดยปกติเมื่อ Optimize ที่ Purchase Event ระบบจะพยายามหา "จำนวน Purchase มากที่สุด" โดยไม่สนใจว่า Purchase แต่ละครั้งมีมูลค่าเท่าไหร่ ปัญหาคือธุรกิจจำนวนมากมีสินค้าหลายราคา บางคนซื้อของ 200 บาท บางคนซื้อของ 5,000 บาท การ Optimize แบบนับจำนวนเฉยๆ อาจทำให้ระบบไปหาคนที่ซื้อของถูกจำนวนมาก แทนที่จะหาคนที่มีโอกาสซื้อของแพง (มูลค่าสูง) ซึ่งอาจไม่ตรงกับเป้าหมายทางธุรกิจที่ต้องการ Revenue สูงสุด

**Value Optimization** แก้ปัญหานี้โดยให้ระบบ Optimize เพื่อ **มูลค่ารวม (Total Purchase Value)** สูงสุด ไม่ใช่แค่จำนวนครั้ง โดยดึงค่า `value` ที่ส่งมาพร้อม Purchase Event (ทบทวน Part 015 Step 146 เรื่อง Dynamic Value)

### Performance Goal ที่เกี่ยวกับ Value

ในหน้า Ad Set เมื่อเลือก Conversion Event = Purchase ระบบจะมี Performance goal ให้เลือกเพิ่มเติม:

- **Maximize number of conversions** — Optimize เพื่อจำนวน Purchase มากที่สุด (ไม่สนมูลค่า)
- **Highest value** (Value Optimization) — Optimize เพื่อมูลค่ารวมสูงสุด เหมาะกับธุรกิจที่มีสินค้าหลายราคาต่างกันมาก
- **ROAS goal** (Minimum ROAS Control) — ตั้งเป้า ROAS ขั้นต่ำที่ต้องการ ระบบจะพยายามไม่ Spend เกินกว่าที่จะทำ ROAS ต่ำกว่าเป้าที่ตั้งไว้ (ตัวเลือกนี้ต้องใช้อย่างระมัดระวัง เพราะถ้าตั้งเป้าสูงเกินไป Ad Set อาจ Spend ได้น้อยมากหรือไม่ Spend เลย)

### เมื่อไหร่ควรใช้ Value Optimization

ควรใช้เมื่อ:

1. ธุรกิจมีสินค้าราคาต่างกันมาก (เช่น สินค้าถูกสุด 100 บาท แพงสุด 10,000 บาท)
2. มี Purchase Event สะสมมากพอ (แนะนำมากกว่า 50-100 Purchase/สัปดาห์ในระดับ Ad Account เพื่อให้ Value Optimization มีข้อมูลมากพอเรียนรู้)
3. เป้าหมายทางธุรกิจคือ Revenue/Profit สูงสุด ไม่ใช่แค่จำนวนออเดอร์

ถ้าสินค้าราคาใกล้เคียงกันหมด (เช่น ร้านขายเสื้อราคาเดียว 590 บาททุกตัว) การใช้ Value Optimization จะไม่ต่างจาก Maximize number of conversions มากนัก ในกรณีนี้แนะนำใช้ Maximize conversions ธรรมดาซึ่งเรียนรู้ได้เร็วกว่าเพราะไม่ต้องพึ่งความแม่นยำของค่า Value

### 1. Conversion location และ Pixel

- **Conversion location:** เลือก Website
- **Pixel:** เลือก Pixel ที่ผูกกับเว็บไซต์จาก Dropdown

- **Schedule:** Run ad set continuously ถ้ายังไม่มีกำหนดสิ้นสุดชัดเจน

## Step 259: งบประมาณที่เหมาะสมและการอ่านเมตริก (ROAS, CPA, Purchase Value)

### งบประมาณเริ่มต้นที่แนะนำตามประเภทสินค้า

| ประเภทสินค้า | CPA เฉลี่ยเบื้องต้น (บาท) | งบต่อวันขั้นต่ำแนะนำ (Optimize Purchase) |
|---|---|---|
| สินค้าราคาถูก (ต่ำกว่า 500 บาท) | 80–150 | 570–1,070 |
| สินค้าราคากลาง (500-2,000 บาท) | 150–350 | 1,070–2,500 |
| สินค้าราคาสูง (2,000-10,000 บาท) | 400–1,200 | 2,850–8,570 |
| สินค้า High-ticket (มากกว่า 10,000 บาท) | 1,500+ | 10,700+ |

ตัวเลขคำนวณจาก (CPA x 50) / 7 ตามสูตรใน Step 253 เป็นค่าประมาณเบื้องต้น ตัวเลขจริงต้องปรับตาม Category สินค้าและการแข่งขันในตลาดขณะนั้น

### วิธีอ่านเมตริกหลักของ Sales Campaign

**1. ROAS (Return on Ad Spend)** = Purchase Value ÷ Amount Spent

ดูได้จาก Column "Purchase ROAS (Return on ad spend)" ใน Ads Manager นี่คือเมตริกสำคัญที่สุดสำหรับ Sales Campaign เพราะบอกตรงๆ ว่าลงทุนโฆษณา 1 บาท ได้ยอดขายกลับมากี่บาท ต้องเทียบกับ **Break-even ROAS** ของธุรกิจ (คำนวณจาก Margin สินค้า — ทบทวน Part 004 Step 34) เช่น ถ้า Margin สินค้าอยู่ที่ 40% Break-even ROAS จะอยู่ที่ประมาณ 2.5 (ลงทุน 1 บาท ต้องได้ยอดขายคืนอย่างน้อย 2.5 บาทถึงจะไม่ขาดทุนหลังหักต้นทุนสินค้า)

**2. CPA (Cost per Purchase/Action)** = Amount Spent ÷ Number of Purchases

ดูได้จาก Column "Cost per Purchase" ใช้เทียบกับ Margin ต่อหน่วยสินค้าเพื่อดูว่ากำไรสุทธิเป็นบวกหรือลบ

**3. Purchase Value** = มูลค่ารวมของ Purchase ทั้งหมดที่เกิดจากแคมเปญ

ใช้ดูภาพรวมว่าแคมเปญสร้าง Revenue ได้เท่าไหร่ในช่วงเวลาที่กำหนด ควรเทียบกับ Amount Spent เพื่อคำนวณ ROAS ด้วยตัวเองเป็นการ Double-check ตัวเลขที่ Ads Manager แสดง

**4. Frequency และ CTR** — ใช้ประกอบการวิเคราะห์ว่าทำไม ROAS ตก เช่น ถ้า Frequency สูงเกินไป (มากกว่า 3-4 ใน 7 วัน) อาจเกิด Ad Fatigue ทำให้ ROAS ลดลง (รายละเอียดเต็มอยู่ใน Part 060)

### เทมเพลตคำนวณ Break-even ROAS และงบต่อวัน (ใช้กรอกเองได้จริง)

ผู้เรียนสามารถคัดลอกเทมเพลตนี้ไปกรอกตัวเลขของธุรกิจตัวเองได้ทันที:

```
1. ราคาขายสินค้าเฉลี่ยต่อออเดอร์ (Average Order Value) = ______ บาท
2. ต้นทุนสินค้า + ค่าส่ง + ค่าดำเนินการต่อออเดอร์ = ______ บาท
3. Margin ต่อออเดอร์ (บรรทัด 1 - บรรทัด 2) = ______ บาท
4. Margin เป็นเปอร์เซ็นต์ (บรรทัด 3 ÷ บรรทัด 1 x 100) = ______ %
5. Break-even ROAS (บรรทัด 1 ÷ บรรทัด 3) = ______
6. ROAS เป้าหมายที่ต้องการกำไรจริง (แนะนำ Break-even ROAS x 1.3-1.5) = ______
7. CPA เป้าหมาย (บรรทัด 1 ÷ ROAS เป้าหมายในบรรทัด 6) = ______ บาท
8. งบต่อสัปดาห์ขั้นต่ำสำหรับ Learning Phase (บรรทัด 7 x 50) = ______ บาท
9. งบต่อวันขั้นต่ำ (บรรทัด 8 ÷ 7) = ______ บาท
```

ตัวอย่างการกรอกจริงสำหรับสินค้าราคาขาย 1,200 บาท ต้นทุนรวม 750 บาท:

```
1. ราคาขายสินค้าเฉลี่ยต่อออเดอร์ = 1,200 บาท
2. ต้นทุนสินค้า + ค่าส่ง + ค่าดำเนินการต่อออเดอร์ = 750 บาท
3. Margin ต่อออเดอร์ = 450 บาท
4. Margin เป็นเปอร์เซ็นต์ = 37.5%
5. Break-even ROAS = 2.67
6. ROAS เป้าหมายที่ต้องการกำไรจริง (x1.4) = 3.73
7. CPA เป้าหมาย = 1,200 ÷ 3.73 = 322 บาท
8. งบต่อสัปดาห์ขั้นต่ำ = 322 x 50 = 16,100 บาท
9. งบต่อวันขั้นต่ำ = 2,300 บาท
```

การกรอกเทมเพลตนี้ก่อนเปิดงบจริงทุกครั้ง ช่วยให้นักยิงแอดรู้ล่วงหน้าว่าต้องใช้งบเท่าไหร่ถึงจะมีโอกาสสมเหตุสมผลที่จะทำกำไรได้ ไม่ใช่การตั้งงบแบบเดาสุ่มแล้วมาดูผลลัพธ์ทีหลัง

### ตัวอย่างการคำนวณ Break-even ROAS

สินค้าราคาขาย 1,000 บาท ต้นทุนสินค้า+ค่าส่ง+ค่าดำเนินการรวม 600 บาท เหลือ Margin 400 บาท (40%)

Break-even ROAS = ราคาขาย ÷ Margin = 1,000 ÷ 400 = **2.5**

หมายความว่าถ้า ROAS ของแคมเปญต่ำกว่า 2.5 ธุรกิจกำลังขาดทุนจากค่าโฆษณา แม้ตัวเลข ROAS จะดูเป็นบวก (เช่น ROAS 1.8) ก็ตาม นักยิงแอดมือใหม่จำนวนมากเข้าใจผิดคิดว่า ROAS มากกว่า 1 คือกำไรแล้ว ซึ่งไม่ถูกต้อง

## Step 260: ข้อผิดพลาดที่พบบ่อย + Workshop สร้างแคมเปญ Purchase Conversion เต็มระบบ

### ข้อผิดพลาดที่พบบ่อยที่สุด 8 ข้อ

**1. Optimize ที่ Purchase ทั้งที่ยังไม่มีข้อมูล Purchase สะสมเลย**
ทำให้ Ad Set ติด Learning Limited ตลอดเวลา ต้นทุนสูงผิดปกติ ควรเริ่มจาก Event ที่ตื้นกว่าตามที่อธิบายใน Step 252 ก่อน

**2. ไม่รู้ Break-even ROAS ของธุรกิจตัวเอง**
ทำให้ตัดสินใจ Scale หรือหยุดแคมเปญผิดพลาด เห็น ROAS เป็นบวกก็คิดว่ากำไรแล้วทั้งที่ยังขาดทุนจริง ต้องคำนวณ Break-even ROAS ให้แม่นยำก่อนตัดสินใจใดๆ

**3. แก้ไขแคมเปญบ่อยเกินไปในช่วง Learning Phase**
ทำให้ Learning Phase รีเซ็ตซ้ำไปซ้ำมา แคมเปญไม่มีวันนิ่ง ควรรอให้ผ่าน Learning Phase (3-7 วัน หรือสะสม Event ครบ 50 ครั้ง) ก่อนปรับแก้ครั้งต่อไป

**4. ใช้ Value Optimization กับสินค้าราคาเดียวกันหมด**
ไม่ได้ประโยชน์เพิ่มจาก Value Optimization และอาจทำให้ Learning ช้าลงเพราะต้องพึ่งความแม่นยำของ Value ที่ไม่มีความหลากหลายให้เรียนรู้ ควรใช้ Maximize conversions ธรรมดาแทนในกรณีนี้

**5. ลิงก์ปลายทาง (Destination) ไม่ตรงกับ Pixel ที่เลือกใน Ad Set**
ทำให้ Event ไม่ถูกนับ หรือนับผิด Pixel ต้องตรวจสอบให้ตรงกันทุกครั้งก่อน Publish

**6. งบต่อวันต่ำเกินไปจนไม่พ้น Learning Phase**
เหมือนที่อธิบายในหลาย Part ก่อนหน้า ต้องคำนวณงบจากสูตร CPA x 50 ÷ 7 เป็นอย่างน้อย

**7. ไม่ได้ติดตั้ง Conversions API ควบคู่กับ Pixel**
ทำให้ข้อมูล Event ขาดหายไปบางส่วนหลัง iOS14+ ลด Event Match Quality และความแม่นยำของการ Optimize ควรติดตั้งคู่กันเสมอ (ทบทวน Part 013)

**8. ตัดสินใจหยุด/ปรับแคมเปญเร็วเกินไปจากข้อมูลไม่กี่วัน**
Sales Campaign ต้องการเวลาสะสมข้อมูลมากกว่า Objective อื่น การดูผลแค่ 1-2 วันแล้วสรุปว่าแคมเปญ "ไม่ดี" อาจผิดพลาด ควรให้เวลาอย่างน้อย 3-7 วันเต็มก่อนตัดสินใจใหญ่ (ยกเว้นกรณีขาดทุนรุนแรงชัดเจนที่ต้องหยุดทันทีเพื่อป้องกันความเสียหาย)

## แนวทางวินิจฉัยปัญหา Sales Campaign แบบเป็นระบบ (Troubleshooting Flow)

เมื่อแคมเปญ Sales ให้ผลลัพธ์ไม่ดีตามคาด ให้ไล่ตรวจตามลำดับนี้ทีละขั้น แทนการเดาสุ่มว่าจะแก้อะไรก่อน:

**ขั้นที่ 1 — ตรวจสอบ Delivery Status ก่อนเสมอ**
- ถ้าสถานะเป็น "Learning" ให้รอต่อ ยังสรุปผลไม่ได้
- ถ้าสถานะเป็น "Learning Limited" ให้ไปที่ขั้นที่ 2 เพื่อแก้ปัญหาปริมาณ Event
- ถ้าสถานะเป็น "Active" แล้วผลลัพธ์ยังไม่ดี ให้ไปที่ขั้นที่ 3

**ขั้นที่ 2 — แก้ปัญหา Learning Limited**
- เพิ่มงบให้ถึงเกณฑ์ตามสูตร CPA x 50 ÷ 7
- หรือเปลี่ยนไป Optimize Event ที่ตื้นกว่าชั่วคราว
- หรือรวม Ad Set หลายตัวเข้าเป็นตัวเดียวเพื่อรวมสัญญาณ

**ขั้นที่ 3 — ตรวจสอบฟันเนลว่าปัญหาอยู่จุดไหน**
- CTR ต่ำ → ปัญหาที่ Creative/Copy ไม่ดึงดูด (กลับไปดู Part 036-038)
- CTR ดี แต่ Cost per Add to Cart สูง → ปัญหาที่ Landing Page โหลดช้าหรือไม่ตรงกับโฆษณา (กลับไปดู Part 054)
- Cost per Add to Cart ดี แต่ Cost per Purchase สูงมาก → ปัญหาที่ขั้นตอน Checkout (ค่าส่งโผล่ทีหลัง, ระบบชำระเงินยุ่งยาก, ต้องสมัครสมาชิกก่อนซื้อ)
- ทุกอย่างดูดีแต่ ROAS ยังต่ำกว่า Break-even → ปัญหาอยู่ที่ Margin สินค้าหรือราคาขายเอง ไม่ใช่ปัญหาการยิงแอด

**ขั้นที่ 4 — ตรวจสอบความผันผวนตามช่วงเวลา**
- เทียบผลลัพธ์วันธรรมดากับวันหยุด/ช่วงเงินเดือนออก
- เทียบกับ Seasonality ของสินค้า (เช่น สินค้าฤดูร้อนขายไม่ดีในฤดูฝน)
- ตรวจสอบว่าคู่แข่งมีโปรโมชันใหญ่ในช่วงเวลาเดียวกันหรือไม่ ซึ่งอาจทำให้ Auction แข่งขันสูงขึ้นชั่วคราว

การไล่ตรวจตามลำดับขั้นแบบนี้ช่วยป้องกันการแก้ปัญหาผิดจุด เช่น การเพิ่มงบหรือเปลี่ยน Audience ทั้งที่ปัญหาจริงอยู่ที่หน้า Checkout ของเว็บไซต์ ซึ่งไม่มีการปรับแคมเปญใดๆ จะช่วยแก้ได้เลย

## Case Study: ร้านขายกระเป๋าแฟชั่นออนไลน์ ปรับ Conversion Event แล้วเห็นความแตกต่างชัดเจน

**สถานการณ์เริ่มต้น:** ร้านขายกระเป๋าแฟชั่นออนไลน์เพิ่งเปิดตัว ยิงแคมเปญ Sales Objective Optimize ที่ Purchase ทันทีตั้งแต่วันแรก โดยไม่มีข้อมูล Pixel สะสมเลย ผลคือหลังรัน 5 วัน ได้ Purchase เพียง 6 ครั้ง จากงบที่ใช้ไป 8,000 บาท คิดเป็น CPA เฉลี่ย 1,333 บาท สูงกว่าราคาขายกระเป๋าเฉลี่ย (890 บาท) เสียอีก ขาดทุนหนักตั้งแต่ต้น

**การปรับกลยุทธ์:**
1. หยุดแคมเปญเดิม สร้างแคมเปญใหม่ Optimize ที่ AddToCart แทน
2. ปรับ Landing Page ให้ปุ่ม "เพิ่มลงตะกร้า" เด่นชัดขึ้นและลดขั้นตอนก่อนถึงปุ่มนี้
3. รันแคมเปญ AddToCart เป็นเวลา 10 วัน สะสมข้อมูล AddToCart ได้ประมาณ 140 ครั้ง และมี Purchase เกิดขึ้นตามมาโดยธรรมชาติ 22 ครั้ง (CPA ตอนนี้ลดลงมาที่ประมาณ 480 บาทต่อ Purchase)
4. เมื่อมีข้อมูล Purchase สะสมมากพอ (มากกว่า 20 ครั้งในบัญชี) จึงสร้าง Ad Set ใหม่ Optimize ที่ Purchase โดยตรง โดยใช้ Audience และ Creative ที่พิสูจน์แล้วว่าได้ผลจากรอบ AddToCart

**ผลลัพธ์:** Ad Set ใหม่ที่ Optimize เป็น Purchase ผ่าน Learning Phase ได้ภายใน 4 วัน (เร็วกว่ารอบแรกมาก เพราะมีสัญญาณพื้นฐานจาก AddToCart ช่วยไว้แล้ว) CPA คงที่อยู่ที่ประมาณ 310 บาทต่อ Purchase ROAS อยู่ที่ 3.1 สูงกว่า Break-even ROAS ของร้าน (2.3) อย่างชัดเจน บทเรียนสำคัญคือการ "ไล่ระดับ Event" จากตื้นไปลึกตามปริมาณข้อมูลที่มีจริง ให้ผลลัพธ์ที่ดีกว่าการรีบ Optimize ที่ Purchase ตั้งแต่วันแรกโดยไม่มีข้อมูลรองรับ

## ภาคผนวก: ตารางเทียบ Performance Goal ทั้งหมดของ Sales Objective

| Performance Goal | ใช้เมื่อ | ความเสี่ยง |
|---|---|---|
| Maximize number of conversions | ธุรกิจใหม่ สินค้าราคาใกล้เคียงกัน ต้องการจำนวนออเดอร์มากที่สุด | อาจได้ออเดอร์มูลค่าต่ำจำนวนมากถ้าสินค้าหลากราคา |
| Highest value | สินค้าหลายราคาต่างกันมาก ต้องการ Revenue สูงสุด | ต้องมีข้อมูล Purchase สะสมมากพอ ไม่เหมาะกับบัญชีใหม่ |
| ROAS goal (Minimum ROAS control) | ธุรกิจที่รู้ Break-even ROAS แน่ชัดแล้วและต้องการควบคุมไม่ให้ต่ำกว่าเกณฑ์ | ถ้าตั้งเป้าสูงเกินจริง Ad Set อาจ Spend ได้น้อยมากหรือไม่ Spend เลย |
| Maximize number of conversions (AddToCart/InitiateCheckout) | บัญชีใหม่ ยังไม่มีข้อมูล Purchase สะสม | Lead ที่ได้อาจไม่ใช่ทุกคนที่ซื้อจริง ต้องไล่ระดับต่อไปที่ Purchase ทีหลัง |

### เช็คลิสต์เสริมก่อนสลับ Conversion Event จาก AddToCart ไป Purchase

- [ ] มี Purchase Event สะสมในบัญชีอย่างน้อย 20-30 ครั้งจากแคมเปญ AddToCart ที่ผ่านมา
- [ ] Landing Page และ Checkout Flow ไม่มีการเปลี่ยนแปลงใหญ่ในช่วงที่ผ่านมา (เพื่อให้ข้อมูลเก่ายังใช้อ้างอิงได้)
- [ ] Audience ที่ใช้ในแคมเปญ AddToCart ให้ผล CPA ที่ยอมรับได้ ไม่ใช่ Audience ที่มีปัญหา
- [ ] เตรียมงบสำหรับ Learning Phase รอบใหม่ (แคมเปญ Purchase จะต้องผ่าน Learning Phase ของตัวเองอีกครั้ง แม้จะใช้ Audience เดิม)
- [ ] ตั้ง Ad Set ใหม่แยกจาก Ad Set เดิม ไม่ควรแก้ Optimization Event ของ Ad Set เดิมที่มีข้อมูลสะสมอยู่แล้ว เพราะจะรีเซ็ต Learning Phase ทันที

## คำถามที่พบบ่อย (FAQ)

**Q: ถ้าสินค้ามีทั้งราคาถูกและราคาแพงปนกัน ควรแยกแคมเปญตามช่วงราคาหรือไม่?**
A: ควรพิจารณาแยก โดยเฉพาะถ้าช่วงราคาต่างกันมาก (เช่น สินค้า 200 บาท กับสินค้า 8,000 บาท) เพราะกลุ่มลูกค้าที่ซื้อของถูกกับของแพงมักมีพฤติกรรมต่างกัน การแยก Ad Set หรือ Campaign ตามช่วงราคาช่วยให้ AI เรียนรู้ได้เฉพาะเจาะจงมากขึ้น และช่วยให้วิเคราะห์ ROAS แยกตามกลุ่มสินค้าได้ชัดเจนกว่าการปนกันในแคมเปญเดียว

**Q: ทำไมแคมเปญที่ Optimize เป็น Purchase แล้ว บางวัน CPA ถูกมาก บางวันแพงมาก ทั้งที่ไม่ได้แก้ไขอะไร?**
A: เป็นเรื่องปกติของระบบ Auction ที่มีการแข่งขันเปลี่ยนแปลงตลอดเวลา (ช่วงเงินเดือนออก, ช่วงเทศกาล, คู่แข่งเพิ่มงบ) ควรดูผลลัพธ์เป็นค่าเฉลี่ยรวม 7 วันขึ้นไปแทนการดูรายวัน และถ้าความผันผวนมากเกินไปอย่างต่อเนื่อง อาจเป็นสัญญาณว่า Ad Set ยังอยู่ใน Learning Limited เพราะ Event ไม่ถึงเกณฑ์ 50 ครั้ง/สัปดาห์

**Q: Advantage+ Shopping Campaign (ASC) ต่างจาก Sales Campaign แบบที่เรียนใน Part นี้อย่างไร?**
A: ASC เป็นรูปแบบแคมเปญที่ Meta ให้ AI ควบคุมเกือบทุกอย่างอัตโนมัติ (Audience, Placement, Creative Variation) โดยมนุษย์ควบคุมได้น้อยกว่า Sales Campaign แบบ Manual ที่เรียนใน Part นี้ ซึ่งเราควบคุม Audience, Budget, Event ได้อย่างละเอียด ทั้งสองแบบมีที่ใช้ต่างกัน — Manual Sales Campaign เหมาะกับการทดสอบและควบคุมอย่างละเอียดในช่วงต้น ส่วน ASC เหมาะกับการ Scale เมื่อมีข้อมูล Pixel สะสมมากแล้ว รายละเอียดเต็มอยู่ใน Part 029

**Q: ควรตั้ง Ad Set กี่ตัวต่อ Campaign สำหรับ Sales Campaign?**
A: ในช่วงทดสอบเริ่มต้น แนะนำ 1-3 Ad Set ต่อ Campaign เพื่อไม่ให้งบกระจายจนแต่ละ Ad Set ได้ Event ไม่ถึงเกณฑ์ 50 ครั้ง/สัปดาห์ เมื่อมีข้อมูลมากพอและเปิด Advantage campaign budget แล้ว สามารถเพิ่ม Ad Set ได้มากขึ้นเพราะระบบจะจัดสรรงบให้ Ad Set ที่ดีที่สุดโดยอัตโนมัติ ทบทวนหลักการจำนวน Ad Set ที่เหมาะสมได้ใน Part 016 Step 156

**Q: ถ้าธุรกิจขายทั้งสินค้าและบริการที่ Sales Cycle ต่างกันมาก ควรแยก Objective ไปเลยหรือไม่?**
A: ควรแยก โดยใช้ Sales Objective สำหรับสินค้าที่ซื้อได้ทันทีผ่านเว็บไซต์ (Impulse/Low-consideration Purchase) และใช้ Leads หรือ Messages Objective สำหรับบริการที่ต้องพูดคุย/ประเมินราคาก่อน (High-consideration) การพยายามใช้ Objective เดียวครอบทุกอย่างมักทำให้ AI สับสนเรื่องสัญญาณ เพราะพฤติกรรมของลูกค้าสองกลุ่มนี้ต่างกันโดยพื้นฐาน

**Q: มี Purchase Event เกิดขึ้นจริง แต่ Ads Manager แสดงตัวเลขน้อยกว่าที่ควรจะเป็น ควรตรวจสอบอะไร?**
A: ตรวจสอบ 3 จุดตามลำดับ: (1) Attribution Window ที่ตั้งไว้ใน Ad Set (ค่าเริ่มต้นมักเป็น 7-day click, 1-day view) อาจไม่ครอบคลุมพฤติกรรมลูกค้าจริงถ้า Sales Cycle ยาวกว่านั้น (2) Event Match Quality ใน Events Manager ต่ำเกินไป ทำให้ Meta จับคู่ Event กับคนที่เห็นโฆษณาไม่ได้ครบ ควรปรับปรุงข้อมูลที่ส่งไปกับ Conversions API (3) มีการยิง Purchase Event ซ้ำ (Duplicate) หรือขาดหาย (Missing) เนื่องจากตั้งค่า Deduplication ระหว่าง Pixel และ CAPI ไม่ถูกต้อง ทบทวนได้ใน Part 015 Step 147

## Case Study เสริม: ธุรกิจอาหารเสริมใช้ Value Optimization แล้วเพิ่ม Revenue โดยไม่เพิ่มงบ

**สถานการณ์:** ธุรกิจอาหารเสริมมีสินค้า 3 ระดับ คือแพ็กทดลอง 390 บาท แพ็กปกติ 1,290 บาท และแพ็กสมาชิกรายปี 6,900 บาท ก่อนหน้านี้รันแคมเปญ Optimize ที่ Maximize number of conversions มาตลอด พบว่ายอดขายส่วนใหญ่ (ประมาณ 70%) มาจากแพ็กทดลองราคาถูก ทำให้ ROAS โดยรวมอยู่ที่ 2.1 ซึ่งสูงกว่า Break-even ROAS เล็กน้อย (1.8) แต่กำไรสุทธิต่อเดือนยังน้อยกว่าที่ธุรกิจต้องการ

**การทดลอง:** หลังจากสะสม Purchase Event ในบัญชีได้มากกว่า 300 ครั้งในช่วง 2 เดือน ทีมงานเปลี่ยน Ad Set บางส่วนไปใช้ Performance goal = Highest Value (Value Optimization) โดยตรวจสอบให้แน่ใจว่า Purchase Event ทุกตัวส่งค่า `value` ตามราคาสินค้าจริงถูกต้อง (ทบทวน Part 015 Step 146)

**ผลลัพธ์:** สัดส่วนยอดขายเปลี่ยนไปอย่างชัดเจน แพ็กสมาชิกรายปีมีสัดส่วนเพิ่มขึ้นจาก 8% เป็น 19% ของยอดขายรวม ทำให้ ROAS โดยรวมขยับจาก 2.1 เป็น 2.9 ทั้งที่งบโฆษณาต่อวันเท่ากันทุกประการ เพราะระบบไปหากลุ่มคนที่มีโอกาสซื้อแพ็กมูลค่าสูงมากขึ้น บทเรียนสำคัญคือ Value Optimization ไม่ได้ช่วยลดต้นทุนโฆษณา แต่ช่วยเปลี่ยน "คุณภาพของยอดขาย" ให้มีมูลค่าเฉลี่ยสูงขึ้น ซึ่งส่งผลต่อกำไรสุทธิได้มากกว่าการพยายามลด CPA เพียงอย่างเดียวในหลายกรณี

## สรุปหลักการสำคัญของ Sales/Conversion Campaign 10 ข้อ

1. เลือก Conversion Event ให้ตรงกับปริมาณข้อมูลที่มีจริง อย่ารีบ Optimize ที่ Purchase ถ้ายังไม่มีข้อมูลสะสม
2. กฎ 50 Events/สัปดาห์คือเกณฑ์ขั้นต่ำที่ต้องคำนึงถึงเสมอเมื่อตั้งงบ
3. ไล่ระดับ Conversion Event จากตื้นไปลึก (ViewContent สำหรับ Retargeting → AddToCart → InitiateCheckout → Purchase) เมื่อข้อมูลยังไม่พอ
4. Value Optimization เหมาะกับธุรกิจที่มีสินค้าหลายราคาต่างกันมากและมีข้อมูลสะสมมากพอเท่านั้น
5. Break-even ROAS ต้องคำนวณให้แม่นยำก่อนตัดสินใจ Scale หรือหยุดแคมเปญ
6. Pixel และ Destination URL ต้องตรงกันเสมอ ไม่เช่นนั้น Event จะไม่ถูกนับหรือนับผิด
7. ติดตั้ง Conversions API ควบคู่กับ Pixel เสมอเพื่อความแม่นยำหลัง iOS14+
8. อย่าแก้ไขแคมเปญที่อยู่ใน Learning Phase โดยไม่จำเป็น เพราะจะรีเซ็ตการเรียนรู้ใหม่ทุกครั้ง
9. อ่านผลลัพธ์แบบดูฟันเนลทั้งหมด (AddToCart → Purchase) ไม่ใช่ดูแค่ตัวเลขปลายทางตัวเดียว
10. ให้เวลาแคมเปญสะสมข้อมูลอย่างน้อย 3-7 วันก่อนตัดสินใจใหญ่ ยกเว้นกรณีขาดทุนรุนแรงชัดเจน

## Checklist ท้ายบท

- [ ] เลือก Objective = Sales และ Conversion location ถูกต้องตามลักษณะธุรกิจ (Website/App/ทั้งสอง/Messaging)
- [ ] วิเคราะห์ปริมาณ Purchase Event ที่มีอยู่จริง ก่อนเลือก Conversion Event ที่จะ Optimize
- [ ] ถ้ายังไม่มีข้อมูล Purchase สะสมมากพอ เริ่มจาก AddToCart/InitiateCheckout ก่อน
- [ ] คำนวณงบต่อวันจากสูตร CPA เป้าหมาย x 50 ÷ 7 เพื่อให้มีโอกาสออกจาก Learning Phase
- [ ] เลือก Performance goal (Maximize conversions หรือ Highest value) เหมาะกับความหลากหลายของราคาสินค้า
- [ ] ตรวจสอบว่า Pixel ที่เลือกใน Ad Set ตรงกับ Pixel ที่ติดตั้งบนหน้า Landing Page ปลายทาง

- [ ] คำนวณ Break-even ROAS ของธุรกิจไว้ล่วงหน้าก่อนตัดสินใจ Scale/หยุดแคมเปญ
- [ ] ตั้งค่า UTM Parameters ให้ครบถ้วนสำหรับการ Track ข้าม Platform

- [ ] ให้เวลาแคมเปญสะสมข้อมูลอย่างน้อย 3-7 วันก่อนตัดสินใจใหญ่ (ยกเว้นขาดทุนรุนแรงชัดเจน)

## Workshop / แบบฝึกหัด

**เป้าหมาย:** สร้างแคมเปญ Purchase Conversion เต็มระบบ 1 แคมเปญ พร้อมคำนวณ Break-even ROAS และแผนไล่ระดับ Conversion Event

**ขั้นตอนที่ต้องทำ:**

1. เลือกสินค้า/ธุรกิจ E-commerce สมมติ 1 ตัว กำหนดราคาขายและต้นทุนสินค้าให้ชัดเจน
2. คำนวณ Break-even ROAS จากราคาขายและ Margin ที่กำหนด
3. สมมติว่าธุรกิจนี้เพิ่งเปิดใหม่ ยังไม่มี Purchase Event สะสม เขียนแผนไล่ระดับ Conversion Event (เริ่มจาก Event อะไร นานเท่าไหร่ก่อนขยับไป Optimize Purchase)
4. เปิด Ads Manager สร้าง Campaign ใหม่ Objective = Sales, Conversion location = Website ตั้งชื่อตาม Naming Convention
5. ตั้งค่า Ad Set: เลือก Pixel, Conversion Event ตามแผนที่วางไว้ในข้อ 3, Performance goal, Audience, Placement = Advantage+
6. คำนวณงบต่อวันจากสูตร CPA เป้าหมาย x 50 ÷ 7 แล้วตั้งงบใน Ad Set ให้ตรงกับตัวเลขที่คำนวณได้
7. สร้าง Ad พร้อม Creative, Copy, Destination URL และ UTM Parameters ครบถ้วน
8. เขียนแผนการอ่านผลลัพธ์หลังแคมเปญวิ่งครบ 7 วัน จะดู Metric อะไรก่อน (ROAS, CPA, Purchase Value) และเกณฑ์ตัดสินใจว่าจะ Scale, ปรับ, หรือหยุดแคมเปญ
9. บันทึก Draft Campaign พร้อมเอกสารการคำนวณทั้งหมด เพื่อทบทวนกับทีม/เพื่อนร่วมเรียนก่อนเปิดงบจริง
10. ใช้เทมเพลตคำนวณ Break-even ROAS ใน Step 259 กรอกตัวเลขของธุรกิจที่เลือกให้ครบทั้ง 9 บรรทัด แล้วเก็บไว้เทียบกับผลลัพธ์จริงหลังแคมเปญวิ่ง

**เกณฑ์ตรวจสอบความสำเร็จ:** แคมเปญผ่าน Checklist ท้ายบททุกข้อ และสามารถอธิบายตัวเลข Break-even ROAS พร้อมแผนไล่ระดับ Conversion Event ได้อย่างชัดเจนโดยไม่ต้องเปิดเอกสารดู

### แบบฝึกหัดเสริม: วินิจฉัยปัญหาจากตัวเลขสมมติ

ฝึกวิเคราะห์สถานการณ์ต่อไปนี้ แล้วเขียนคำตอบว่าควรทำอย่างไรต่อ พร้อมอธิบายเหตุผล:

**สถานการณ์ A:** แคมเปญมี Cost per Add to Cart อยู่ที่ 25 บาท (ถูกมาก) แต่ Cost per Purchase อยู่ที่ 850 บาท (แพงมาก) ทั้งที่ราคาสินค้าเฉลี่ยอยู่ที่ 690 บาท ควรแก้ปัญหาที่จุดไหนก่อน?

**สถานการณ์ B:** Ad Set สถานะแสดง "Learning Limited" มา 2 สัปดาห์แล้ว โดยได้ Purchase เฉลี่ยเพียง 12 ครั้ง/สัปดาห์ งบต่อวันอยู่ที่ 500 บาท ควรปรับอะไรก่อน?

**สถานการณ์ C:** ROAS ของแคมเปญอยู่ที่ 4.2 ซึ่งดูสูงมาก แต่เจ้าของธุรกิจบอกว่ากำไรเดือนนี้ลดลง ควรตรวจสอบอะไรเพิ่มเติม?

(เฉลยแนวทาง: สถานการณ์ A ควรตรวจสอบขั้นตอน Checkout บนเว็บไซต์ก่อน เพราะ Drop-off ระหว่าง AddToCart กับ Purchase สูงผิดปกติ อาจเป็นปัญหาเรื่อง Payment Gateway หรือค่าส่งที่โผล่มาทีหลังจนลูกค้าเปลี่ยนใจ ไม่ใช่ปัญหาที่ตัวโฆษณา — สถานการณ์ B ควรพิจารณาเพิ่มงบหรือเปลี่ยนไป Optimize Event ที่ตื้นกว่าชั่วคราวเพื่อให้ผ่านเกณฑ์ 50 Events/สัปดาห์ — สถานการณ์ C ควรตรวจสอบว่า ROAS ที่เห็นคำนวณจาก Purchase Value ที่ถูกต้องหรือไม่ อาจมีปัญหาการยิง Event ซ้ำ (Duplicate) ทำให้ตัวเลขดูดีเกินจริง หรือตรวจสอบว่ามีต้นทุนอื่นที่เพิ่มขึ้นในเดือนนี้ เช่น ค่าคืนสินค้า (Return Rate) ที่ไม่ได้สะท้อนอยู่ใน ROAS ของ Ads Manager)

## สรุปและเชื่อมไปยัง Part ถัดไป

Part นี้เราเรียนรู้การสร้างแคมเปญ Conversions ตั้งแต่การเลือก Conversion Location, การเลือก Conversion Event ให้เหมาะกับปริมาณข้อมูลที่มี, กฎ Minimum Event Volume ที่ส่งผลต่อ Learning Phase, Value-Based Optimization สำหรับธุรกิจที่มีสินค้าหลายราคา, การตั้งค่าทุกระดับตั้งแต่ Campaign ถึง Ad, และการอ่านเมตริกสำคัญอย่าง ROAS และ CPA พร้อมความเข้าใจเรื่อง Break-even ROAS ที่นักยิงแอดมือใหม่มักเข้าใจผิด

Sales Objective คือจุดสุดยอดของสิ่งที่เราเรียนมาตลอด Section C เพราะมันรวมทุกอย่างที่เรียนมา ตั้งแต่ Pixel (Part 013-015) โครงสร้างแคมเปญ (Part 016) Objective Selection (Part 017) Budget Strategy (Part 018) และ Placement (Part 019) เข้าด้วยกันในรูปแบบแคมเปญเดียวที่วัดผลด้วยเงินจริงตรงที่สุด

ใน **Part 027: สร้างแคมเปญ Catalog Sales และ Dynamic Ads** เราจะขยับไปสู่รูปแบบแคมเปญขายที่ซับซ้อนขึ้นอีกระดับ คือการใช้ Product Catalog เพื่อสร้างโฆษณาที่ปรับเปลี่ยนสินค้าที่แสดงให้ตรงกับความสนใจของแต่ละคนโดยอัตโนมัติ (Dynamic Ads) ซึ่งเป็นเครื่องมือสำคัญมากสำหรับธุรกิจ E-commerce ที่มีสินค้าจำนวนมากและต้องการทำ Retargeting แบบเจาะรายสินค้า

แคมเปญ Sales/Conversions คือรูปแบบแคมเปญที่ให้ผลตอบแทนสูงที่สุดถ้าทำถูกต้อง แต่ก็เป็นรูปแบบที่ลงทุนผิดพลาดได้เร็วที่สุดถ้าตั้งค่าผิด เพราะงบที่ใช้มักสูงกว่า Objective อื่น ผู้เรียนควรฝึกคำนวณ Break-even ROAS และ Minimum Event Volume ให้คล่องจนเป็นสัญชาตญาณ เพราะสองอย่างนี้คือเครื่องมือป้องกันการขาดทุนที่สำคัญที่สุดสำหรับนักยิงแอดที่ทำงานกับเงินของธุรกิจหรือลูกค้าจริง

ก่อนไป Part ถัดไป ให้ทบทวนตัวเองด้วยคำถามเหล่านี้จนตอบได้อย่างมั่นใจ: อะไรคือความแตกต่างระหว่างการ Optimize ที่ AddToCart กับ Purchase และควรเลือกแบบไหนตอนไหน กฎ 50 Events ต่อสัปดาห์คำนวณงบต่อวันอย่างไร Break-even ROAS ของธุรกิจตัวเองคำนวณจากอะไร และทำไม ROAS ที่เป็นบวกไม่ได้แปลว่ากำไรเสมอไป ถ้าตอบคำถามเหล่านี้ได้อย่างชัดเจนโดยไม่ต้องเปิดเอกสาร แสดงว่าพร้อมสำหรับการสร้างแคมเปญ Conversions ในสถานการณ์จริงแล้ว

หมายเหตุปิดท้าย: เช่นเดียวกับทุก Part ใน Section C ชื่อฟิลด์และตำแหน่งเมนูใน Ads Manager อาจเปลี่ยนไปตามการอัปเดตของ Meta แต่หลักการเบื้องหลัง (ปริมาณข้อมูลที่ AI ต้องการเพื่อเรียนรู้, ความสัมพันธ์ระหว่างความลึกของ Event กับความแม่นยำ, และการคำนวณความคุ้มค่าทางธุรกิจก่อนใช้งบ) จะยังคงใช้ได้เสมอไม่ว่าอินเทอร์เฟซจะเปลี่ยนไปแบบไหนก็ตาม
