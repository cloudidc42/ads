## Step 171: Daily Budget vs Lifetime Budget ต่างกันอย่างไร

### นิยามที่ต้องเข้าใจให้แม่นก่อน

**Daily Budget (งบต่อวัน)** คือจำนวนเงินเฉลี่ยที่คุณยินยอมให้ระบบใช้ *ต่อวัน* โดยคำว่า "เฉลี่ย" สำคัญมาก เพราะ Meta ไม่ได้ล็อกให้ใช้เท่ากันทุกวันเป๊ะๆ ในบางวันระบบอาจใช้เกินงบที่ตั้งไว้ได้สูงสุดถึง **25%** ของ Daily Budget (เช่น ตั้ง 1,000 บาท/วัน วันที่มีโอกาสดีระบบอาจใช้ถึง 1,250 บาท) แต่จะไปหักชดเชยในวันที่โอกาสน้อยกว่า ทำให้เฉลี่ยทั้งสัปดาห์ไม่เกินงบที่ตั้งไว้คูณ 7 วัน

**Lifetime Budget (งบตลอดอายุแคมเปญ)** คือจำนวนเงินรวมทั้งหมดที่ต้องการใช้ตลอดช่วงเวลาที่กำหนด (ต้องระบุวันเริ่ม-วันจบที่ชัดเจนเสมอ) ระบบจะคำนวณเองว่าแต่ละวันควรใช้เท่าไหร่ โดยพยายามใช้งบให้ **หมดพอดีเมื่อถึงวันสิ้นสุด** และมักจะเกลี่ยงบไปยังช่วงเวลาที่ "มีโอกาสได้ผลลัพธ์ดีที่สุด" มากกว่าเกลี่ยเท่าๆกันทุกวัน

### ตารางเปรียบเทียบแบบละเอียด

| ประเด็น | Daily Budget | Lifetime Budget |
|---|---|---|
| ต้องระบุวันจบหรือไม่ | ไม่ต้อง (รันต่อเนื่องได้ไม่จำกัด) | ต้องระบุวันเริ่ม-วันจบเสมอ |
| ความผันแปรของงบต่อวัน | ใช้เกินได้สูงสุด 25% ในวันที่โอกาสดี แต่เฉลี่ยรายสัปดาห์ไม่เกิน | ระบบเกลี่ยเองตามโอกาส อาจใช้มากบางวัน น้อยบางวัน ต่างกันได้มากกว่า Daily |
| เหมาะกับ | แคมเปญ Evergreen ที่รันต่อเนื่องไม่มีกำหนดจบ (เช่น Always-on Retargeting) | แคมเปญที่มีกรอบเวลาชัดเจน (เช่น โปรโมชั่น 7 วัน, Flash Sale, อีเวนต์) |
| การควบคุมงบรวม | ควบคุมยากกว่าถ้าไม่หมั่นเช็ก (รันไปเรื่อยๆ เผลอใช้เกินเป้าได้) | ควบคุมงบรวมได้แม่นยำกว่า เพราะกำหนดเพดานรวมตายตัว |
| ผลต่อ Learning Phase | เสถียรกว่า เพราะงบสม่ำเสมอทุกวัน | อาจกระทบ Learning Phase ถ้าระบบเกลี่ยงบน้อยเกินไปในบางวันแรก |
| ความยืดหยุ่นในการหยุด/พัก | หยุดเมื่อไหร่ก็ได้ ไม่กระทบการคำนวณ | หยุดกลางทางจะทำให้งบที่เหลือ "เสียโอกาส" เพราะระบบวางแผนใช้จนหมดในกรอบเวลาที่กำหนดไว้แล้ว |

### เมื่อไหร่ควรใช้ Daily Budget

- แคมเปญที่ต้องรันต่อเนื่องไม่มีวันจบ เช่น Always-on Sales Campaign, Retargeting ที่ต้องวิ่งตลอดเวลา
- ธุรกิจที่ต้องการควบคุมกระแสเงินสดรายวันอย่างเข้มงวด (เช่น SME ที่จัดสรรงบเป็นรายวันจากยอดขายวันก่อน)
- มือใหม่ที่ยังไม่มั่นใจเรื่อง Pacing ของ Lifetime Budget ควรเริ่มจาก Daily Budget ก่อนเสมอ เพราะคาดเดาพฤติกรรมการใช้เงินได้ง่ายกว่า

### เมื่อไหร่ควรใช้ Lifetime Budget

- แคมเปญที่มีกรอบเวลาตายตัวชัดเจน เช่น 11.11, 12.12, Flash Sale 3 วัน, เปิดตัวสินค้าใหม่ 14 วัน
- ต้องการควบคุมงบรวมแบบเป๊ะๆ ไม่ให้เกินที่ตกลงกับลูกค้า (สำคัญมากสำหรับเอเจนซี่ที่รับงบมาบริหารเป็นก้อน)
- ต้องการให้ระบบช่วยตัดสินใจว่าวันไหนควรใช้งบมากกว่าวันไหน ตามโอกาสในการทำ Conversion (เช่น รู้ว่าวันศุกร์-อาทิตย์คนซื้อของมากกว่า ระบบจะเกลี่ยงบไปทางนั้นให้เองถ้าข้อมูลสนับสนุน)

### ตัวอย่างตัวเลขจริงให้เห็นภาพ

ร้านเสื้อผ้าออนไลน์วางแผนแคมเปญ Flash Sale 5 วัน (ศุกร์-อังคาร) งบรวม 15,000 บาท

**แบบที่ 1 — ตั้ง Daily Budget 3,000 บาท/วัน x 5 วัน:**
งบจะถูกใช้ใกล้เคียง 3,000 บาททุกวัน (อาจขยับ ±25% บางวัน) แม้ว่าวันเสาร์-อาทิตย์อาจมีโอกาสขายดีกว่าวันจันทร์-อังคารมาก ระบบก็จะไม่รู้ว่าให้เกลี่ยงบไปทางไหนมากกว่าเพราะถูกล็อกด้วยเพดานรายวันที่เท่ากันทุกวัน

**แบบที่ 2 — ตั้ง Lifetime Budget 15,000 บาท ระบุช่วง 5 วัน:**
ระบบมีโอกาสเกลี่ยงบไปยังวันเสาร์-อาทิตย์มากกว่า (เช่น ใช้ 4,000 บาทวันเสาร์ 4,500 บาทวันอาทิตย์ แล้วลดเหลือ 2,000 บาทวันจันทร์-อังคาร) ถ้าข้อมูล Auction บอกว่าวันเสาร์-อาทิตย์มีโอกาสได้ผลลัพธ์ดีกว่า ซึ่งในทางทฤษฎีน่าจะได้ผลลัพธ์รวมที่ดีกว่าแบบที่ 1 แต่ **ข้อแม้คือต้องมีข้อมูลในระบบพอให้ AI ตัดสินใจได้แม่นยำ** ถ้าเป็นบัญชีใหม่ที่ไม่มีข้อมูลเลย ผลอาจไม่ต่างจาก Daily Budget มากนัก

### ข้อผิดพลาดที่พบบ่อย

- ตั้ง Lifetime Budget แล้วไม่ได้ระบุวันจบให้ชัดเจน หรือระบุช่วงเวลาสั้นเกินไป (1-2 วัน) ทำให้ระบบไม่มีเวลาเกลี่ยงบอย่างมีประสิทธิภาพ (ควรมีอย่างน้อย 4-7 วันขึ้นไปถึงจะเห็นประโยชน์ของการเกลี่ยงบจริง)
- หยุดแคมเปญ Lifetime Budget กลางทางโดยไม่รู้ว่างบที่เหลือจะ "หายไป" ไม่ได้ใช้ต่อ ต่างจาก Daily Budget ที่หยุดเมื่อไหร่ก็แค่หยุดใช้งบตรงนั้น ไม่มีผลอะไรซับซ้อน
- ใช้ Daily Budget แต่ลืมว่าระบบใช้เกินได้ถึง 25% ในวันที่โอกาสดี ทำให้ตกใจเมื่อเห็นยอดใช้จ่ายบางวันสูงกว่าที่ตั้งไว้ (นี่ไม่ใช่บั๊ก เป็นการทำงานปกติของระบบ)
- คิดว่า Lifetime Budget จะประหยัดกว่า Daily Budget เสมอ ทั้งที่ความจริงคืองบรวมเท่ากัน แค่วิธีเกลี่ยรายวันต่างกัน ไม่ได้ถูกกว่าโดยอัตโนมัติ

## Step 172: Campaign Budget Optimization (CBO) เจาะลึก

### CBO คืออะไรกันแน่

Campaign Budget Optimization (ปัจจุบัน Meta เรียกอย่างเป็นทางการว่า **Advantage Campaign Budget**) คือการตั้งงบไว้ที่ระดับ **Campaign** เพียงจุดเดียว แล้วให้ระบบ Machine Learning เป็นคนตัดสินใจว่าจะกระจายงบไปให้ Ad Set ไหนมากหรือน้อยแบบ **Real-time** ตามผลลัพธ์ที่แต่ละ Ad Set ทำได้จริงในขณะนั้น

หลักการทำงานคือ ระบบจะประเมินทุก Ad Set ภายใน Campaign อย่างต่อเนื่องแล้วโยกงบไปให้ Ad Set ที่ "มีโอกาสสร้างผลลัพธ์ดีที่สุดในราคาที่ดีที่สุด" ในแต่ละช่วงเวลา ถ้า Ad Set A กำลังทำ Cost per Purchase ได้ 150 บาท ในขณะที่ Ad Set B ทำได้ 400 บาท ระบบจะเทงบไปที่ Ad Set A มากขึ้นโดยอัตโนมัติแบบไม่ต้องให้คนไปกดปรับเอง

### ข้อดีของ CBO

1. **ประหยัดเวลาบริหารจัดการ** — ไม่ต้องเข้าไปเช็กและปรับงบราย Ad Set ทุกวัน ระบบทำให้อัตโนมัติ เหมาะกับคนดูแลหลายบัญชีพร้อมกัน
2. **ลด Bias ของมนุษย์** — บางครั้งนักยิงแอดมีอคติชอบ Ad Set ที่ตัวเอง "รู้สึกว่าน่าจะดี" ทั้งที่ตัวเลขจริงไม่ได้ดีที่สุด CBO ตัดปัจจัยความรู้สึกออกไป ใช้ตัวเลขล้วนๆ
3. **ตอบสนองเร็วกว่ามนุษย์** — ระบบปรับงบได้เป็นรายชั่วโมง ในขณะที่คนอาจเข้าไปเช็กวันละครั้งเท่านั้น
4. **เหมาะกับการทดสอบ Audience หลายกลุ่มพร้อมกัน** — สร้าง Ad Set 3-5 กลุ่มไว้ในแคมเปญเดียว ให้ระบบเลือกกลุ่มที่ดีที่สุดให้เอง โดยไม่ต้องตั้งงบแยกทีละกลุ่มแบบเดา

### ข้อเสียและข้อจำกัดของ CBO

1. **Ad Set บางกลุ่มอาจไม่ได้งบเลยหรือได้น้อยมาก** — ถ้าคุณต้องการทดสอบทุกกลุ่มให้ได้ข้อมูลเท่ากันก่อนตัดสินใจ (เช่น A/B Test Audience) CBO อาจเทงบไปกลุ่มที่ "ชนะเร็ว" ตั้งแต่ต้น ทำให้กลุ่มอื่นไม่มีโอกาสได้แสดงศักยภาพเต็มที่ (Winner-take-most Effect)
2. **ควบคุมยากเมื่อมี Ad Set ที่มีเป้าหมายต่างกัน** — เช่น Ad Set หนึ่งเน้น Retargeting (ควรได้งบเยอะเพราะ Convert ง่าย) อีก Ad Set เน้น Cold Prospecting (ควรได้งบเพื่อหาลูกค้าใหม่ต่อเนื่อง แม้ CPA จะสูงกว่า) — CBO จะเทงบไปที่ Retargeting เกือบหมดเพราะ CPA ถูกกว่า ทำให้ Cold Prospecting ไม่ได้งบพอจะหาลูกค้าใหม่เข้าระบบเลย
3. **Minimum Budget ต่อ Ad Set ควบคุมได้จำกัด** — สามารถตั้ง "Minimum Daily Budget" ราย Ad Set ได้ในบางกรณี แต่ไม่ยืดหยุ่นเท่าการตั้งงบ ABO แยกเอง

### การตั้งค่า CBO ใน Ads Manager

1. ที่ Campaign Level → เปิด "Advantage Campaign Budget" (บางบัญชีอาจเห็นเป็น Toggle เปิด-ปิด)
2. เลือก Daily Budget หรือ Lifetime Budget ที่ระดับ Campaign
3. เลือก Bid Strategy ที่ระดับ Campaign (มีผลกับทุก Ad Set ในแคมเปญนั้น)
4. สร้าง Ad Set หลายกลุ่มตามปกติ โดยไม่ต้องตั้งงบราย Ad Set (ช่อง Budget จะถูกซ่อนไปเพราะย้ายไปคุมที่ Campaign แล้ว)
5. หากต้องการกันงบขั้นต่ำให้ Ad Set สำคัญไม่ให้ถูกลดจนแทบไม่ได้แสดงผล ให้ตั้ง "Cost per Result Goal" หรือปรับ Bid ราย Ad Set เพื่อชี้นำระบบทางอ้อม

### ตัวอย่างตัวเลขการทำงานจริงของ CBO

Campaign หนึ่งตั้ง CBO ที่ 6,000 บาท/วัน มี 3 Ad Set (Interest A, Interest B, Lookalike 1%) หลังรัน 5 วัน:

| Ad Set | วันที่ 1 | วันที่ 3 | วันที่ 5 | Cost per Purchase เฉลี่ย |
|---|---|---|---|---|
| Interest A | 2,000 บาท | 1,200 บาท | 500 บาท | 320 บาท |
| Interest B | 2,000 บาท | 1,800 บาท | 800 บาท | 280 บาท |
| Lookalike 1% | 2,000 บาท | 3,000 บาท | 4,700 บาท | 145 บาท |

เห็นได้ชัดว่าระบบเทงบไปที่ Lookalike 1% มากขึ้นทุกวันเพราะทำ Cost per Purchase ได้ดีที่สุด นี่คือพฤติกรรมปกติของ CBO — ถ้าคุณต้องการให้ Interest A/B ได้งบทดสอบต่อเนื่องเพื่อเก็บข้อมูลระยะยาว (ไม่ใช่แค่ระยะสั้น) CBO อาจไม่ใช่ทางเลือกที่ดีที่สุดสำหรับสถานการณ์นี้

### ข้อผิดพลาดที่พบบ่อย

- ใช้ CBO แล้วยัด Ad Set ที่มีเป้าหมายต่างกันสิ้นเชิงไว้ในแคมเปญเดียว (เช่น ปนกันระหว่าง Retargeting กับ Cold Prospecting) ทำให้งบไม่กระจายอย่างที่ต้องการ
- คาดหวังให้ทุก Ad Set ได้งบเท่ากันภายใต้ CBO ทั้งที่หลักการของ CBO คือการ "ไม่เท่ากัน" โดยเจตนา
- ไม่ได้เผื่อ Ad Set ที่มีศักยภาพสูงแต่ยังไม่มีข้อมูล (Ad ใหม่ล่าสุด) ให้มีโอกาสได้งบทดสอบก่อนที่ระบบจะตัดสินโดยข้อมูลไม่พอ

## Step 173: Ad Set Budget Optimization (ABO) เจาะลึก

### ABO คืออะไร

Ad Set Budget Optimization คือการตั้งงบแยกที่ระดับ **Ad Set** เอง แต่ละ Ad Set มีเพดานงบของตัวเองที่ตายตัว ไม่ถูกระบบโยกงบไปให้ Ad Set อื่นโดยอัตโนมัติ พูดง่ายๆ คือ "คุณคุมเองทุกบาท ทุก Ad Set"

### ข้อดีของ ABO

1. **ควบคุมการทดสอบได้แม่นยำ** — ถ้าต้องการ A/B Test Audience 3 กลุ่มให้ได้งบเท่ากันเป๊ะๆ เพื่อเปรียบเทียบผลลัพธ์อย่างเป็นธรรม (Apples-to-apples Comparison) ABO คือทางเลือกเดียวที่ทำได้
2. **ปกป้อง Ad Set ที่มีความสำคัญเชิงกลยุทธ์** — เช่น Ad Set ที่ยิง Cold Audience เพื่อหาลูกค้าใหม่ ต้องมีงบการันตีทุกวันแม้ CPA จะสูงกว่า Retargeting เพราะถ้าไม่มีลูกค้าใหม่เข้าระบบต่อเนื่อง สุดท้าย Retargeting Pool จะหมดและทั้งบัญชีจะโตต่อไม่ได้
3. **คาดการณ์งบได้แม่นยำกว่า** — เหมาะกับการรายงานลูกค้าที่ต้องการรู้ชัดว่าแต่ละกลุ่มเป้าหมายใช้งบเท่าไหร่แน่นอน
4. **เหมาะกับการ Scale แบบมีจังหวะ** — ปรับงบ Ad Set ที่ดีขึ้นทีละ 20% ตามจังหวะที่ต้องการ ไม่ต้องพึ่งการตัดสินใจอัตโนมัติของระบบ

### ข้อเสียของ ABO

1. **ใช้เวลาบริหารจัดการมากกว่า** — ต้องเข้าไปเช็กและปรับงบราย Ad Set เองทุกวัน/สัปดาห์
2. **มี Bias ของมนุษย์เข้ามาปน** — การตัดสินใจปรับงบอาจไม่แม่นยำเท่าการให้ AI ตัดสินใจแบบ Real-time ถ้าไม่มีวินัยในการดูข้อมูลสม่ำเสมอ
3. **เสี่ยงตั้งงบผิดสัดส่วนได้ง่าย** — ถ้าไม่มีกรอบคิดชัดเจน อาจให้งบ Ad Set ที่ผลงานแย่มากเกินไปโดยไม่รู้ตัว

### การตั้งค่า ABO ใน Ads Manager

1. ที่ Campaign Level → **ปิด** "Advantage Campaign Budget" (ไม่เปิด Toggle)
2. ไปที่ Ad Set Level แต่ละกลุ่ม → ตั้ง Daily/Lifetime Budget แยกทีละกลุ่มตามที่วางแผนไว้
3. Bid Strategy สามารถตั้งแยกตาม Ad Set ได้ (ยืดหยุ่นกว่า CBO ที่ Bid Strategy ผูกกับ Campaign)
4. เหมาะมากสำหรับการทำ Naming Convention ที่ระบุงบไว้ในชื่อ Ad Set เพื่อให้ตรวจสอบง่าย เช่น `AS_Lookalike1%_ABO_1500THB`

### ตัวอย่างการวางแผน ABO เชิงกลยุทธ์

ธุรกิจคอร์สออนไลน์ งบรวม 20,000 บาท/สัปดาห์ ต้องการควบคุมชัดเจนว่าแต่ละกลุ่มได้งบเท่าไหร่:

| Ad Set | เป้าหมาย | งบ/วัน (ABO) | เหตุผลที่ต้องการันตีงบ |
|---|---|---|---|
| Cold — Lookalike 1% | หาลูกค้าใหม่ | 1,200 บาท | ต้องมีลูกค้าใหม่เข้าระบบต่อเนื่องทุกวัน แม้ CPA สูงกว่า |
| Cold — Interest กว้าง | ทดสอบ Audience ใหม่ | 500 บาท | ต้องการข้อมูลทดสอบต่อเนื่อง ไม่อยากให้ CBO ตัดงบจนเหลือ 0 |
| Warm — Video Viewers 50%+ | รีทาร์เก็ตกลุ่มอุ่น | 800 บาท | มี Pool ขนาดจำกัด งบเกินความจำเป็นจะทำให้ Frequency สูงเกินไป |
| Hot — Add to Cart/Checkout | ปิดการขาย | 1,357 บาท | เป็นกลุ่มที่ให้ ROAS สูงสุด ควรได้งบมากสุดแต่ไม่ล้น Pool |

การกำหนดงบแบบนี้ทำได้เฉพาะ ABO เท่านั้น เพราะถ้าใช้ CBO ระบบอาจเทงบไปที่กลุ่ม Hot ทั้งหมดจนกลุ่ม Cold แทบไม่ได้งบเลย ซึ่งจะทำให้ธุรกิจไม่มีลูกค้าใหม่เข้าระบบในระยะยาว

### ข้อผิดพลาดที่พบบ่อย

- ตั้งงบ ABO แล้วไม่เคยกลับมาปรับเลยตลอดทั้งเดือน ทั้งที่ผลลัพธ์ราย Ad Set เปลี่ยนไปมากแล้ว (ต้องมีวินัยเข้าไปดูข้อมูลอย่างน้อยสัปดาห์ละ 1-2 ครั้ง)
- ตั้งงบเท่ากันทุก Ad Set โดยไม่สนใจว่าแต่ละกลุ่มมีขนาด Audience ต่างกันมาก (เช่น Ad Set ที่มี Audience 500,000 คน กับ Ad Set ที่มี Audience 20,000 คน ไม่ควรได้งบเท่ากัน เพราะกลุ่มเล็กจะ Frequency สูงเกินไปเร็วมาก)
- ลืมเช็ก Total Budget รวมทุก Ad Set ว่าตรงกับงบที่ตกลงกับลูกค้าหรือไม่ (ต่างจาก CBO ที่ควบคุมง่ายกว่าเพราะมีเพดานเดียว)

## Step 174: เมื่อไหร่ควรใช้ CBO เมื่อไหร่ควรใช้ ABO

### กรอบการตัดสินใจหลัก

| สถานการณ์ | แนะนำ | เหตุผล |
|---|---|---|
| ต้องการ A/B Test Audience หลายกลุ่มให้ยุติธรรม (งบเท่ากัน) | ABO | CBO จะเทงบไปกลุ่มที่ชนะเร็วก่อนได้ข้อมูลครบ ทำให้เทียบกันไม่ยุติธรรม |
| มี Ad Set หลายกลุ่มที่ "เป้าหมายเดียวกัน" (เช่น ทดสอบ Creative 5 ตัวในกลุ่มเดียวกัน) | CBO | เหมาะมาก เพราะต้องการให้ระบบเลือก Creative ที่ดีที่สุดเองแบบอัตโนมัติ |
| มี Ad Set ที่ "บทบาทต่างกัน" (Cold หาใหม่ vs Warm รีทาร์เก็ต) ในแคมเปญเดียว | ABO | ต้องการันตีงบให้ Cold Audience ไม่ให้ระบบตัดจนเหลือ 0 |
| ธุรกิจที่มีงบจำกัดมาก (ต่ำกว่า 1,000 บาท/วัน) และมี Ad Set น้อย (1-2 กลุ่ม) | CBO หรือ ABO ก็ได้ (ผลต่างไม่มาก) | งบน้อยเกินกว่าจะเห็นความแตกต่างชัดเจนระหว่างสองระบบ |
| ต้องการรายงานลูกค้าที่ต้องระบุงบแยกตามกลุ่มเป้าหมายชัดเจน | ABO | รายงานง่ายกว่า ควบคุมได้ตรงตามที่ตกลงกับลูกค้า |
| ต้องการประหยัดเวลาบริหารจัดการ ดูหลายบัญชีพร้อมกัน | CBO | ลดงานที่ต้องเข้าไปปรับงบเองทุกวัน |
| แคมเปญ Scale ที่มี Ad Set จำนวนมาก (10+ กลุ่ม) และต้องการให้ AI จัดการงบเอง | CBO | บริหารด้วยมือ 10+ Ad Set ทำได้ยากและช้ากว่า AI มาก |

### แนวทาง Hybrid ที่มืออาชีพใช้จริง

ในทางปฏิบัติ นักยิงแอดระดับมืออาชีพมักไม่เลือกแค่ CBO หรือ ABO อย่างใดอย่างหนึ่งตลอดทั้งบัญชี แต่จะ **แยก Campaign ตามบทบาท** เช่น:

- **Campaign 1 (Cold Prospecting)** — ใช้ ABO เพื่อการันตีงบให้แต่ละ Audience ที่กำลังทดสอบ
- **Campaign 2 (Warm Retargeting)** — ใช้ CBO เพราะ Ad Set ในกลุ่มนี้มีเป้าหมายเดียวกันหมด (ปิดการขาย) ให้ระบบเลือกกลุ่มที่ Convert ดีที่สุดเอง
- **Campaign 3 (Creative Testing)** — ใช้ CBO เสมอ เพราะต้องการให้ระบบหา Creative ที่ชนะให้เร็วที่สุด

วิธีนี้ผสมข้อดีของทั้งสองระบบเข้าด้วยกัน โดยใช้ ABO ตรงจุดที่ต้องควบคุมความยุติธรรมของการทดสอบ และใช้ CBO ตรงจุดที่ต้องการความเร็วในการหาผู้ชนะ

### ตารางสรุปเปรียบเทียบเชิงตัวเลข (จากข้อมูลบัญชีตัวอย่างในตลาดไทย)

| ตัวชี้วัด | CBO (เฉลี่ย) | ABO (เฉลี่ย) |
|---|---|---|
| เวลาที่ใช้บริหารจัดการต่อสัปดาห์ | 1-2 ชั่วโมง | 3-5 ชั่วโมง |
| ความแม่นยำของ A/B Test | ต่ำ-กลาง (มี Bias จากการเทงบเร็ว) | สูง (งบเท่ากันแท้จริง) |
| ความเสี่ยง Ad Set สำคัญไม่ได้งบ | สูง | ต่ำ (ควบคุมได้เอง) |
| ความเหมาะสมกับบัญชีที่มี Ad Set จำนวนมาก | สูง | ต่ำ-กลาง |

## Step 175: Bid Strategy — Lowest Cost, Cost Cap, Bid Cap, ROAS Goal

### ภาพรวม Bid Strategy ทั้ง 4 แบบ

Bid Strategy คือ "วิธีที่คุณสั่งให้ระบบประมูล" ในตลาด Auction ไม่ใช่แค่การตั้งงบเฉยๆ — คุณกำลังบอกระบบว่า "ให้ประมูลแบบไหน" ซึ่งมีผลต่อทั้งปริมาณผลลัพธ์ ต้นทุนต่อผลลัพธ์ และความเร็วในการใช้งบ

**1. Lowest Cost (ชื่อเดิม) / ปัจจุบันคือค่า Default ไม่มีชื่อแยก**
ระบบจะพยายามหาผลลัพธ์ให้ได้มากที่สุดในงบที่มี โดยไม่สนใจว่าต้นทุนต่อผลลัพธ์จะสูงหรือต่ำ ตราบใดที่ยังใช้งบได้อยู่ ระบบจะประมูลไปเรื่อยๆ นี่คือค่า Default ที่ Meta ตั้งให้ทุกแคมเปญโดยอัตโนมัติถ้าไม่ได้เข้าไปปรับ

- ข้อดี: ใช้งบเต็มที่ทุกวัน ไม่มีความเสี่ยง "ไม่วิ่ง" เพราะไม่มีเพดานต้นทุนที่จำกัด
- ข้อเสีย: ไม่มีการควบคุมต้นทุนต่อผลลัพธ์เลย บางวันอาจได้ CPA ที่แพงกว่าที่ต้องการมากถ้า Auction แข่งขันสูง
- เหมาะกับ: มือใหม่ที่ยังไม่รู้ Benchmark ต้นทุนของธุรกิจตัวเอง หรือช่วงเริ่มต้นแคมเปญที่ต้องการให้ Learning Phase จบเร็วที่สุด

**2. Cost Cap (เพดานต้นทุนเฉลี่ย)**
คุณกำหนด "ต้นทุนเฉลี่ยที่ยอมรับได้ต่อผลลัพธ์" ระบบจะพยายามคุมต้นทุนเฉลี่ยให้ไม่เกินตัวเลขนี้ตลอดการรัน (คำว่า "เฉลี่ย" สำคัญ เพราะบางผลลัพธ์อาจแพงกว่าเพดาน แต่บางผลลัพธ์ถูกกว่า สุดท้ายเฉลี่ยรวมจะพยายามไม่เกินที่ตั้งไว้)

- ข้อดี: ควบคุมต้นทุนได้ดีกว่า Lowest Cost มาก เหมาะกับธุรกิจที่รู้ Break-even CPA ชัดเจนแล้ว
- ข้อเสีย: ถ้าตั้งเพดานต่ำเกินไป (ต่ำกว่าที่ตลาดแข่งขันได้จริง) แคมเปญอาจใช้งบไม่หมดหรือ "ไม่วิ่ง" เลย เพราะระบบไม่กล้าประมูลแพงพอจะชนะ
- เหมาะกับ: ธุรกิจที่มี Break-even ROAS/CPA ชัดเจนแล้วและต้องการรักษากำไรให้สม่ำเสมอ

**3. Bid Cap (เพดานราคาประมูลสูงสุด)**
คุณกำหนด "ราคาสูงสุดที่ยอมประมูลในแต่ละ Auction" (ไม่ใช่ต้นทุนเฉลี่ยแบบ Cost Cap แต่เป็นเพดานราคาประมูลจริงในแต่ละครั้ง) ควบคุมเข้มงวดกว่า Cost Cap มาก และต้องใช้ความรู้เชิงลึกเรื่อง Auction Dynamics ค่อนข้างสูง

- ข้อดี: ควบคุมสูงสุดในทุก Bid Strategy เหมาะกับมืออาชีพที่ต้องการควบคุมทุกรายละเอียด
- ข้อเสีย: ตั้งยากที่สุด ต้องมีข้อมูล Auction ในอดีตมากพอจะประเมินราคาที่เหมาะสม ถ้าตั้งผิดมีโอกาส "ไม่วิ่งเลย" สูงมาก
- เหมาะกับ: นักยิงแอดระดับ Advanced ที่มีข้อมูล Benchmark ราคาประมูลของ Audience ตัวเองมานานพอ

**4. ROAS Goal (เป้าหมายผลตอบแทนต่อการลงทุน)**
เฉพาะ Sales Objective ที่มี Value Optimization คุณกำหนด "ROAS ขั้นต่ำที่ต้องการ" (เช่น 3.0 หมายถึงทุก 1 บาทที่ลงทุนต้องได้ยอดขายคืนอย่างน้อย 3 บาท) ระบบจะพยายามหาลูกค้าที่มีโอกาสสร้าง ROAS ตามเป้าหมายนี้

- ข้อดี: เหมาะมากกับธุรกิจที่มี Order Value หลากหลายและสนใจ "มูลค่า" มากกว่า "จำนวนครั้ง" ของ Conversion
- ข้อเสีย: ต้องมีข้อมูล Value ที่แม่นยำมาก (Pixel/CAPI ต้องส่ง Purchase Value ถูกต้อง 100%) ถ้าตั้งเป้า ROAS สูงเกินจริง แคมเปญอาจไม่วิ่งเลย
- เหมาะกับ: E-commerce ที่มีสินค้าหลากหลายราคาและต้องการเน้นกำไรมากกว่าปริมาณออเดอร์

### ตารางสรุปเปรียบเทียบทั้ง 4 Bid Strategy

| Bid Strategy | ควบคุมอะไร | ความเสี่ยงหลัก | ระดับผู้ใช้ที่เหมาะสม |
|---|---|---|---|
| Lowest Cost | ไม่ควบคุมต้นทุน เน้นผลลัพธ์มากสุด | CPA อาจพุ่งสูงไม่จำกัดถ้า Auction แข่งดุ | มือใหม่ - กลาง |
| Cost Cap | ต้นทุนเฉลี่ยต่อผลลัพธ์ | ไม่วิ่ง/ใช้งบไม่หมดถ้าตั้งเพดานต่ำเกินไป | กลาง - สูง |
| Bid Cap | ราคาประมูลสูงสุดต่อครั้ง | ไม่วิ่งง่ายที่สุดถ้าประเมินราคาผิด | สูง (Advanced) |
| ROAS Goal | ผลตอบแทนต่อการลงทุน (มูลค่า) | ต้องมี Value Data แม่นยำมาก ไม่งั้นเป้าหมายผิดเพี้ยน | กลาง - สูง (E-commerce) |

### ตัวอย่างตัวเลขจริงเปรียบเทียบ Lowest Cost vs Cost Cap

ร้านขายอาหารเสริมออนไลน์ ทดสอบ 2 Ad Set คู่กัน งบ 5,000 บาท/วัน 7 วัน เป้าหมาย Cost per Purchase ที่รับได้คือ 250 บาท:

| ตัวชี้วัด | Lowest Cost | Cost Cap (ตั้งเพดาน 250 บาท) |
|---|---|---|
| งบที่ใช้ทั้ง 7 วัน | 35,000 บาท (ใช้เต็ม 100%) | 31,500 บาท (ใช้ 90% เพราะบางวันประมูลไม่ทันเพดาน) |
| จำนวน Purchase | 106 ครั้ง | 118 ครั้ง |
| Cost per Purchase เฉลี่ย | 330 บาท | 267 บาท |
| วันที่ Cost per Purchase พุ่งสูงสุด | 480 บาท (วันที่ 5) | 290 บาท (วันที่ 5) |

จะเห็นว่า Cost Cap ควบคุมความผันผวนของต้นทุนได้ดีกว่ามาก แม้จะใช้งบไม่เต็ม 100% แต่ได้ Purchase มากกว่าและ Cost per Purchase เฉลี่ยต่ำกว่า Lowest Cost ชัดเจน — นี่คือเหตุผลที่ธุรกิจที่มี Break-even ชัดเจนแล้วมักเปลี่ยนจาก Lowest Cost ไปใช้ Cost Cap หลังจากผ่านช่วงทดสอบเริ่มต้น

### ข้อผิดพลาดที่พบบ่อย

- ตั้ง Cost Cap หรือ Bid Cap ตั้งแต่วันแรกที่ยังไม่มีข้อมูล Benchmark เลย ทำให้เดาเพดานผิดและแคมเปญไม่วิ่งตั้งแต่ต้น (ควรรัน Lowest Cost อย่างน้อย 1-2 สัปดาห์แรกเพื่อเก็บ Benchmark ก่อน)
- ใช้ ROAS Goal ทั้งที่ Pixel ยังส่ง Purchase Value ไม่แม่นยำ (เช่น ส่งค่า Value เป็น 0 หรือ Static Value ที่ไม่ตรงกับราคาสินค้าจริง) ทำให้ระบบตัดสินใจผิดพลาดทั้งหมด
- ตั้งเพดาน Cost Cap ต่ำเกินไปโดยหวังจะ "บีบ" ให้ต้นทุนถูกลง แต่ผลคือแคมเปญใช้งบไม่หมดและได้ผลลัพธ์น้อยกว่าที่ควรจะเป็น
- เปลี่ยน Bid Strategy กลางแคมเปญบ่อยเกินไปเพื่อลองผิดลองถูก ทำให้ Learning Phase ต้องรีเซ็ตใหม่ทุกครั้ง (การเปลี่ยน Bid Strategy จะรีเซ็ต Learning Phase เสมอ ต่างจากการปรับ Budget แบบเล็กน้อยที่ไม่รีเซ็ต)

## Step 176: Pacing และการกระจายงบตลอดวัน

### Pacing คืออะไร

Pacing คือกลไกที่ Meta ใช้ตัดสินใจว่าจะ "เข้าประมูล Auction บ่อยแค่ไหนในแต่ละช่วงเวลาของวัน" เพื่อให้งบที่ตั้งไว้ถูกใช้ครบพอดีเมื่อสิ้นวัน (หรือสิ้นสุดช่วงเวลาที่กำหนดสำหรับ Lifetime Budget) ไม่ใช่ใช้งบหมดตั้งแต่ 9 โมงเช้าแล้วหยุดฉายทั้งวัน

ระบบมี 2 รูปแบบ Pacing หลัก:

**1. Standard Pacing (ค่า Default)**
ระบบจะกระจายงบให้ครอบคลุมตลอดทั้งวัน (หรือทั้งช่วงเวลาที่กำหนด) โดยพยายามจับโอกาสที่ดีที่สุดตลอดเวลา ไม่เร่งใช้งบเร็วเกินไป เหมาะกับแคมเปญส่วนใหญ่

**2. Accelerated Pacing (เร่งใช้งบ)**
ระบบจะพยายามใช้งบให้เร็วที่สุด ไม่รอจังหวะที่ดีที่สุด เหมาะกับสถานการณ์ที่ต้องการผลลัพธ์เร็วมากในเวลาจำกัด เช่น โปรโมชั่น Flash Sale ไม่กี่ชั่วโมง หรือข่าวด่วนที่ต้องการ Reach เร็วที่สุด — ข้อเสียคือมักได้ CPA ที่แพงกว่า Standard Pacing เพราะไม่รอเลือกจังหวะที่ดีที่สุด

### ทำไมเข้าใจ Pacing ถึงสำคัญ

หลายคนเห็นว่าแคมเปญ "ใช้งบน้อยในช่วงเช้า แล้วเร่งใช้มากขึ้นช่วงเย็น" แล้วเข้าใจผิดว่าระบบมีบั๊ก ทั้งที่จริงคือ Pacing กำลังทำงานตามที่ควรจะเป็น — ระบบกำลังรอจังหวะที่ Auction มีการแข่งขันน้อยกว่าหรือมีโอกาส Conversion สูงกว่า (เช่น ช่วงเย็นหลังเลิกงานที่คนไทยเปิดโทรศัพท์เล่นมากขึ้น มักมี Conversion Rate สูงกว่าช่วงเช้า)

### ตัวอย่างกราฟการใช้งบตลอดวัน (Standard Pacing)

สมมติงบ 2,400 บาท/วัน สำหรับร้านอาหารที่คนสั่งเดลิเวอรี่ตอนเย็น-ค่ำเป็นหลัก:

| ช่วงเวลา | สัดส่วนงบที่ใช้โดยประมาณ | เหตุผลจากข้อมูลพฤติกรรม |
|---|---|---|
| 06:00–10:00 | 8% (192 บาท) | คนส่วนใหญ่ยังไม่คิดเรื่องมื้อเย็น Auction เงียบ |
| 10:00–14:00 | 22% (528 บาท) | ช่วงมื้อเที่ยง มีการค้นหา/สั่งอาหารสูง |
| 14:00–17:00 | 12% (288 บาท) | ช่วงพักบ่าย Engagement ต่ำ |
| 17:00–21:00 | 43% (1,032 บาท) | Prime Time มื้อเย็น Conversion Rate สูงสุดของวัน |
| 21:00–06:00 | 15% (360 บาท) | ดึกดื่น มีบางกลุ่มสั่งของกินดึกแต่น้อยกว่าช่วงเย็น |

ตัวเลขนี้เป็นภาพประกอบให้เข้าใจหลักการ ไม่ใช่ตัวเลขตายตัว — ระบบจะเรียนรู้และปรับสัดส่วนจริงตามข้อมูล Conversion ของแต่ละบัญชีเอง

### ข้อผิดพลาดที่พบบ่อย

- ตั้งงบน้อยเกินไปแล้วเปิด Ad Scheduling จำกัดช่วงเวลาแคบมาก ทำให้ Pacing ไม่มีพื้นที่พอจะกระจายงบอย่างมีประสิทธิภาพ
- เปลี่ยนจาก Standard เป็น Accelerated Pacing โดยไม่เข้าใจว่าจะทำให้ CPA แพงขึ้น แล้วบ่นว่า "ต้นทุนพุ่ง" ทั้งที่ตัวเองเป็นคนเลือกตั้งค่านี้เอง
- เข้าไปเช็กผลลัพธ์ตอนเช้าแล้วรีบสรุปว่าแคมเปญ "ไม่ดี" เพราะเห็นตัวเลขน้อย ทั้งที่ Pacing ยังไม่ทันกระจายงบไปถึงช่วง Prime Time ของวันเลย (ควรรอดูผลรวมทั้งวันหรือหลายวันก่อนตัดสิน ไม่ใช่ดูแค่บางช่วงเวลา)

## Step 177: Minimum Budget ที่แนะนำตาม Objective

### ทำไมต้องมี Minimum Budget

Learning Phase ของ Meta ต้องการ "จำนวน Optimization Event" ที่มากพอในช่วง 7 วันแรกถึงจะออกจาก Learning Phase ได้ (โดยทั่วไปแนะนำ 50 Events/สัปดาห์/Ad Set แม้บางกรณีจะจบได้ด้วยจำนวนน้อยกว่านั้น) ถ้างบน้อยเกินไปจนได้ Event ไม่ถึงเกณฑ์ Ad Set จะติดอยู่ใน Learning Phase ตลอดไป (หรือถูกจัดเป็น "Learning Limited") ซึ่งหมายถึงระบบยังไม่ได้ใช้ศักยภาพ Machine Learning เต็มที่ ทำให้ผลลัพธ์แพงกว่าที่ควรเป็น

### ตารางแนะนำ Minimum Budget ตาม Objective (อ้างอิงตลาดไทย)

| Objective / Optimization Goal | Minimum Budget แนะนำ/วัน (บาท) | เหตุผล |
|---|---|---|
| Awareness (Reach) | 100-300 | ไม่ต้องพึ่ง Conversion Event มาก เน้นกระจาย Reach เป็นหลัก |
| Awareness (Ad Recall Lift) | 3,000+ | ต้องการ Reach ฐานใหญ่พอให้วัด Lift ได้อย่างมีความหมายทางสถิติ |
| Traffic (Landing Page Views) | 200-400 | ต้นทุนต่อ LPV มักไม่แพง ได้ปริมาณคลิกพอสมควรในงบไม่สูง |
| Engagement (ThruPlay) | 150-350 | ThruPlay มักมีต้นทุนต่ำ ได้ Volume ง่าย |
| Leads (Instant Form) | 500-800 | ต้องการลีดอย่างน้อย 5-10 ครั้ง/วันเพื่อให้ Learning Phase ขยับได้เร็ว |
| Leads (Website Leads) | 700-1,200 | Friction สูงกว่า Instant Form ต้องการงบมากกว่าเพื่อให้ได้จำนวน Event พอ |
| Sales (Website Conversions — Purchase) | 800-1,500 | ต้องการ Purchase อย่างน้อย 7-15 ครั้ง/สัปดาห์ต่อ Ad Set (คิดเป็นรายวันประมาณ 1-3 ครั้ง) |
| Sales (Catalog / Dynamic Retargeting) | 300-600 | Pool มักเป็น Warm Audience ต้นทุนต่ำกว่า Cold Sales |
| Sales (Store Traffic) | 500-1,000 | ขึ้นกับขนาดรัศมีและความหนาแน่นของประชากรรอบสาขา |

> ตัวเลขเหล่านี้เป็นค่ากลางสำหรับอ้างอิงในตลาดไทยปี 2025-2026 ธุรกิจที่มี CPM สูงกว่าค่าเฉลี่ย (เช่น อุตสาหกรรมที่แข่งขันดุเดือดอย่างการเงิน/ความงาม) อาจต้องใช้งบสูงกว่านี้เพื่อให้ได้จำนวน Event เท่ากัน

### วิธีคำนวณ Minimum Budget ด้วยตัวเอง (สูตรที่ใช้งานได้จริง)

```
Minimum Budget ต่อวัน = (จำนวน Event ขั้นต่ำที่ต้องการต่อสัปดาห์ ÷ 7) x ต้นทุนต่อ Event โดยประมาณ
```

ตัวอย่าง: ธุรกิจต้องการ Purchase อย่างน้อย 14 ครั้ง/สัปดาห์ต่อ Ad Set (เพื่อให้ Learning Phase มีโอกาสจบเร็ว) และคาดว่า Cost per Purchase อยู่ที่ 200 บาท

```
Minimum Budget/วัน = (14 ÷ 7) x 200 = 2 x 200 = 400 บาท/วัน
```

แต่ถ้ายังไม่มีข้อมูล Cost per Purchase มาก่อนเลย (ธุรกิจใหม่) ให้ใช้ค่าประมาณจากตารางด้านบนเป็นจุดเริ่มต้น แล้วปรับตามข้อมูลจริงหลัง 5-7 วันแรก

### ข้อผิดพลาดที่พบบ่อย

- ตั้งงบต่ำกว่า Minimum Budget ที่แนะนำแล้วคาดหวังผลลัพธ์เท่ากับบัญชีที่ใช้งบเต็ม ทำให้ผิดหวังและเลิกยิงแอดเร็วเกินไปทั้งที่ปัญหาคือ "งบไม่พอให้ระบบเรียนรู้" ไม่ใช่ "แอดไม่เวิร์ก"
- ใช้ตัวเลข Minimum Budget ของ Objective หนึ่งไปใช้กับอีก Objective โดยไม่ปรับ (เช่น ใช้เกณฑ์ Traffic ไปตั้งงบ Sales Objective ทำให้งบน้อยเกินไปสำหรับ Purchase Event ที่ต้องการ Volume มากกว่า)
- ไม่คำนึงถึง Cost per Event ที่แตกต่างกันมากในแต่ละอุตสาหกรรม (เช่น อสังหาริมทรัพย์มี Cost per Lead แพงกว่าร้านขายเสื้อผ้ามาก การใช้ตัวเลข Minimum Budget แบบเดียวกันทุกธุรกิจจึงผิดพลาดได้)

## Step 178: การปรับ Budget โดยไม่รีเซ็ต Learning Phase

### กฎสำคัญที่ต้องจำ

Meta มีเกณฑ์ชัดเจนว่าการปรับ Budget แบบไหนจะรีเซ็ต Learning Phase และแบบไหนไม่รีเซ็ต:

**การเปลี่ยนแปลงที่ "ไม่รีเซ็ต" Learning Phase:**
- ปรับ Budget ขึ้นหรือลงไม่เกิน **20% ของงบปัจจุบัน** ในครั้งเดียว
- ปรับ Bid หรือ Cost Cap เล็กน้อย (ไม่ใช่เปลี่ยน Bid Strategy ทั้งหมด)
- Meta ระบุว่าการเปลี่ยนแปลงเล็กน้อยเหล่านี้จะทำให้ Ad Set เข้าสู่สถานะ "Learning (Limited)" ชั่วคราวเท่านั้น ไม่ใช่การรีเซ็ตแบบเต็มรูปแบบ

**การเปลี่ยนแปลงที่ "รีเซ็ต" Learning Phase แบบเต็มรูปแบบ:**
- ปรับ Budget เกิน 20% ในครั้งเดียว (ไม่ว่าจะเพิ่มขึ้นหรือลดลง)
- เปลี่ยน Optimization Goal
- เปลี่ยน Bid Strategy (เช่น จาก Lowest Cost ไปเป็น Cost Cap)
- แก้ไข Targeting/Audience อย่างมีนัยสำคัญ (เพิ่ม/ลบ Interest จำนวนมาก)
- หยุดแคมเปญนานเกิน 7 วันแล้วเปิดใหม่ (ระบบมองเป็นการเริ่มต้นใหม่)
- แก้ไข Creative ที่มีนัยสำคัญในบาง Ad (เพิ่ม Ad ใหม่เข้าไปในกลุ่มเดิม ไม่รีเซ็ตทั้ง Ad Set แต่ Ad ใหม่นั้นจะเริ่ม Learning Phase ของตัวเองใหม่)

### เทคนิคการ Scale งบแบบปลอดภัย (20% Rule)

ถ้าต้องการเพิ่มงบจาก 1,000 บาท เป็น 2,000 บาท (เพิ่ม 100%) ห้ามเพิ่มทีเดียวเด็ดขาด เพราะจะรีเซ็ต Learning Phase ให้ทำแบบขั้นบันไดดังนี้:

| รอบที่ | งบก่อนปรับ | ปรับเพิ่ม (สูงสุด 20%) | งบใหม่ | ควรเว้นระยะก่อนปรับรอบต่อไป |
|---|---|---|---|---|
| รอบที่ 1 | 1,000 บาท | +20% | 1,200 บาท | รอ 24-48 ชม. ให้ระบบปรับตัว |
| รอบที่ 2 | 1,200 บาท | +20% | 1,440 บาท | รอ 24-48 ชม. |
| รอบที่ 3 | 1,440 บาท | +20% | 1,728 บาท | รอ 24-48 ชม. |
| รอบที่ 4 | 1,728 บาท | +20% | 2,074 บาท | ถึงเป้าหมายที่ 2,000+ บาทแล้ว |

วิธีนี้ใช้เวลาประมาณ 6-8 วันถึงจะขึ้นงบเป็น 2 เท่าได้อย่างปลอดภัย ช้ากว่าการเพิ่มทีเดียวแน่นอน แต่ **ป้องกันไม่ให้ CPA พุ่งกระชากในช่วงที่ Learning Phase รีเซ็ตใหม่** ซึ่งมักทำให้เสียเงินไปกับช่วง "เรียนรู้ใหม่" มากกว่าการค่อยๆขยับ

### เมื่อไหร่ที่ "ยอมรีเซ็ต" Learning Phase ดีกว่า

ในบางสถานการณ์ การรีเซ็ต Learning Phase อาจคุ้มค่ากว่าการค่อยๆขยับ เช่น:
- ต้องการ Scale งบแบบก้าวกระโดดในช่วงเทศกาลใหญ่ที่มีเวลาจำกัด (เช่น เหลือแค่ 3 วันก่อน 11.11) การค่อยๆขยับทีละ 20% อาจไม่ทันเวลา จึงยอมรีเซ็ตแล้วเพิ่มทีเดียวเพื่อจับโอกาสให้ทัน
- Ad Set เดิมผลงานแย่มากจนต้องการเริ่มต้นใหม่จริงๆ (ในกรณีนี้การรีเซ็ตคือสิ่งที่ต้องการอยู่แล้ว)

### ข้อผิดพลาดที่พบบ่อย

- เพิ่มงบทีเดียวมากกว่า 20% เพราะรีบเร่งอยากได้ผลลัพธ์เร็ว แล้วเจอ CPA พุ่งกระชาก 3-5 วันจากการรีเซ็ต Learning Phase โดยไม่รู้ตัวว่าสาเหตุคืออะไร
- ลดงบลงมากกว่า 20% ในช่วงที่ผลลัพธ์ไม่ดี (คิดว่าลดงบจะช่วยประหยัด) แต่กลับทำให้ Ad Set ต้องเรียนรู้ใหม่และ CPA แพงขึ้นไปอีกในช่วงแรกหลังปรับ
- ปรับ Budget พร้อมกับเปลี่ยน Creative หรือ Targeting ในเวลาเดียวกัน ทำให้แยกไม่ออกว่าผลลัพธ์ที่เปลี่ยนไปเกิดจากปัจจัยไหน (ควรปรับทีละอย่าง ไม่ปรับหลายตัวแปรพร้อมกัน)
- นับวันผิด — คิดว่าปรับงบวันนี้ พรุ่งนี้จะเห็นผลทันที ทั้งที่ Learning Phase (แม้แบบ Limited) ต้องใช้เวลาอย่างน้อย 3-5 วันถึงจะเสถียร ต้องให้เวลาระบบก่อนตัดสินใจปรับซ้ำ

## Step 179: Ad Scheduling และ Dayparting

### Ad Scheduling คืออะไร

Ad Scheduling (หรือ Dayparting) คือการกำหนดวันและช่วงเวลาที่ต้องการให้โฆษณาแสดงผลเท่านั้น แทนที่จะให้แสดงตลอด 24 ชั่วโมง 7 วัน ฟีเจอร์นี้มีเงื่อนไขสำคัญคือ **ใช้ได้เฉพาะกับ Lifetime Budget เท่านั้น** (ไม่สามารถใช้ Ad Scheduling แบบเจาะช่วงเวลาเฉพาะกับ Daily Budget ได้ ถ้าใช้ Daily Budget โฆษณาจะแสดงตลอด 24 ชั่วโมงเสมอ)

### เมื่อไหร่ควรใช้ Dayparting

1. **ธุรกิจที่มีทีมตอบแชท/รับสายเฉพาะช่วงเวลาทำการ** — เช่น คลินิก ร้านอาหารที่เปิดรับออเดอร์เฉพาะ 10:00-22:00 ไม่ควรยิงแอดตอนตี 2 เพราะถ้ามีคนสนใจแต่ไม่มีใครตอบ จะเสียโอกาสปิดการขายและลูกค้าอาจหมดความสนใจไปแล้วตอนเช้า
2. **ธุรกิจ B2B ที่ตัดสินใจในเวลาทำงาน** — เจาะช่วง 09:00-18:00 วันจันทร์-ศุกร์ เพราะผู้มีอำนาจตัดสินใจมักใช้โซเชียลมีเดียเพื่อธุรกิจในเวลาทำงานเท่านั้น
3. **ร้านอาหาร/เดลิเวอรี่ที่รู้ Prime Time ชัดเจน** — เจาะช่วง 11:00-13:00 และ 17:00-20:00 ที่คนตัดสินใจสั่งอาหารมากที่สุด
4. **ธุรกิจที่มีงบจำกัดมากและต้องการความคุ้มค่าสูงสุด** — ตัดช่วงเวลาที่ข้อมูลในอดีตแสดงว่า Conversion Rate ต่ำมากออกไปเลย

### เมื่อไหร่ไม่ควรใช้ Dayparting

- ธุรกิจ E-commerce ที่ระบบสั่งซื้อ/ชำระเงินอัตโนมัติ 24 ชั่วโมงและไม่ต้องพึ่งคนตอบเลย — การจำกัดเวลาจะทำให้เสียโอกาสขายในช่วงดึกที่บางกลุ่มลูกค้าเลือกซื้อของ (มีงานวิจัยพฤติกรรมจำนวนมากชี้ว่าช่วง 22:00-01:00 เป็นช่วงที่คนไทยจำนวนไม่น้อยเลือกซื้อของออนไลน์เพราะเป็นเวลาว่างส่วนตัว)
- แคมเปญที่ยังอยู่ใน Learning Phase — การจำกัดช่วงเวลาแสดงผลทำให้ระบบมีโอกาสเรียนรู้น้อยลง อาจทำให้ Learning Phase จบช้ากว่าที่ควร

### ตัวอย่างการตั้งค่า Dayparting จริง (คลินิกทำฟัน)

คลินิกเปิดรับสาย/แชท 09:00-19:00 ทุกวัน ไม่มีทีมตอบนอกเวลานี้ ตั้ง Ad Scheduling ดังนี้:

| วัน | ช่วงเวลาที่ฉายโฆษณา | เหตุผล |
|---|---|---|
| จันทร์-ศุกร์ | 08:30-19:30 | เผื่อเวลาก่อน-หลังเปิด/ปิดคลินิก 30 นาทีให้คนเห็นแอดล่วงหน้าแล้วโทรตอนเปิด |
| เสาร์-อาทิตย์ | 09:00-18:00 | ลดเวลาลงเล็กน้อยเพราะสถิติแสดงว่า Engagement วันหยุดเริ่มช้ากว่าวันทำงาน |
| ทุกวัน 19:30-08:30 | ไม่ฉายโฆษณา | ไม่มีคนตอบ ป้องกันการเสียโอกาสและ Follow-up ช้าเกินไป |

### ข้อผิดพลาดที่พบบ่อย

- พยายามตั้ง Ad Scheduling กับ Daily Budget แล้วสงสัยว่าทำไมตั้งไม่ได้ (ต้องเปลี่ยนเป็น Lifetime Budget ก่อนถึงจะเจาะช่วงเวลาได้)
- ตั้งช่วงเวลาแคบเกินไป (เช่น เปิดแค่ 2 ชั่วโมง/วัน) ทำให้ Learning Phase ไม่มีโอกาสสะสม Event ให้พอในแต่ละวัน
- ตัดช่วงเวลาออกโดยไม่มีข้อมูลรองรับ เป็นการเดาเอาเองว่า "กลางคืนไม่มีคนซื้อ" ทั้งที่ไม่เคยเช็ก Breakdown by Time of Day ในรายงานจริงก่อนตัดสินใจ
- ใช้ Dayparting เพื่อประหยัดงบ แต่กลับทำให้พลาดกลุ่มลูกค้าที่ตัดสินใจซื้อในช่วงเวลาที่ถูกตัดออกไปโดยไม่รู้ตัว

## Case Study: ร้านค้าปลีกเสื้อผ้าแฟชั่นออนไลน์ ปรับโครงสร้างงบใหม่ทั้งบัญชี

**สถานการณ์:** ร้านเสื้อผ้าแฟชั่นออนไลน์ขนาดกลาง งบโฆษณาเดิม 60,000 บาท/เดือน ใช้ CBO เดียวยัดทุก Ad Set (Cold, Warm, Retargeting) ไว้ในแคมเปญเดียวมาตลอด 6 เดือน ปัญหาที่พบคือ Cost per Purchase ค่อยๆแพงขึ้นทุกเดือน (จาก 180 บาท เป็น 340 บาท) และเจ้าของร้านสังเกตว่ายอดขายเริ่มพึ่ง "ลูกค้าเก่า" มากขึ้นเรื่อยๆ

**การวิเคราะห์:** เมื่อตรวจ Breakdown พบว่า CBO เทงบไปที่ Ad Set Retargeting เกือบ 85% ของงบทั้งหมด เพราะ Cost per Purchase ถูกที่สุด ทำให้ Ad Set Cold Prospecting ได้งบไม่ถึง 10% มา 3 เดือนติดต่อกัน — Retargeting Pool จึงค่อยๆหมดเพราะไม่มีลูกค้าใหม่เข้าระบบทดแทนคนที่ซื้อไปแล้ว สุดท้ายระบบต้องรีทาร์เก็ตซ้ำกับคนกลุ่มเดิมที่ Frequency สูงขึ้นเรื่อยๆ (จาก 3 เป็น 8+ ต่อสัปดาห์) ทำให้ Conversion Rate ตกและต้นทุนพุ่ง

**การแก้ไข:** แยกโครงสร้างใหม่เป็น 3 Campaign:
- Campaign A (ABO): Cold Prospecting งบการันตี 15,000 บาท/เดือน (500 บาท/วัน) แบ่ง 3 Ad Set (Lookalike 1%, Lookalike 2-5%, Interest กว้าง)
- Campaign B (ABO): Warm Audience งบการันตี 12,000 บาท/เดือน (400 บาท/วัน) สำหรับ Video Viewers และ Engager 30-180 วัน
- Campaign C (CBO): Hot Retargeting งบ 33,000 บาท/เดือน (1,100 บาท/วัน) ให้ระบบเลือกกลุ่ม Add to Cart/Checkout ที่ Convert ดีที่สุดเอง เพราะทุก Ad Set ในกลุ่มนี้มีบทบาทเหมือนกันคือปิดการขาย

**ผลลัพธ์หลัง 45 วัน:** Cost per Purchase ลดจาก 340 บาท กลับมาเหลือ 215 บาท เพราะ Retargeting Pool มีคนใหม่เข้ามาเติมต่อเนื่องจาก Campaign A/B ทุกสัปดาห์ Frequency ของ Campaign C ลดลงมาอยู่ที่ 3-4 ต่อสัปดาห์ (จาก 8+) และยอดขายรวมเพิ่มขึ้น 28% ด้วยงบรวมเท่าเดิม

**บทเรียน:** การยัดทุก Ad Set ไว้ใน CBO เดียวโดยไม่แยกตามบทบาท คือสาเหตุที่ทำให้ธุรกิจจำนวนมาก "โตได้ระยะสั้นแต่ตันในระยะยาว" เพราะ CBO จะเลือกกลุ่มที่ถูกที่สุดเสมอ ซึ่งมักเป็น Retargeting Pool ที่มีขนาดจำกัดและหมดไปเรื่อยๆถ้าไม่เติมลูกค้าใหม่

## Workshop / แบบฝึกหัด: วางแผนงบประมาณแคมเปญ 30 วัน

### โจทย์

ธุรกิจ: ร้านขายเครื่องนอน (หมอน ผ้าห่ม ที่นอน) ออนไลน์ มีเว็บไซต์พร้อม Pixel/CAPI สมบูรณ์ Purchase เฉลี่ยเดือนก่อน 65 ครั้ง Cost per Purchase เฉลี่ย 260 บาท ราคาสินค้าเฉลี่ย 890 บาท ต้องการวางแผนงบประมาณเดือนถัดไปทั้งหมด **45,000 บาท** สำหรับ 30 วัน โดยแบ่งเป็น 3 ช่วงตามกลยุทธ์ Full-Funnel

### แนวทางคำนวณทีละขั้น

**ขั้นที่ 1 — แบ่งงบตามบทบาท Funnel**

| บทบาท | สัดส่วนงบ | งบรวม (บาท) | Campaign Type |
|---|---|---|---|
| Cold Prospecting (หาลูกค้าใหม่) | 30% | 13,500 | ABO |
| Warm Nurture (Engagement/Traffic) | 20% | 9,000 | ABO |
| Hot Retargeting/Sales | 50% | 22,500 | CBO |

**ขั้นที่ 2 — แปลงเป็นงบรายวันเฉลี่ย**

```
Cold Prospecting: 13,500 ÷ 30 วัน = 450 บาท/วัน
Warm Nurture:      9,000 ÷ 30 วัน = 300 บาท/วัน
Hot Retargeting:  22,500 ÷ 30 วัน = 750 บาท/วัน
รวมทั้งหมด:        45,000 ÷ 30 วัน = 1,500 บาท/วัน
```

**ขั้นที่ 3 — ตารางงบประมาณรายวัน 30 วันแบบเต็ม (ปรับตาม Pacing และวันสำคัญ)**

สมมติมีโปรโมชั่นสิ้นเดือน (วันที่ 25-30) ที่ต้องการเพิ่มงบ Hot Retargeting เป็นพิเศษ:

| วันที่ | Cold (บาท) | Warm (บาท) | Hot (บาท) | รวม/วัน (บาท) | หมายเหตุ |
|---|---|---|---|---|---|
| 1-3 | 450 | 300 | 750 | 1,500 | Learning Phase เริ่มต้น รันงบคงที่ |
| 4-7 | 450 | 300 | 750 | 1,500 | รอ Learning Phase จบ (สัปดาห์แรก) |
| 8-10 | 540 (+20%) | 300 | 750 | 1,590 | เริ่มปรับ Cold ขึ้นตาม 20% Rule เพราะ Cost per Lookalike ดี |
| 11-14 | 540 | 360 (+20%) | 900 (+20%) | 1,800 | Scale ทุกกลุ่มที่ผลงานดีทีละ 20% |
| 15-17 | 540 | 360 | 900 | 1,800 | คงที่ให้ Learning Phase เสถียรหลังปรับ |
| 18-21 | 500 (-8% ปรับตาม Audience หมด) | 360 | 1,080 (+20%) | 1,940 | ลด Cold ที่ Audience เริ่มอิ่มตัว เพิ่ม Hot ต่อ |
| 22-24 | 500 | 360 | 1,080 | 1,940 | คงที่เตรียมความพร้อมก่อนโปรโมชั่น |
| 25-27 | 500 | 300 (-17% ลดเพื่อโยกไป Hot) | 1,600 (+48% เพราะ Lifetime Budget แยกสำหรับโปร) | 2,400 | ช่วงโปรโมชั่นสิ้นเดือน เพิ่ม Hot Retargeting เต็มที่ |
| 28-30 | 500 | 300 | 1,600 | 2,400 | ต่อเนื่องช่วงโปรโมชั่น |

**หมายเหตุสำคัญสำหรับ Workshop:** ช่วงวันที่ 25-30 ที่ต้องการเพิ่มงบ Hot Retargeting กระชากขึ้นมาก (จาก 1,080 เป็น 1,600 คือ +48%) เกินกฎ 20% Rule ในทางปฏิบัติมืออาชีพจะ **สร้าง Campaign ใหม่แยกเฉพาะโปรโมชั่นนี้** (ใช้ Lifetime Budget ระบุช่วง 25-30) แทนการปรับ Campaign เดิมที่รันอยู่ เพื่อไม่กระทบ Learning Phase ของ Campaign หลักที่กำลังเสถียรอยู่แล้ว

**ขั้นที่ 4 — ตรวจสอบผลรวมให้ตรงกับงบที่วางแผน**

```
รวมงบ Cold (วัน 1-30): ประมาณ 13,970 บาท
รวมงบ Warm (วัน 1-30): ประมาณ 9,540 บาท
รวมงบ Hot (วัน 1-30):  ประมาณ 22,290 บาท
รวมทั้งหมด: ประมาณ 45,800 บาท (ใกล้เคียงงบที่ตั้งไว้ 45,000 บาท คลาดเคลื่อนได้ ±5% จากการปรับ Pacing)
```

### คำถามให้ฝึกคิดต่อ (ไม่มีเฉลยตายตัว ให้ลองตอบด้วยเหตุผลของตัวเอง)

1. ถ้า Cost per Purchase ของ Cold Prospecting แพงกว่าที่คาดไว้ 50% ตั้งแต่สัปดาห์แรก ควรปรับแผนงบประมาณ 30 วันนี้อย่างไร?
2. ถ้าธุรกิจนี้อยากลองใช้ ROAS Goal แทน Lowest Cost ใน Campaign Hot Retargeting ควรเริ่มใช้ตอนไหนของแผน 30 วันนี้ และต้องมีข้อมูลอะไรก่อน?
3. สมมติวันที่ 15 ธุรกิจได้รับงบเพิ่มจากเจ้าของร้านอีก 10,000 บาทแบบไม่ทันตั้งตัว ควรกระจายงบเพิ่มนี้ไปที่ Campaign ไหนก่อน และปรับแบบไหนให้ไม่กระทบ Learning Phase ที่เสถียรอยู่แล้ว?

**วิธีส่งงาน:** ทำตารางงบประมาณ 30 วันแบบเดียวกันนี้สำหรับธุรกิจของตัวเอง/ลูกค้าจริง 1 เคส พร้อมระบุเหตุผลการเลือก CBO/ABO และ Bid Strategy ของแต่ละ Campaign

## สรุปและเชื่อมไปยัง Part ถัดไป

Part นี้ปูพื้นฐานที่นักยิงแอดต้องใช้ทุกวันในการทำงานจริง คือ **การจัดสรรงบประมาณและเลือก Bid Strategy ให้สอดคล้องกับกลยุทธ์ Funnel** เราเรียนรู้ความแตกต่างของ Daily vs Lifetime Budget, กลไกของ CBO และ ABO พร้อมกรอบการตัดสินใจว่าเมื่อไหร่ควรใช้แบบไหน, Bid Strategy ทั้ง 4 แบบที่ควบคุมการประมูลในระดับความเข้มข้นต่างกัน, กลไก Pacing ที่กระจายงบตลอดวัน, ตัวเลข Minimum Budget ที่ใช้ได้จริง, กฎ 20% Rule ในการ Scale งบอย่างปลอดภัย และการใช้ Dayparting ให้ตรงกับพฤติกรรมลูกค้า

ต่อไปเราจะย้ายโฟกัสไปที่อีกตัวแปรสำคัญที่กำหนดว่าโฆษณาของคุณจะไปโชว์ที่ไหน — ใน **Part 019: Ad Placements และ Automatic vs Manual Placements** เราจะเจาะลึกทุก Placement ของ Facebook/Instagram ตั้งแต่ Feed, Stories, Reels, Audience Network ไปจนถึง Messenger พร้อมตาราง Aspect Ratio ของครีเอทีฟที่ต้องใช้ในแต่ละตำแหน่งให้ถูกต้อง เพื่อให้งบที่คุณวางแผนไว้อย่างดีใน Part นี้ ถูกใช้ไปกับ Placement ที่เหมาะสมที่สุดสำหรับ Objective และครีเอทีฟที่มี
